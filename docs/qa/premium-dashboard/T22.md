## 성능과 미측정 항목

동일 로컬 배포용 빌드·합성 API·390×900·무제한 로컬 네트워크에서5개 독립 context를 열어 최초/반복 navigation을 각5회 측정했다. Playwright clock을 사용하지 않았다. 최초 LCP 중앙값88ms(84–92), 반복76ms(68–324); CLS 최대0.00430. `performance/results.json`에 개별값을 보존했다. 서버/네트워크가 운영과 달라 실제 사용자 p75 목표 달성을 주장하지 않는다. 캐시를 켜도 최초/반복 전송량이 같았으므로 반복 navigation을 유효한 warm HTTP-cache 측정으로 간주하지 않는다. INP와 실제 cold/warm 네트워크 성능 비교는 미측정이다.

빌드에 저장된 전체 정적 JS는4,750,389→4,769,475bytes(+19,086, 약0.40%)다. 이 값은 전체 경로 파일 합계이며 첫 화면 번들/압축 전송량을 뜻하지 않는다. 출처는 `baseline-build.json`, `final-build-size.json`.

남은 검증은 직원5명의 업무 시간/실수 비교, 실제 iOS/Android 키보드·터치·Windows, 브라우저200% 확대 및 화면읽기 도구 전수검사, 운영 DB를 포함한 각 역할의 저장/재시도, 실제 사용자 Core Web Vitals다. 자동 QA만으로 ‘어워즈 수준’ 또는 업무시간20% 개선을 인증하지 않는다. T22의 자동·로컬 부분은 완료했고 이 실환경 항목은 미측정으로 남긴다.
