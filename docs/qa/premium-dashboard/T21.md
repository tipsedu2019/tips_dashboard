# T21 — 탐색 계약 검토

기준 `5e423390`, 2026-09-15. 이번 카드는 계획에 명시된 설계 검토이며 새 검색 기능 구현 카드가 아니다.

## 일정 링크

실제 `registration-workspace-route.ts`의 `buildRegistrationWorkspaceSearchParams`는 `view=calendar&kind=level_test|visit_consultation|observation`을 지원한다. 청강 `observation`은 observationRuntimeVersion=1일 때만 허용하고 그 외에는 all로 정규화한다. `ops-task-workspace.tsx`의 route effect는 이 parser를 소비한다. 특정 달력 날짜를 수락하는 query 계약은 없으므로 **오늘의 유형별 건수**를 특정 날짜 목록으로 연결하는 약속은 현재 성립하지 않는다.

이번 UI에서는 카운트를 읽기 전용으로 유지한다. 전체 일정은 기존 등록 달력으로 연결하고, 각 일정 행은 서버가 제공한 정확한 href를 사용한다. 청강 상세는 taskId/trackId/appointmentId/observationId/view의 정확한 5개 query 및 UUID를 검사하는 기존 계약을 보존한다. 숫자 클릭 때문에 허용하지 않은 날짜 필터나 청강 URL을 추정하지 않는다.

## 빠른 이동

현재 command-search는 권한으로 걸러진 메뉴 탐색이다. 새 entity reader가 없고 기존 학생·수업 목록 쿼리는 각 업무 화면 소유이므로 헤더에서 전수 preload하지 않는다. 직원 5명의 검색 시간·사용 빈도 근거도 이번 작업에 제공되지 않았다. 기존 클릭 검색과 키보드 접근성만 유지하며 커스텀 단축키를 복원하지 않는다.

향후 확장 카드 입력 계약: 종류(student/class), id, 이름, 동명이인 구분 학교·학년/수업 담당자, 검증된 detail href. 서버가 인증·역할·tenant로 범위를 제한하고 2자 이상 입력, 250ms debounce, 종류별5개/전체15개 상한을 API 비용 검토 후 확정한다. 요청 취소 및 generation guard, 한글 조합 중 요청 금지, 지연/빈결과/오류 상태, 개인정보 없는 계측이 필요하다. 목록 API를 재사용할 수 있는지는 독립 read API 검토에서 결정하며 현재 계약으로 보장하지 않는다.

결과: 날짜 계약 또는 검색 사용성 근거가 확보되면 별도 구현 Issue로 분리할 수 있다. 이번 전체 UI 고도화에 미확정 API를 추가하지 않는다.
