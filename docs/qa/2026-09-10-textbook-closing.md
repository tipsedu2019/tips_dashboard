# 정산 목록·상세 화면 정돈

2026-09-10 · `codex/dashboard-apple-design-20260909` · 로컬 3137 합성 데이터

## 변경

- 월별 목록을 공통 프레임·도구 모음·표 셀·스크롤 영역·페이지 탐색으로 통일했다. 반복 건수 배지를 제거하고 페이지 탐색에서 전체 건수를 표시한다.
- 데스크톱과 모바일 모두 월 제목으로 상세를 열고, 중복 상세 버튼을 제거했다. 행 전체의 키보드 이벤트를 없애 체크박스의 Space가 상세 열기로 전파되지 않는다. 같은 월이라도 과목을 포함한 선택 이름으로 구별한다.
- 모바일은 작은 수량 카드 네 개를 입고·출고·기말·마진의 간결한 목록으로 바꿨다. 공통 40px 선택 영역과 Button을 재사용하며 선택 확정은 선택 시 한 번 표시한다.
- `ClosingStatus`를 목록·모바일·상세에서 함께 사용해 draft/locked를 초안/확정으로 표시한다.
- 상세의 저장값/현재값 카드 여덟 개를 네 행의 비교표로 교체했다. 기존 불일치 항목과 개수를 유지하고, 색상과 스크린리더 문구로 차이를 구분한다. 긴 메모는 생략하지 않는다.
- 상세 창은 데스크톱 최대 1024px로 넓혀 일곱 이동 열을 함께 읽게 했다. 교재명과 위치는 줄바꿈한다. 헤더·닫기 버튼은 본문 스크롤과 분리해 표를 가리지 않는다.
- 로딩/조회 실패 중 임시 0과 복사 작업이 노출되지 않는다. 이동 내역 조회 오류는 상세 안에 재시도와 함께 표시한다. 검색 결과 없음, 전체 내역 없음, 로딩, 오류를 구분하고 넓은 표 밖에 안내해 모바일에서도 볼 수 있게 했다.
- 현재 페이지 건수를 N/N으로 반복하던 배지를 제거했다. 이동 내역의 전체 건수와 페이지 탐색은 그대로 유지한다.

## 보존과 성능 경계

금액·수량 계산, 저장값 추출, 불일치 판정, 초안 저장/일괄 확정, 권한, 선택 및 입력 revision, 서버 페이지와 URL, 복사 범위·취소·권한 변경 보호를 유지했다. 월마감 추가 폼의 입력과 전체 선택 시 4건 저장 범위도 변경하지 않았다.

시작 소스와 최종 함수 선언 비교에서 216개가 동일하다. 변경 함수는 화면 조합, 정산 목록, 정산 상세 세 개이며 `ClosingStatus` 하나를 추가했다. `submitClosing`, `lockSelectedClosings`, `copyClosingDetail`은 원문이 동일하다. 조회 서비스·ledger·DB·RPC 정의를 수정하지 않았다. 함수 비교는 코드 범위 증거이며 런타임 검사를 대신하지 않는다.

공통 UI를 재사용하고 기존 서버 조회·페이지 크기·선택 메모화를 유지했다. 이번 단계에서 처리 시간이나 렌더링 속도 향상을 측정하거나 주장하지 않는다.

## 실제 브라우저

- 1280×720: 정산 목록과 상세 비교, Space 선택 시 상세가 열리지 않는 것, 월 버튼의 상세 열기를 확인했다. 상세 폭 1022/1022px, 이동 영역 938/938px로 가로 넘침 없이 일곱 열을 표시한다. 긴 교재명 셀은 277/277px이며 줄바꿈한다.
- 390×844: 문서 375/375px, 목록 카드 315/315px로 가로 넘침이 없다. 모바일 선택과 확정 진입점이 표시된다. 상세 비교표 287/287px, 메모 289/289px로 줄바꿈하고 이동 내역만 920px 표를 내부에서 탐색한다. ArrowRight로 scrollLeft 0→40px를 확인했다.
- 없는 교재 검색 후 빈 결과 안내와 0건 페이지 상태가 모바일 안에 보인다. 오류 합성 응답에서 재시도와 조회 실패를 표시하고 빈 내역으로 안내하지 않는다. 지연 모드에서 상세 로딩만 표시하며 임시 금융 값 표가 없다.
- 라이트/다크 테마의 상태·비교 차이·버튼과 키보드 초점을 확인한 뒤 라이트로 복원했다. viewport도 기본값으로 복원했다.
- 기존 월마감 추가 폼에서 기초 수량 7 입력 후 기말 7권과 저장 4건을 확인하고 닫았다. 실제 저장·확정은 실행하지 않았다.
