# 교재 처리 결과 알림과 일괄 실행 안정성

- 날짜: 2026-09-11
- 브랜치: `codex/dashboard-apple-design-20260909`. 기존 누적 변경 보존.
- 범위: 교재관리 목록의 일시적 처리 결과와 주문·입고 일괄 처리 상태.

## 문제와 변경

출고 행에서 처리가 실패하면 상단 Alert가 새로 생겨 탭·검색창·표가 모두 58px 내려가는 문제를 실제 로컬 브라우저에서 재현했다. 목록의 처리 결과를 공통 `ActionFeedback`으로 옮겨 화면 하단에 표시한다. 기존 Alert/Button과 색상·그림자·간격 토큰을 재사용하며 새 패키지는 추가하지 않았다.

정보는 `role="status"`, 오류는 `role="alert"`로 구분한다. 표시 시 초점을 이동하지 않고, 사용자가 닫거나 다음 작업을 시작할 때까지 유지한다. 닫으면 알림 표시 당시 조작 요소로 돌아가며 해당 요소가 사라지거나 비활성화됐으면 현재 목록 검색창으로 돌아간다. 긴 문구는 줄바꿈하고 최대 30dvh 안에서 스크롤할 수 있다. 모바일 닫기는 44×44px이다. 치수는 프로젝트 선택 값이며 Apple 공식 치수가 아니다.

폼·일괄 편집·확인 창이 소유한 오류는 기존 창 안에 유지한다. 스키마/API 가용성이나 목록 참조자료 조회 오류를 나타내는 지속적인 안내는 이번 이동 대상에 포함하지 않았다. 하단 알림은 표시 중 일부 페이지 이동 영역과 겹칠 수 있으며 닫아서 제거할 수 있다.

기존 폼 실행에 한정됐던 동일 actor/action 중복 방지를 모든 `runAction` 호출에 적용했다. React가 비활성 상태를 그리기 전 같은 핸들러가 연속 호출되어도 같은 작업은 한 번만 실행한다. 일괄 처리 중 선택 주문·입고·반품·선택 해제 조작을 비활성화하고 입고 버튼에 `aria-busy`, 상태 영역에 처리 중 안내를 제공한다. 버튼 문구와 너비는 유지한다. 기존 선택 변경 시 오래된 완료 응답을 반영하지 않는 보호는 유지했다.

## 브라우저 검수

실제 제품 컴포넌트를 로컬 합성 fixture에 연결했다. 출고 오류는 null Supabase의 `fixture_transport_disabled`이며 운영 오류나 실제 출고 결과가 아니다.

| 조건 | 측정 결과 |
|---|---|
| 1280×720, 변경 전 오류 | 탭 y85→143, 검색 y150→208, 표 y247→305: 모두 +58px |
| 같은 크기·데이터, 변경 후 오류 | 탭 y85, 검색 y150, 표 y247 유지: 이동 0px |
| 390×844, 변경 후 오류 | 문서 기준 탭 y113, 검색 y214, 표 y425 유지: 이동 0px |
| 모바일 조작 버튼이 보이는 위치에서 재시도 | scrollY49 유지, 탭 y64·검색 y165·표 y376 유지 |
| 모바일 알림 | 너비343px, 닫기44×44px, 페이지 가로 넘침0 |
| 키보드 닫기 | 출고 검색창으로 복귀, 목록의 문서 위치 유지 |
| 공통 상태 비교 화면 | 정보/status·오류/alert, 긴 한국어 문구, 표시 시 초점 유지와 닫은 뒤 원래 버튼 복귀 |

모바일 최초 자동 조작에서는 화면 밖 버튼에 접근하기 위한 스크롤이 발생했다. 이것을 알림에 의한 레이아웃 이동으로 합산하지 않았다. 버튼이 보이는 동일 스크롤 위치에서 재시도해 뷰포트 좌표까지 유지되는지 별도로 확인했다. 브라우저 전체 CLS나 모든 작업의 화면 흔들림이 0이라고 주장하지 않는다.

알림 자체에 이동·등장 애니메이션을 추가하지 않았다(이동0px, 지속0ms, easing 없음). 닫기 버튼은 기존 공통 상태 전환을 재사용한다. 이번 단계에서 OS reduced-motion 설정이나 실제 스크린리더 낭독을 새로 실기기 검수하지 않았다.

증거: `.codex-artifacts/textbook-action-feedback-20260911/`의 `desktop-before.png`, `desktop-error-before.png`, `desktop-error-after.png`, `layout-metrics.json`, `mobile-verified.json`, `component-browser.json`. 초기 viewport override가 검수 탭에 적용되지 않은 재측정 값은 모바일 증거에서 제외하고, 실제 innerWidth390/innerHeight844를 포함하는 `mobile-verified.json`을 최종 기준으로 사용했다. 임시 크기 변경은 복원했다.

## 보존·검증·성능

- 관련 고유 검사95개 통과: workspace 구조 계약91개 + 집중 동작4개. 최종 제품 build(TypeScript 포함), 대상 ESLint, diff 공백 검사 통과.
- 같은 렌더의 일괄 입고 핸들러를 두 번 호출해 최신 상세 조회1회, 처리 중 비활성·aria-busy·상태 표시를 확인했다. 지연 실패 후 선택2건 유지, 쓰기0회, 알림 유지·닫기·재시도를 검증했다.
- 공통 알림의 정보 역할·초점 유지·닫기 callback1회와 초점 복귀를 검증했다. 기존 일괄 주문의 6단계 완료 후 stale 응답 억제와 폼을 쓰지 않는 일괄 출고의 선택 변경 보호도 다시 확인했다.
- 직전 구현과 AST 비교에서 기존 함수212개와 textbookService 호출식25곳이 동일했다. 변경 함수는 workspace 표시부, `runAction`, `PurchaseProcessTable`이다. 서비스/API/DB, 수량·금액 계산, 문서 데이터·출력 코드를 변경하지 않았다.
- 주문서·반품 요청서·PNG/PDF는 변경 영향을 받지 않아 기존 검수를 재사용했다. 이번 단계에서 출력 파일을 새로 생성하지 않았다.
- 새 요청을 추가하지 않았다. 중복 호출 실험의 조회1회는 실행 가드 검증이며 평균 응답 시간이나 전반적인 렌더링 성능 개선의 증거로 확대하지 않는다.
- 운영 데이터 변경·외부 발송·푸시·배포 없음. 성공 저장과 실운영 결과는 검수 범위에 포함하지 않는다.
