실제 Next UI와 로컬 전용 합성 API를 사용했다. `scripts/qa/curriculum-scheduling-fixture-server.mjs`로 재현 가능하며 외부 API로 쓰기를 전달하지 않는다.

- 일정 목록·편성에서 교재 및 진도 UI가 사라졌다. 월별 날짜 입력, 회차 생성, 휴강/보강 편집은 유지된다.
- 9월 종료일을 9월 30일에서 29일로 변경하여 저장하고 다시 열어 유지되는 것을 확인했다. API 저장 데이터의 기존 teacherNote도 유지됐다.
- 교재 종료일을 12월 31일에서 30일로 저장하고 재진입하여 확인했다. 종료일이 시작일보다 이르면 인라인 오류가 표시되고 저장 요청이 발생하지 않는다. 삭제된 카탈로그 항목도 기존 제목과 사용기간을 표시한다.
- 일정 변경 후 돌아가기에서 미저장 확인, Escape 취소, 변경사항 버리기 후 목록 복귀를 확인했다.
- 합성 조회 오류 시 재시도 버튼, 재시도 후 빈 목록과 0건 표시를 확인했다. 정상 흐름 콘솔 오류는 없었으며 오류 주입 시 예상된 500 응답만 발생했다.
- 모바일 편성의 문서 가로 넘침이 없고, 교재 날짜는 한 열로 배열하여 네이티브 날짜 선택 아이콘을 포함한다.
- 편성 진입의 불필요한 수업 목록·공통 카탈로그·교재 후보 요청은 0건이다. 이전 소스에서는 이 요청들이 편성 화면에서도 실행됐다. 실제 운영 응답시간 개선 수치는 별도 측정하지 않았다.

## 자동 검증

- 일정·교재 사용기간·서비스 계약·쿼리 예산 관련 Node 테스트 239개 통과.
- 공통 디자인 계약 테스트 통과. 마이그레이션 레이아웃 40개 통과(워크플로 해시 갱신 후).
- TypeScript, 변경 소스 ESLint, Next production build 통과.
- 격리 DB에서 새 교재/일정 pgTAP, 기간 선택 호환성, 이전 v1 번호 페이지, 관리 상세 계약, DB lint, 배포 후 읽기 계약 통과.
- 실제 v2 SQL 출력 5개 행을 앱의 `readCurriculumNumberedPage` 소비 코드에 통과시켰다. 레거시 문자열 회차 키·일정 상태·집계 검증 완료.

## 데이터 및 배포 경계

운영 읽기 조사에서는 수업계획에 교재가 있지만 수업관리 교재가 비어 있는 수업이 44개였다. 마이그레이션은 양쪽 ID의 합집합과 확인 가능한 기존 사용 날짜를 수업관리로 옮기고, 원본 계획·진도 기록은 보존한다. 카탈로그에서 사라진 3개 교재도 ID와 기존 제목을 보존한다. 배포 시 이미 열린 화면을 위해 기존 v1 조회 함수는 유지하고 새 화면은 v2를 사용한다.

이 문서의 화면 쓰기 증거는 합성 데이터다. 운영 배포와 실제 DB 반영은 별도 릴리스 확인 대상이다.
