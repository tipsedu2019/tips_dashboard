## 운영 반영 순서와 범위

이번 작업은 로컬 수정·검증까지다. 원격 push, 운영 DB 적용, Vercel 배포, 실제 알림 발송은 수행하지 않았다.

새 프런트엔드가 RPC를 사용하므로 운영 적용 시 다음 두 DB 마이그레이션을 먼저 반영해야 한다.

1. `20260921114313_textbook_lifecycle_atomic.sql`
2. `20260921114314_signup_identity_isolation.sql`

고유 제약 추가 전 기존 중복 이동이 없는지 읽기 전용으로 확인한다. 중복이 있으면 마이그레이션이 중단되며, 이 변경은 과거 재고 이력을 자동 삭제하거나 정정하지 않는다.

```sql
select purchase_order_line_id, move_type, count(*)
from public.textbook_stock_moves
where purchase_order_line_id is not null
  and move_type in ('purchase_receipt', 'return_out')
group by purchase_order_line_id, move_type
having count(*) > 1;
```

운영 마이그레이션 성공 후 앱을 배포하고 저장·반품·과목 전환을 운영 권한으로 확인해야 한다. 기존 가입 충돌로 이미 잘못 연결된 계정이 있는지와 과거 재고 불일치 여부는 운영 데이터 검사 전에는 확정하지 않는다.
