# 출고 처리표와 공통 버튼 검수

2026-09-10 · `codex/dashboard-apple-design-20260909` · 로컬 3137 합성 데이터

## 완료 범위

- 출고 목록을 공통 표 프레임·도구 모음·선택 체크박스·셀·모바일 카드로 정돈했다. 교재명과 대상을 앞에 배치하고 긴 제목과 수업명을 줄바꿈한다.
- 기본 출고 버튼과 상세·출고 전 취소·고객 반품·이력 삭제의 역할을 나눴다. 학생, 요청, 주문·입고, 출고의 행 메뉴는 같은 `DataTableRowActions`를 사용한다. 주문·출고 제목은 `DataTableDetailButton`을 재사용한다.
- 반복 요약 배지를 수량·청구 한 줄로 줄였다. 집계 미확인은 0과 구분한다. 그룹 하단은 `이 페이지 합계`로 표시한다. 출고 이력은 주 목록 아래에 두며, 이력이 없다고 확인된 경우 이력과 그 전용 페이지 탐색을 함께 숨긴다.
- 일반 버튼의 기본·hover·pressed·focus·disabled 상태를 `Button`에서 관리한다. 16개 호출 파일의 로컬 hover/pressed/disabled 스타일을 제거하거나 공통 destructive 변형으로 옮겼다. 학생/수업 CSS에서 버튼 색·그림자·pressed 덮어쓰기를 제거하고 필요한 배치 크기만 유지했다.
- 메뉴 표면과 항목 높이도 공통 `DropdownMenu` 기준으로 맞췄다. 사용 기준은 `src/components/ui/README.md`와 데이터테이블 README에 기록했다.

같은 역할·variant의 버튼 상태를 통일하는 작업이다. 캘린더 범위 셀, 탐색 탭, 업무 상태 표시의 고유 의미까지 동일한 액션 버튼으로 바꾸지는 않는다. 실사·정산 처리표 전체 개편은 이번 단계에 포함하지 않는다.

## 보존 및 성능

기존 실행 콜백, 권한, 저장 중 비활성, 최신 상세 재조회, 취소·반품·삭제 확인, 서버 순서·그룹·페이지·URL 필터와 전체 대상 청구 준비를 유지한다. DB·RPC·인증·출력 코드는 변경하지 않았다.

출고 행의 교재·수업·위치·일시 표시를 accepted data별로 한 번 계산해 데스크톱과 모바일에서 공유한다. 선택 상태와 별개이며 새 데이터에는 다시 계산한다.

동일한 실제 컴포넌트/JSDOM 전송 하네스에서 20행, 선택 변경 5회를 비교했다:

| 측정 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 교재 조회 함수 호출 | 200 | 0 |
| 수업 조회 함수 호출 | 200 | 0 |
| 위치 표시 함수 호출 | 200 | 0 |
| 일시 조회 함수 호출 | 200 | 0 |

총 800회의 불필요한 표시 조회를 제거했다. 최초 계산과 새 데이터 계산은 필요하다. 앱 전체 렌더링 횟수나 체감 시간의 배율을 측정한 결과는 아니다.

## 자동 검증

- 교재·공통 표·공통 메뉴·등록 과목 관련 363개 통과 (`tests-final.log`).
- 관리·일정·할 일·보강·등록 목록 관련 297개 통과 (`management-regression.log`). 합계 660개.
- 집계 미확인 단언을 추가한 출고 renderer 및 공통 메뉴 검사 50개도 별도 재실행해 통과했다 (`summary-and-shared-final.log`). 이는 위 660개에 포함되는 재검사다.
- 선택 변경 시 표시 조회 0회, 새 페이지 데이터에 대한 캐시 갱신, 데스크톱/모바일 동일 데이터, 빈 이력의 독립 pager 제거, 취소 전에 최신 상세를 읽는 경계를 검사했다.
- 공통 메뉴를 열기만 해서는 작업을 실행하지 않으며 선택한 작업만 한 번 실행한다. native disabled 버튼은 실행되지 않는다.
- 교재 처리표를 제외한 스타일 정리 15개 파일의 이벤트 및 disabled JSX 속성을 시작 소스와 비교해 모두 동일함을 확인했다 (`caller-behavior-comparison.json`). 교재 처리표의 구조 변경은 위 런타임 검사로 확인했다.
- TypeScript 검사 및 최종 production build 통과. ESLint 오류 0, 기존 시간표 useMemo 의존성 경고 1개. 변경 전 파일에도 같은 경고가 있음을 확인했다.
- `git diff --check` 통과.

## 실제 브라우저

제품 컴포넌트를 합성 조회 데이터에 연결한 별도 탭에서 검수했다.

- 1280×720: 교재→대상→상태→수량의 위계, 긴 제목 줄바꿈, 다음 처리 버튼과 공통 메뉴, 이력 없는 경우 pager 제거를 확인했다. 문서 가로 넘침 없음.
- 390×844: 문서 clientWidth/scrollWidth 390/390px. 긴 제목 5개는 각 187px 영역에 60px 높이로 줄바꿈하며 제목 자체 가로 넘침도 없다.
- 모바일 선택 후 일괄 출고 버튼 표시, 대기 행 메뉴의 상세/출고 전 취소, 완료 행 메뉴의 상세/고객 반품/허용된 이력 삭제를 확인했다. 메뉴 Escape 후 원래 더보기 버튼으로 초점이 복귀한다.
- 제목에서 기존 출고 상세를 조회하고 닫았다. 검색 불일치의 빈 상태와 Escape 초기화 후 대기 조건 유지를 확인했다. 저장·출고·취소·반품·삭제는 실행하지 않았다.
- 공통 Button의 8개 variant × 활성/비활성 × 4개 CSS 문맥(기본·학생·수업·학생 상세)을 비교했다. 밝은/어두운 테마에서 64개 표본의 문맥별 기본 상태 스타일 차이 0. outline hover 문맥 비교와 실제 키보드 focus ring도 확인했다.
- pressed 밝기 95%, disabled 밝기 100%/불투명도 50%, 150ms ease-out 및 reduced-motion transition 제거는 공통 소스에서 확인했다. 누른 상태 유지와 OS reduced-motion 전환은 브라우저에서 별도로 재현하지 않았다.
- 모바일 검수 탭 콘솔 오류 0. 임시 화면 크기는 원복했다. 사용자가 열어 둔 교재 편집 화면은 조작하지 않았다.

합성 자료의 상태 그룹 순서·일시·검색별 집계 응답을 실제 strict parser 계약에 맞게 보완했다. 제품 parser나 저장 경계를 완화하지 않았다.

## 증거와 제한

`.codex-artifacts/textbook-sales-20260910/`에 시작 소스, 변경 전후 화면, 모바일 화면·너비 측정, 메뉴 초점, 버튼 기본/hover/다크/focus 비교, 성능 전후 JSON, 테스트·타입·린트·빌드 로그가 있다. `button-hover-focus.json`의 초기 focus 표본은 유효한 focus 증거가 아니며 실제 focus 확인은 별도 `button-focus.json`을 사용한다.

실제 재고 이동·저장·고객 전송·운영 데이터 변경은 하지 않았다. 로컬 검수 완료이며 푸시·배포는 수행하지 않았다.
