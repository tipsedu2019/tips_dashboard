# 주문서·반품 요청서·청구 준비 창 · 2026-09-10

20단계의 공통 창을 문서 작업까지 확장했다. `codex/dashboard-apple-design-20260909`의 로컬 변경이다.

## 변경

- `DocumentDialogContent`가 기존 폼·상세와 프레임·제목·본문 스크롤·하단 버튼을 공유한다. 문서용 넓은 너비와 고정 높이를 사용한다.
- 반복 배지 3개를 건수·묶음·권수 한 줄로 정리했다. 이미지/PDF는 공통 저장 메뉴로 묶고 전체/개별 범위를 유지했다. 청구 준비의 전체/개별 메시지 복사도 유지한다.
- 파일 진행·완료·실패 메시지는 높이를 예약한 하단 영역에 표시한다. 마지막 파일을 다시 저장할 수 있으며 창을 닫으면 임시 URL을 해제한다.
- 같은 창에서 동시에 여러 파일을 생성하지 않는다. 닫거나 자료가 바뀐 뒤 늦게 완료된 작업은 파일 다운로드와 완료 표시를 실행하지 않는다. 복사 실패 때 전체 텍스트를 선택하는 대체 경로도 유지한다.
- 내보내기는 화면 문서의 복사본을 별도 영역에서 처리한다. 기존 방식은 화면의 실제 문서 너비를 변경했으므로 생성 중 미리보기 재배치가 발생할 수 있었다. 이제 화면 크기를 변경하지 않으며 문서 조작 도구도 출력에서 제외한다.
- 모바일에서 가로로 숨겨진 표 열까지 출력 너비에 포함한다. 화면의 개별 저장 버튼은 보이는 너비에 남고, 표 영역은 키보드 가로 스크롤을 지원한다.
- 조회 실패를 ‘문서 없음’으로 표시하지 않고 실제 조회 안내와 다시 불러오기를 제공한다. 공급처 미지정 값 `unspecified`는 화면과 문서에서 한국어로 표시한다.

기존 TIPS 컴포넌트와 [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)의 비동기 알림·포커스·긴 내용·내부 스크롤 기준을 참고했다. 새 디자인 라이브러리나 플러그인은 추가하지 않았다.

## 검증

관련 **459개 검사 통과**. 10개 파일을 각각 독립 프로세스로 실행한 458개와, 마지막 문서 오류/모바일 열 보완 후 문서·workspace 96개 재검증을 중복 없이 집계했다. 새 문서 런타임 검사는 5개다. TypeScript, 변경 파일 ESLint, production build, diff 공백 검사도 통과했다.

- 화면과 별도 캡처 노드, 전체 교재/수량/금액 포함, 조작 버튼 제외, 모바일 숨겨진 열 포함, 동시 내보내기 차단.
- 실패 후 재시도, 내부 오류 문자열 비노출, 닫은 뒤 파일 생성 차단, 임시 노드·URL 정리.
- 청구 복사 실패 시 전체 텍스트 보존·선택·초점, 다시 열 때 초기화.
- 빈 문서의 저장 비활성·닫기 유지, 조회 실패 시 잘못된 빈 상태 미표시와 재조회.
- 기존 전체 필터 범위 문서 조회, 늦은 응답, 분류·재고·저장·원장·공통 표 회귀 검사.

신규 테스트의 처음 3개 실패는 검사 본문이 아닌 종료 훅에서 발생했다. 테스트용 추가 React 루트를 JSDOM 종료 전에 정리하도록 하네스를 수정한 뒤 통과했다. 합격 결과는 수정 후 실행을 기준으로 한다.

## 실제 브라우저·파일

`127.0.0.1:3137`의 합성 자료로 검수했다. 시작 시 기존 fixture 서버가 응답하지 않아 해당 로컬 프로세스를 재시작했다. 공급처/청구 문서용 합성 읽기 응답을 보강했으며 실제 DB 쓰기는 차단된 환경이다.

| 상태 | 결과 |
| --- | --- |
| 1280×720 이미지 생성 전/후 | 창 `(64,24,1152,672)`, 상단 도구 영역 `(65,90,1150,57)` 동일. 본문 가로 초과 0px. |
| 390×844 문서 스크롤 | 창 `(16,16,358,812)`, 하단 `(17,706,356,121)` 유지. 본문 스크롤 295px와 표 가로 이동 80px, 본문 가로 초과 0px. |
| 주문/반품/청구 준비 | 해당 문서 제목·수량·금액·발신 표시, 청구 전체 복사 성공, 문서 오류의 재조회 동선 확인. |
| 데스크톱 출력 | PNG 2174×1204, PDF 1페이지 생성. PNG와 PDF 내부 JPEG를 직접 열어 4종/4권/36,000원 및 위치별 수량·단가·발신을 확인했다. |
| 모바일 출력 | 가로로 숨겨진 열을 포함한 PNG를 생성해 전체 교재명·위치별 수량·단가·금액을 확인했다. |

첫 복제 출력 시 캡처 대상 자체에 화면 밖 위치를 지정해 빈 이미지가 생성됐다. 화면 밖 위치를 부모 컨테이너에 지정하도록 고친 뒤 실제 PNG/PDF를 재생성·검수했다. 잘못 생성된 파일은 제거했다. 모바일 출력은 기존 반응형 문서의 세로 메타데이터 배치를 유지한다. PDF는 기존 단일 이미지 페이지 방식이며 A4 다중 페이지 출력까지 검증한 결과가 아니다.

문서의 내용·구조는 레이아웃과 접근성 속성을 제외한 AST 비교에서 동일하다. 교재명·문서 메타데이터·표 열·수량·단가·금액을 유지했다. 이번 화면 구성 외 기존 workspace 함수 201개와 서비스 호출 25곳이 동일하다. 공급처 미지정 이름 표시만 모델에서 별도로 보완했다.

증거는 `.codex-artifacts/textbook-document-dialogs-20260910/`의 개별 로그, `final-focused.log`, `test-results.json`, `preservation.json`, `document-preservation.json`, 좌표 JSON, 화면 캡처와 `order-export.png`, `order-export.pdf`, `mobile-order-export.png`에 있다. 검수 후 화면 크기를 복원하고 수정된 주문서 창을 열어 두었다.

운영 성능·전체 CLS 수치를 주장하지 않는다. 실제 주문/반품/청구 전송, DB 변경, 운영 저장, 푸시·배포는 수행하지 않았다.
