## 재현한 결함과 수정

관리자 등록 목록에서 모바일 카드를 Enter로 열고 실제 상세 로딩이 끝난 뒤 Escape로 닫으면, 상담 완료 탭과 전체 범위는 유지되지만 `document.activeElement`가 `BODY`로 이동했다. 모션 감소 상태에서도 닫기 완료 후 재확인했다.

등록 상세는 제어형 Radix Dialog를 직접 열며 연결된 `DialogTrigger`가 없다. 공통 `DialogContent`에 명시적으로 선택하는 `restoreFocusToOpener` 옵션을 추가하고 등록 신청서 host에 적용했다. 열기 직전 요소와 pathname을 기록하고, 닫힌 뒤 여전히 연결돼 있고 보이는 활성 요소에만 `preventScroll`로 복귀한다. 외부 `onCloseAutoFocus`가 기본 동작을 취소하면 이를 존중하고, 다른 pathname으로 이동하면 이전 목록에 포커스를 주지 않는다. 기존 호출부의 기본 동작은 유지한다.

[Radix Dialog 공식 문서](https://www.radix-ui.com/primitives/docs/components/dialog)의 autofocus 이벤트와 실제 설치된 컴포넌트를 확인했다. 새 패키지·DB·업무 정책 변경은 없다.

## 수정본 검증

- JSDOM에서 실제 React/Radix 공통 컴포넌트로 재현 테스트의 수정 전 실패를 확인했다. 수정 후 7/7: 로딩 뒤 카드 복귀, 다시 열린 다른 카드 복귀, 중첩 창의 부모/원래 카드 복귀, 숨김·비활성·제거된 대상 제외, 다른 경로 이동 제외, 호출자 autofocus 우선.
- 등록 workspace, 지연 로딩, 청강 초안 이동, 알림톡 미리보기, 사이드바 포커스, 교재 문서 다이얼로그를 포함한 관련 회귀 318/318 통과.
- 로컬 `127.0.0.1:3209`의 실제 등록 fixture를 Chrome에서 검증했다. PC 행 Enter→Escape, 모바일 카드 Enter→닫기 버튼, 다크·모션 감소 모바일의 중첩 이력→부모 버튼→Escape→카드 복귀가 모두 통과했다. 문서 가로 넘침 없음. 실제 DB 저장의 증거는 아니다.
- 프로덕션 빌드(내장 TypeScript 검사 포함), 별도 `tsc --noEmit` 통과. 전체 린트 오류 0·기존 경고 5개. 후속 배포 결과는 릴리스 기록에 최종 기록한다.

## 남은 검증과 한계

1. 실제 인증한 안전한 테스트 DB에서 저장→재조회→목록 복귀, 실제 교사·조교·조회 계정의 업무 흐름, 전역 모든 탭/다이얼로그/실패·재시도 상태 조합은 아직 미검증이다. 이전 로컬 fixture/격리 SQL 테스트와 합쳐 실제 저장 완료라고 보고하지 않는다.
2. 교재 설정의 권한 조회 일시 실패는 새로고침으로 회복했지만 원인은 확정하지 못했다. 운영 편집 권한을 우회하거나 완화하지 않았다.
3. CDP 이벤트 이력이 잘려 전체 19개 이동의 요청 수·HTTP 실패 수·응답 크기를 신뢰성 있게 집계하지 못했다. 이번 실행을 네트워크 오류 0회나 성능 개선 근거로 사용하지 않는다.
4. 공개 수업 summary 재검증의 기존 network 실패는 미해결이다. 이전 진단의 172175ms는 서버 진단 구간이며 사용자 응답 시간으로 해석하지 않는다.
5. 이번 포커스 수정에 대해 성능 전후 수치를 새로 측정하지 않았다. 앞선 동일 fixture 비교와 구분하며 성능 향상률을 주장하지 않는다.
