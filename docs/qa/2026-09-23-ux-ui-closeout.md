## 완료한 변경

- 캘린더 입력 창의 일정 유형·시기·학교·과학 영역을 실제 선택 제어의 label과 연결했다. 학년 메뉴는 필드 이름과 현재 선택을 함께 읽는다.
- 일정 추가·저장·삭제·닫기와 학년 선택에 공통 `Button size="form"`을 사용한다. 모바일 44px, 데스크톱 36px 규격을 재사용하며 색·글꼴·저장 payload를 바꾸지 않았다.
- 수업계획의 기존 실패 12건 중 7건은 퇴역한 교재/진도 편집·모드 탭·장식 타임라인을 요구하므로 제거했다. 나머지 5건은 현재 일정 전용 화면의 이름·배치에 맞췄다. 현재 교재 필터는 `class-textbook-picker-model`, 학습 이력 보존은 `schedule-only-plan`, 저장·초안·중복 요청·생성 미리보기는 `class-schedule-draft-navigation`에서 검증한다.
- 실제 렌더링한 일정 전용 화면에서 주 행동 중복 없음, 구 진도 URL로 진입해도 교재/진도 편집 없음, 저장 없이 복귀, 미저장 상태에서 ‘계속 편집’ 후 초안 보존을 추가 검증한다. 실패 검사를 skip 처리하지 않았다.
- 수업 상세의 ‘연결 교재’ 기대값을 현재 ‘사용 교재’로 정비했다. 추가로 발견한 캘린더의 구 한 주 목록 기대값 1건도 상세 열기가 가능한 공용 Calendar 복구 경로로 정비했다.
- 정비한 검사와 캘린더 실제 컴포넌트 검사를 필수 guardrails CI에 포함했다.

## 캘린더 간헐 조회 조사

운영 로그인 상태에서 기존 조회 1회, 캐시를 비활성화한 새로고침 3회, 10월 이동 및 9월 복귀 2회를 측정했다. `get_operations_calendar_range_v1`은 모두 HTTP 200으로 완료됐고 브라우저 요청 시간은 각각 99 / 25 / 26 / 22 / 896 / 188ms였다. 측정 구간의 네트워크 실패와 브라우저 error는 0건이다. 선택 목록과 과학 영역 RPC도 200이었다. 임시 캐시 설정은 복원했다.

운영 `pg_stat_statements`에서 주 캘린더 호출 집계는 171회, 평균 실행 227.06ms, 최대 3050.79ms였다. 이 집계는 성공적으로 기록된 SQL 실행이며 브라우저·인증·네트워크 전체 시간이나 과거 취소 요청을 증명하지 않는다. 클라이언트의 기존 8초 요청 제한과 자동 재시도 금지 계약을 유지했다.

**과거 최초 실패는 이번 조사에서 재현되지 않았고 원인은 확정할 수 없다.** 실패 당시 HTTP 상태/SQLSTATE/요청 ID가 없어 특정 DB·네트워크 원인으로 귀속하거나 근거 없이 제한시간을 늘리지 않았다. 현재 장애는 관찰되지 않았다. 재발할 경우 실패한 RPC 이름, 시각, HTTP 상태, 요청 중단 여부를 함께 확보하면 다음 조사의 범위를 좁힐 수 있다.

실패·정상 0건 구분, 같은 범위 재시도, 이전 결과 유지, 역순 응답 무시, 과밀 후 한 주 복구와 상세 접근은 격리된 실제 컴포넌트 테스트로 별도 검증했다.

## 검증 결과

- 수업계획·교재 관련 102개 테스트 통과, skip 0.
- 캘린더 폼·조회·복구 관련 77개 테스트 통과, skip 0.
- TypeScript 및 변경 파일 ESLint 통과. pnpm 실행 래퍼가 미승인 의존성 build script 단계에서 멈춰, 이미 설치된 tsc/eslint 실행 파일로 검사했다. 새 의존성 build script를 승인하거나 실행하지 않았다.
- 합성 Supabase 환경의 Next production build 통과. 이 빌드는 컴파일 검증이며 운영 데이터 조회 증거와 구분한다.
- 합성 데이터의 실제 Chrome에서 일정 유형·시기·학교의 접근 가능한 이름과 ‘학년 전체’ 확인. Tab → 유형 목록 → Escape 후 제어 초점 복귀 확인.
- 같은 공용 폼을 쓰는 학교 연간 일정표의 미입력 셀 → 추가에서도 이름과 미리 선택된 학교·학년·시기가 올바르게 읽히는 것을 확인했다.
- 390×844에서 추가/저장 버튼 44px, 가로 넘침 없음. 메모에서 Tab으로 저장 버튼에 도달하며 화면 안으로 스크롤됨. Escape로 닫힌 뒤 새 학사 일정 버튼에 초점 복귀.
- 720×450의 좁은 유효 공간에서도 가로 넘침 없이 저장·닫기에 도달. 이 결과를 실제 200% 브라우저 확대와 동일한 검증으로 표기하지 않는다.
- 운영에서 에뮬레이션 터치 이벤트로 일정 창 열기·닫기 및 초점 복귀 확인. 운영 저장·삭제·상태 변경·발송은 하지 않았다.

## 환경 때문에 확인하지 못한 항목

- 실제 Chrome 확대 배율과 VoiceOver: macOS 제어 도구가 잠긴 Mac을 반환하여 실행하지 못했다. 브라우저 접근성 트리와 키보드 검증은 완료했지만 실제 음성 읽기 순서 검증을 대체하지 않는다.
- 실기기 터치: 연결된 모바일 실기기가 없어 실제 iOS/Android 기기 검증은 하지 못했다. 위 결과는 Chrome 터치 에뮬레이션이다.

기존 구현 문서의 ‘배포 전’과 ‘기존 실패 13건’은 당시 기록이다. PR #66 운영 반영은 완료했으며, 이 문서가 후속 정비 상태를 설명한다. 이번 추가 변경의 CI·병합·운영 확인 결과는 PR과 로컬 `output/ux-closeout/` 배포 기록에 보존한다.
