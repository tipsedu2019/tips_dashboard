# Basic class information saves preserve authored lesson history

The class-management form sends a full basic-information patch to `update_class_operational_v1`; it does not send `schedule_plan`. Before this change, updating the weekly classroom could change inferred occupancy of old lessons and run the complete operating-reference validator. An old lesson without a time then rejected an otherwise independent classroom edit with SQLSTATE `23P01` (`timetable_resource_conflict`). The isolated fixture reproduces this with 80 pre-existing authored rows, including missing historic time and overlapping rows.

## Exact behavior and boundary

One existing function is replaced: `public.update_class_operational_v1(uuid,jsonb,uuid,jsonb)`. For a patch without `schedule_plan` and without closing (including `개강 준비 ↔ 수강`), the existing private exact-row capability is used. It binds the before and expected after row to the authenticated actor, class, request, and transaction. The ordinary basic save does not build the dated/weekly comparison set. It preserves the saved lesson-plan JSON and learning data byte-for-byte as JSON values. Other classes are not written.

Entered nonempty classroom/teacher labels must resolve uniquely in their existing catalogs. Changed weekly strings must have valid weekday/time syntax and intervals; start 24:00 is invalid, end 24:00 is allowed. Existing unchanged missing or malformed fields are not revalidated while editing a different field. Empty/unassigned classrooms remain valid. Another class occupying the same resource is not a blocker for this basic-info command, consistent with the requested input-preserving policy.

Authentication, row and resource locks, exact-row guards, receipt replay, different-payload request rejection, existing table constraints, and textbook retirement behavior remain. Expected-row textbook projection exactly matches the existing BEFORE trigger whenever either textbook field is present and usage is an object, including explicit usage changes and usage-only retirement. A metadata-only update sets the unchanged room as well so the existing statement guard verifies every basic edit. An unexpected trigger that rewrites the lesson plan fails atomically. Notifications and approvals are not sent or executed.

Lesson-plan-only writes keep PR161's existing CAS/input path. Mixed basic-plus-plan commands, closing and attempts to reopen a closed class, normalized weekly-default writes, timetable presets, direct table writes and makeup approval retain their prior separate paths. The class-management room edit is a basic-only command, so none of those other paths is required for the reported fix. The legacy Agent weekly-time command uses the same ordinary RPC and therefore also accepts overlapping resource input; its credential scope, target version, preview rollback, receipt and replay protections remain. Its normalized weekly branch retains the separate defaults writer.
