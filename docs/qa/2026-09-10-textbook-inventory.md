# 재고 실사·이력 화면 정돈

2026-09-10 · `codex/dashboard-apple-design-20260909` · 로컬 3137 합성 데이터

## 변경

- 재고 실사와 재고 이력을 각각 공통 프레임·도구 모음·표 셀·스크롤 영역·모바일 영역·페이지 탐색으로 구성했다.
- 데스크톱 교재명과 출판사·위치를 줄바꿈한다. 중복 위치 열을 교재 보조 정보로 옮기고 표 최소 너비를 1260px에서 1160px로 줄였다. 현재→실사→차이 순서를 유지하며 수량 입력 옆에 현재값 입력/초기화를 배치했다.
- 데스크톱과 모바일은 `InventoryCountQuantityInput`, `InventoryCountSubmitButton`, `InventoryCountDifference`를 재사용한다. 반영 가능/진행/비활성은 공통 Button을 사용한다.
- 모바일에 공통 행 선택 체크박스를 추가해 기존 선택 반영 흐름을 사용할 수 있게 했다. 작은 정보 카드 세 개를 한 줄로 합치고, 폼 전체를 누를 때 축소되던 효과와 별도 그림자를 제거했다.
- 위치·종수 반복 배지, 실사 기준 배지, 그룹의 권장 건수 반복 표시를 줄였다. 권장·대기·완료·전체 필터는 0건이어도 유지하고 모바일에서 두 열로 배치한다. 권장 분류의 업무 기준은 변경하지 않았다.
- 최종 실사 문구의 반복 날짜를 제거하고, 긴 이력 제목·메모를 끝까지 읽을 수 있게 했다. ‘최근 N건’의 페이지 건수 배지를 제거하고 번호형 페이지 탐색에서 정확한 범위를 표시한다.
- 공통 교재 처리표의 고정 작업 헤더를 불투명한 배경과 z-index로 보완해 뒤쪽 열 글자가 비치지 않게 했다. 실사 상태 배지도 다크 테마에 맞췄다.
- 위치 확인/목록 로딩, 조회 실패, 필터별 빈 결과를 구분한다. 예를 들어 완료 0건은 ‘완료한 실사가 없습니다’로 표시한다. 이력도 조회 전부터 ‘이력이 없습니다’로 단정하지 않는다.

## 보존

기존 필터·서버 페이지·순서·그룹 접기·위치, 수량 및 메모 정규화, 0권 반영, 최신 잔고 조회, 예상 수량, request ID, 권한·인증, 선택/입력 revision, 실패 후 재시도와 완료 후 갱신을 유지했다. 실제 저장 함수는 변경하지 않았다.

시작 소스와 최종 함수 선언 비교에서 211개가 동일하다. 변경 함수는 화면 조합, 실사 표, 모바일 폼, 이력 표, 상태 색상 5개이며 입력·반영·차이 표시 컴포넌트 3개를 추가했다. 함수 비교는 코드 범위의 증거이며 아래 런타임 검사를 대신하지 않는다.

페이지당 10/15/20행과 기존 서버 조회 경계, 메모화 및 content-visibility를 유지했다. 이번 단계는 입력 UI 중복을 없애고 업무 접근성을 개선한 것으로, 추가적인 시간 성능 향상 수치를 측정하거나 주장하지 않는다.

마지막 로딩/이력/테마 보완 뒤 화면 소스·렌더러 144개를 재실행해 모두 통과했다. 위 187개에 포함되는 재검사다. TypeScript, 변경 제품 파일 ESLint(오류·경고 0), 최종 production build 및 `git diff --check`도 통과했다. 로그는 아래 증거 폴더에 있다.

## 실제 브라우저

- 데스크톱 1280×720, 교재 23건 중 첫 10건: 문서 clientWidth/scrollWidth 1265/1265px, 표 스크롤 영역 944px에 1160px 표를 수용한다. 긴 제목 셀 260px에 가로 넘침 없이 줄바꿈한다.
- 표에 키보드 초점을 두고 ArrowRight로 scrollLeft 0→40px 이동을 확인했다. 마지막 작업 헤더는 불투명한 테마 배경, sticky, z-index 20이다.
- 모바일 390×844: 문서 375/375px, 카드 315/315px로 가로 넘침이 없다. 긴 제목, 수량·메모·초기화·반영·체크박스가 카드 안에 표시된다.
- 현재 13권인 교재에 0을 입력해 차이 -13과 단건/선택 반영 활성 상태를 확인했다. 메모 입력과 초기화를 확인했으며 실제 반영 버튼은 누르지 않았다.
- 완료 0건 선택 후 완료 필터가 그대로 남고 정확한 빈 문구가 표시된다. 별도 합성 오류/지연 모드에서 위치 재시도 안내, 목록·이력 오류 및 로딩 문구를 확인했다.
- 재고 이력의 긴 제목·메모·실행자가 표시된다. 삭제는 실행하지 않았다.
- 다크 테마의 입력·버튼·상태 색상 확인 후 원래 라이트 테마로 복원했다. 임시 viewport도 1280×720 기본값으로 복원했다. 최종 검수 탭 콘솔 오류 0.

키보드·폼·오류 구분 점검에는 저장소가 지정한 [Vercel Web Interface Guidelines revision](https://github.com/vercel-labs/web-interface-guidelines/blob/e3d624baaf29dc1fc645aff3e38f03e564d2d6b1/command.md)을 참고하고 TIPS의 기존 입력·권한 계약을 우선했다.

## 증거와 제한

`.codex-artifacts/textbook-inventory-20260910/`에 시작 소스, 최종 함수 비교, 변경 전후 데스크톱·모바일·다크 화면, DOM 너비, 키보드 스크롤, 빈 결과·오류·로딩 상태 및 검사 로그를 저장했다. 합성 전송 계층의 재고 이력과 완료 필터 요약 응답을 실제 조회 계약에 맞춰 보완했다.

로컬 합성 데이터 검수다. 실제 재고 반영·삭제·저장·외부 전송·DB 변경은 하지 않았다. 푸시·배포하지 않았다. 정산 화면 전체 개편은 이번 단계에 포함하지 않는다.
