# 목록 필터 직접 노출

학생관리·수업관리·수업계획에서 필터 버튼 안에 상태 조건 하나만 남아 있어, 버튼을 누르는 단계를 제거하도록 요청받았다.

## 반영

- 세 화면에서 일반 필터 버튼과 팝오버를 제거했다. 학생관리는 재원 상태·학교 구분·학교·학년, 수업관리와 수업계획은 수업 상태·과목·학년·선생님·강의실을 바로 표시한다.
- `DataTableFilters`와 필드 폭 토큰을 공통으로 사용한다. 상태를 먼저 두고 데스크톱에서는 조건을 한 줄에 배치하며 공간이 부족하면 줄바꿈한다. 390px 모바일에서는 두 열을 사용한다.
- 활성 조건이 있을 때 초기화 버튼 하나를 조건 옆에 표시한다. 선택값은 컨트롤에서 확인하므로 중복 필터 배지를 제거했다. 수업계획의 업무량 요약과 기존 작업 분류·보기 기능은 유지했다.
- 학생 검색 X 버튼에도 눌릴 때 세로 중앙 정렬이 유지되도록 수정했다. 앞선 수업 검색 버튼 수정과 같은 방식이며 실제 포인터 클릭으로 초기화를 확인했다.
- 필터 값과 선택지, 종속 조건 초기화, URL·페이지·정렬·행 선택 및 데이터 조회 계약은 유지했다. API·DB·권한 코드는 이번 단계에서 변경하지 않았다.

## 자동 검사

- 관련 Node 테스트 **136/136 통과**. 관리 목록과 academic/operations pagination, 검색/필터 전환, 기간 URL 정리, 직접 노출된 조건 및 초기화, 공통 표와 toolbar를 포함한다.
- 제품 TypeScript no-emit, 변경 대상 ESLint, Next production build, `git diff --check` 통과.
- 기존 테스트의 팝오버 열기 및 중복 요약 기대를 직접 노출 방식으로 갱신했다. 실패/재시도·권한 변경·지연 응답·페이지/URL 보존 검사는 유지했다.
- 증거: `.codex-artifacts/filter-toolbar-20260910/`의 `tests.log`, `typecheck.log`, `eslint.log`, `eslint-tests-final.log`, `build.log`.

## 브라우저

실제 제품 컴포넌트에 합성 데이터·서비스를 연결한 3137 fixture에서 검수했다. 운영 데이터를 변경하지 않았다.

- 세 화면의 1357×987 데스크톱과390×844 모바일에서 상태 및 나머지 조건이 바로 노출되고 일반 필터 버튼이 없는 것을 확인했다. 모바일 문서의 가로 넘침은 없다.
- 수업관리: 수업 상태를 개강 준비로 바꾸면 URL에 반영되고 조건 초기화로 수강 기본값을 복원한다.
- 학생관리: 모바일에서 퇴원 선택 → 합성 학생1명 → 조건 초기화 → 전체8명 복원을 확인했다. 검색 입력 및 X 버튼 클릭으로 검색어·q 제거도 확인했다.
- 수업계획: ArrowDown/Enter로 수학 선택 → 과목 컨트롤로 초점 복귀 → URL의 subject와 수업1개 반영을 확인했다. 모바일 초기화로5개 조건의 기본값과 전체 목록을 복원한다.
- 초기화 버튼은 각 필터 영역에 하나만 있으며 기본 조건이면 사라진다. 필터 변경은 기존 조회 경로를 사용한다.
- 화면 기록: `classes-desktop.png`, `classes-mobile.png`, `students-desktop.png`, `students-mobile.png`, `students-mobile-filtered.png`, `curriculum-desktop.png`, `curriculum-mobile.png`, `curriculum-mobile-filtered.png`. 상태 기록은 `browser-checks.json`이다.

이번 필터 UI 범위의 로컬 구현과 검수는 완료했다. 푸시·배포하지 않았다.
