# 교재 재고 등록·수정 및 상세 창 통일 · 2026-09-10

19단계의 공통 폼을 교재 재고 등록·수정과 상세 조회에 확장했다. 별도 작업 브랜치 `codex/dashboard-apple-design-20260909`에서 구현했다. 앞선 필터 안정성 조사와 공통 컨트롤 기준을 따른다.

## 적용

- 교재명은 전체 너비, 과목·상태는 두 열로 배치했다. 학교 구분과 학년에는 각각 전체 행을 제공해 글자가 세로로 꺾이지 않는다. 모바일 학년은 3열, 데스크톱은 6열이다.
- 등록·수정은 기존 `FormDialogContent`를 재사용한다. 제목·하단 행동을 고정하고 본문만 스크롤한다. 저장 중 이름과 버튼 크기를 유지하며 실패한 입력을 보존하고 오류에 초점을 옮긴다. 마스터 저장에도 같은 사용자·작업의 동시 제출 차단을 적용했다.
- 처음 열었을 때 여러 필수 경고가 동시에 표시되던 부분은 하단의 다음 입력 안내로 통합했다. 필수 분류 검증, 중복 교재 확인, 조회 실패 시 저장 차단은 그대로다. 분류 설정 조회 오류와 재시도는 창 안에 표시한다.
- 중복 교재 목록도 공통 Button을 사용한다. 긴 교재명을 줄바꿈하고 출판사·분류를 다음 행에 표시한다. 새 교재 중복으로 실제 차단될 때만 ‘저장 잠김’을 표시한다.
- `DetailDialogContent`와 `FormDialogContent`가 내부 프레임·헤더·본문 스크롤 여백을 공유한다. 교재/구매 상세의 대기·오류 창은 편집 창과 같은 42rem 기준, 출고 상세는 34rem 기준을 사용한다. 화면 크기에 맞춰 높이를 제한한다.
- 출고 상세의 작은 카드 4개를 설명 목록으로 바꿨다. 교재명·대상을 전체 너비로 표시하고, 구분·상태·수업·위치·출고월·처리일시·수량·금액·기존 메모를 보여준다. 이미 조회한 데이터만 사용한다. 추가 API 요청은 없다.

출고 지연 fixture의 타임아웃 오류에서 재시도했고, 정상 긴 제목 fixture로 이동해 완료 화면을 비교했다. 같은 요청의 성공 재시도·본문 유지 여부는 런타임 하네스에서 별도로 검증했다. 수정 중 합성 데이터의 제목/이름·수령인/선생님 값 불일치는 기존 응답 검증에 의해 거부됐으며, fixture 값을 일치시킨 뒤 최종 화면을 검수했다.

스크린샷 `desktop-master-error.png`, `mobile-master-bottom.png`, `desktop-sale-detail.png`, `mobile-sale-detail.png`, `desktop-master-edit.png`와 좌표 JSON은 같은 artifact 폴더에 있다. 검수 후 모바일 크기를 복원했다. reduced-motion은 공통 프레임의 기존 애니메이션 제거 기준을 사용하며 OS 설정 전환은 이번에 측정하지 않았다. 정착된 좌표 비교는 전체 CLS·운영 성능 측정이 아니다.

## 보존과 범위

변경 전후 AST 비교에서 기존 함수 199개와 서비스 호출 25곳이 동일했다(`preservation.json`). 변경 함수는 화면 배치, 피드백 초기화와 제출 보호에 한정된다. 저장 페이로드·분류·중복·수량·가격 계산과 인증/권한·DB·서비스 계약은 유지했다.

이번 단계의 공통화는 디자인 일관성과 유지보수 개선이며 별도 속도 향상 수치는 주장하지 않는다. 문서 작성·출력 창은 이번 범위에 포함하지 않았다. 실제 운영 저장, 재고 변경, 외부 전송, DB 변경, 푸시·배포는 수행하지 않았다.
