# 교재 일괄 속성 변경 창

- 날짜: 2026-09-10
- 브랜치: `codex/dashboard-apple-design-20260909`; 기존 누적 변경 보존.
- 범위: 교재 재고의 선택 → 속성 변경 → 저장/취소. 이전에 완료한 개별 등록·수정·문서 창을 재설계하지 않고 남아 있던 인라인 일괄 폼을 정리했다.

## 변경

- 목록 안에 펼쳐지던 속성 입력을 기존 `FormDialogContent`로 옮겼다. 검색·필터·고정 컬럼·목록 위치를 유지하며 제목, 내부 스크롤, 하단 피드백과 저장·취소 배치를 재사용한다.
- 과목/세부과목, 출판사/판매가, 상태 순서로 정렬했다. 학교·학년 변경은 해당 옵션을 선택하면 표시하며 화면 순서와 키보드 순서를 일치시켰다.
- 변경할 값이 없거나 필수 분류가 유효하지 않으면 저장할 수 없다. 분류 조회 실패와 재시도는 창 안에서 표시한다.
- 취소하면 선택은 유지하고 초안을 초기화한다. 실패하면 선택과 초안을 보존한다. 성공 후 창과 선택을 정리하고 검색창으로 초점을 돌려준다.
- 일괄 속성 저장도 기존 동시 제출 차단을 재사용한다. 열기/닫기마다 작업 회차를 구분해 이전 요청의 늦은 실패·성공이 다시 연 창을 변경하지 못하게 했다.
- 공통 폼 하단 버튼의 모바일 높이를 44px로 맞췄다. 데스크톱은 기존 36px이며 색·상태·모션은 기존 Button 토큰을 그대로 쓴다. 새 폼의 입력/선택도 같은 높이다.

## 기능·성능·보존

- 관련 고유 검사 100개: workspace 계약91, master controls6, metadata 복구1, 기존 선택 동시성2. 일부 검사는 독립 프로세스로 검증했다. 집계/로그는 같은 증거 폴더의 `validation-summary.txt`에 있다.
- 실제 워크스페이스 검사에서 무변경 제출 금지, 취소/재열기, 중복 제출 1회, 실패 후 재시도 성공, 같은 초안을 재입력한 새 창에 대한 늦은 결과 차단을 확인했다.
- 최종 제품 build(TypeScript 포함), 대상 ESLint, `git diff --check` 통과.
- 변경 직전 snapshot과 비교해 textbookService 호출식25곳, 기존 함수206개의 내용이 동일하다. 변경된 저장 함수는 폼 생명주기·동시 제출 보호와 성공 후 UI 정리만 보완했다. 데이터 payload 생성, 선택 대상, 금액·재고 계산과 API/DB 계약을 유지했다.
- 주문서·반품 요청서 카드 구조/내용 AST 동일. 이번 단계에서 PNG/PDF 출력물을 새로 생성해 비교하지 않았다.
- 194px→0px는 해당 조작의 표 위치 측정값이며 전체 CLS/렌더링 속도 개선 수치가 아니다. 공용 컴포넌트 재사용만으로 성능 향상을 주장하지 않는다.
- 로컬 브라우저 저장은 null Supabase fixture 경계에서 차단된다. 성공 경로는 제어된 합성 transport의 테스트로 확인했다. 운영 저장·고객 발송·푸시·배포는 수행하지 않았다.
