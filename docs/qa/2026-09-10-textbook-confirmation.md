# 교재관리 확인 창 통일

- 날짜: 2026-09-10
- 브랜치: `codex/dashboard-apple-design-20260909`; 누적 변경 보존.
- 범위: 교재 정리·미사용 보관함 비우기, 요청 삭제, 공급처/고객 반품, 출고 취소/이력 삭제, 재고 이력 삭제 확인 창.

## 적용

- 중복된 확인 창 2개를 공통 `ConfirmationDialogContent`로 통일했다. 기존 `DialogFrame`, Radix modal, Button, Alert와 표면/모션 토큰을 재사용한다. 패키지 설치·교체 없음.
- 제목과 처리 결과 설명, 대상 목록, 하단 취소/실행을 분리했다. 긴 교재명과 상세 정보는 줄바꿈하며, 대상은 최대 5개와 나머지 건수를 표시한다. 미사용 보관함의 전체 대상 수를 별도로 전달해 12건 중 5개 미리보기에도 ‘외 7건 더’가 맞게 표시된다.
- 교재 정리 대상은 창을 열 때 고정한다. 성공 후 목록을 갱신하는 중에도 대상 수 변화로 창 크기가 흔들리지 않는다.
- 확인 전에는 기존과 같이 쓰기를 실행하지 않는다. 실행 중 버튼 이름은 유지하고 진행 상태를 표시하며 중복 실행·닫기를 차단한다. 성공 후 닫고, 실패하면 대상과 오류를 남겨 재시도할 수 있다.
- 취소가 최초 초점을 받는다. Esc 취소 후 시작 버튼으로 복귀하고, 처리 성공으로 해당 행/메뉴가 없어질 수 있을 때는 목록 검색으로 이동한다. 대상 영역은 키보드로 스크롤할 수 있다.
- 교사용 출고 취소에서 ‘학생 미지정’으로 표시하던 오류를 발견했다. 목록에서 다시 찾던 중복 표시 함수를 제거하고 최신 상세 조회 결과의 교재·수령인·교사용/학생용·수업·위치·수량·상태·월을 사용한다. 실행 직전 재조회와 기존 쓰기 계약은 유지한다.

## 근거와 프로젝트 선택 값

- WAI-ARIA의 확인 창 의미, 접근 가능한 제목/설명과 모달 동작을 따른다. 기존 Radix Dialog에 `alertdialog` 역할과 취소 우선 초점, 외부 클릭 차단을 명시했다. [WAI-ARIA Alert Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/), 2026-09-10 확인.
- 비동기 작업이 완료된 뒤 제어 상태로 닫는 방식을 참고했다. [Radix Alert Dialog – asynchronous submission](https://www.radix-ui.com/primitives/docs/components/alert-dialog#close-after-asynchronous-form-submission), 2026-09-10 확인. 문서 표시 버전은 1.1.20이며 프로젝트의 기존 Dialog 의존성은 1.1.15다. AlertDialog 패키지를 설치했다고 주장하지 않는다.
- 너비 최대 512px, 높이 `max(400, 270 + 표시 대상 수×64)`px 및 화면 높이 제한, 데스크톱 버튼36px/모바일44px는 프로젝트 선택 값이다. Apple 공식 치수가 아니다.

- 브라우저 저장은 null Supabase 경계의 `fixture_transport_disabled`로 차단했다. 실제 운영 삭제/반품을 실행한 증거가 아니다.
- 성공·지연·재시도와 중복 실행은 제어된 합성 transport의 실제 workspace 테스트로 별도 검증했다.
- `desktop-cleanup.png`, `desktop-error.png`, `mobile-cleanup-error.png`, `desktop-sale-cancel.png`, `desktop-sale-error.png` 및 좌표 JSON은 `.codex-artifacts/textbook-confirmation-20260910/`에 있다.
- 이전 raw 확인 창을 같은 상태로 캡처한 자료는 이번 단계에서 확보하지 않았다. 잘림은 변경 직전 코드의 `truncate`와 현재 실제 화면을 구분해 기록했다. 오류 전후 좌표 비교는 수정 후 같은 상태에서 측정했다.
- 공통 reduced-motion 규칙과 모션 토큰은 유지했다. 이번 단계에서 OS 모션 감소 설정을 별도로 전환하지 않았다.

## 보존·검증 범위

- 변경 직전 snapshot과 비교해 textbookService 호출식25곳과 기존 함수196개의 내용이 동일하다. 확인 처리의 Promise 결과·중복 실행 보호·완료 후 UI 정리와 대상 표시를 변경했으며, 기존 fresh recheck, 권한, 선택 보호, payload, 재고/금액 계산, API·DB 계약을 유지한다.
- 주문서·반품 요청서 카드 구조/내용 AST 동일. 이번 단계에서 PNG/PDF를 새로 생성해 비교하지 않았다.
- 관련 고유 검사103개 통과: workspace 계약91개, 확인 창 실행 흐름6개, 기존 공통 폼 회귀6개. 먼저 실행한 workspace 집중3개는 91개에 포함하며 중복 합산하지 않았다. 최종 제품 빌드(TypeScript 포함), 대상 ESLint와 diff 공백 검사 통과. 결과와 로그는 같은 증거 폴더의 `validation-summary.txt`, `contracts.log`, 개별 시나리오 로그, `build-final.log`, `lint.log`에 있다.
- 전체 계약 검사에서 이전 inline 이벤트와 workspace 내부 설명 컴포넌트를 찾던 정적 검사2개가 실패했다. 공용화된 현재 위치와 키보드/클릭 초점 복귀 계약을 확인하도록 갱신한 뒤 전체91개를 다시 통과했다.
- 공용화만으로 속도 향상을 주장하지 않는다. 이번 측정은 확인 창 오류·스크롤 전후의 위치 안정성이다.
- 운영 DB 변경·고객 발송·푸시·배포 없음.
