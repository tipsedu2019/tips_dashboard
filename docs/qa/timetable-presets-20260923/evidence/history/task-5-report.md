## Implemented

- `createTimetablePlanService({client,actorScope})` calls the canonical get-plan, get-revision, mutate-item and mutate-plan RPCs with exact argument envelopes and forwards `AbortSignal`; it rejects malformed responses. Future Task 7 transfer methods call `preview_timetable_plan_transfer_v1({p_request})` and `commit_timetable_plan_transfer_v1({p_command})` and cannot fake success while the backend is absent. Transfer result contracts require either a complete authorized snapshot or a delta with class labels, source plan metadata and complete operating reference.
- `createTimetablePlanController({service,actorScope,planId,storage?})` in the canonical model owns one actor/plan. It has `snapshot()`, `subscribe`, `load`, `refresh`, `checkRevision`, `dispatch`, `retry`, `resolveStale`, `undo`, `applyTransfer`, `clearSensitive`, `destroy`. `snapshot()` returns server `snapshot` and optimistic `draft` separately, plus `saveState`, `conflicts`, `referenceStatus`, `recoveryAvailable`, `dirty` and `error`. Save states are idle/saving/saved/error/stale.
- Per-item queues serialize A→B. A submitted request body and requestKey are frozen through uncertain failure and same-tab reload; retry replays that exact body. Server revisions advance only from authoritative results. A newer local draft survives refresh and earlier replies. Replay cannot lower an item revision or restore older shadows. A stale item does not block another item. `resolveStale(itemId,'accept_server'|'reapply_draft')` drops only that item's old command; explicit reapply uses the current server revision and a new key. An ambiguous request can still replay its original receipt even if a refresh saw the write. Undo is a new inverse command bound to the last own saved revision, so another editor's revision prevents a silent overwrite.
- Session storage is keyed by actor scope and plan ID and stores pending edit plus any submitted command identity. Reload in the same tab restores unsaved state for explicit retry. Scope revocation/logout removes that key and clears sensitive state. Old read/save successes and errors from a retired epoch are ignored. Access failures clear scope; transient reference failures preserve prior display, mark it unverifiable and block new saves.
- A narrow watcher subscribes to INSERT/UPDATE of the plan ID and `operating` rows in `timetable_invalidation_signals`; it reads no timetable rows through Realtime. Signals trigger authorized refresh. A 20-second revision/fingerprint check runs only while visible; visibility/focus immediately refreshes. Plan `shadowFingerprint` covers dated changes and KST day rollover. The hook returns the required service state/actions and the controller for Task 6 integration.
- Transfer `applyTransfer` atomically accepts a complete snapshot, or applies item/applied-history delta together with a complete server operating reference and display labels. Task 7 must supply that response shape before enabling transfer UI.
