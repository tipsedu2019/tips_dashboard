Rulings I made

Final reply draft, chronological. Reconcile against every Ruling line before use.

1. ‘진행’을 로컬 구현 승인으로 적용했습니다. 변경 시 추가 구현을 되돌리는 비용이 있습니다.
2. 순차 구현과 독립 검토를 사용했습니다. 비용은 검토 시간 증가입니다.
3. 잠금·그림자 조회 기반을 앞 단계로 옮겼습니다. 변경 시 단계 간 책임 조정이 필요합니다.
4. 그림자에 최소 수업 표시 정보를 추가했습니다. 변경 시 응답 필드 조정이 필요합니다.
5. 기존 stale 오류 변환 일부를 운영 잠금 단계로 옮겼습니다. 변경 시 검증 순서 조정이 필요합니다.
6. 정규화 시간표는 실제 슬롯을 읽습니다. 변경 시 기존 문자열 호환을 다시 검증해야 합니다.
7. 모호한 옛 강의실 문자열은 기존 해석을 유지했습니다. 변경 시 호환 처리 보수가 필요합니다.
8. 네트워크 없는 DB는 컨테이너 내부 연결로 경쟁을 검증했습니다. 다른 환경에는 실행기 조정이 필요합니다.
9. 드래그는 시각 차이로 계산해 원래 분 오프셋을 보존합니다. 변경 시 화면 변환 로직 조정이 필요합니다.
10. 교사·강의실 이름의 기존 중복 금지를 유지했습니다. 동명 자원 지원에는 별도 스키마 설계가 필요합니다.
11. ID·수정번호만 담는 변경 알림 테이블을 추가했습니다. 추가 스키마 유지 비용이 있습니다.
12. 전체 복제는 초안 배치를 보존하고 반영 완료 수업은 미배치로 만듭니다. 변경 시 복제 정책 조정이 필요합니다.
13. 운영 자원 잠금 함수와 키를 통일했습니다. 변경 시 내부 호출부 수정이 필요합니다.
14. 이동·복사 API 타입을 먼저 정의했습니다. 변경 시 타입 계약 보정이 필요합니다.
15. 미배치 수업은 프리셋으로 복사할 수 있지만 운영 반영·이동은 막습니다. 변경 시 검증 정책 조정이 필요합니다.
16. 복구에 필요한 서버 가져오기 API도 구현했습니다. 가져오기 코드 유지 비용이 추가됩니다.
17. 미저장 복구는 같은 탭·세션으로 한정했습니다. 브라우저 종료 후까지 보존하려면 별도 저장 설계가 필요합니다.
18. 자원이 불명확한 신규 수강 배치는 막고 기존 문제의 수정·제거는 허용합니다. 명시적 미지정 상태에는 정책 보완이 필요합니다.
19. 보강 강의실은 정확히 일치하는 유일한 이름만 ID로 연결합니다. 다른 표기 지원에는 검증 보완이 필요합니다.
20. 새 보강 일정은 한국 시간으로 변환합니다. 다른 시간대 지원에는 추가 매핑이 필요합니다.
21. 기간을 지정해도 주간 수강 그림자는 점유를 유지합니다. 일회성 시간표에는 별도 정책이 필요합니다.
22. 기간은 시작·종료일을 함께 입력합니다. 한쪽만 지정하려면 추가 규칙이 필요합니다.
23. 잠금 기반 쓰기는 지원하는 격리 수준으로 제한했습니다. 고급 SQL 클라이언트는 트랜잭션 설정을 맞춰야 합니다.
24. 초 단위 옛 시각은 반올림하지 않고 미해결로 보존합니다. 초 단위 편집에는 시간 모델 확장이 필요합니다.
25. 보강의 업무 오류와 실제 동시성 오류를 분리했습니다. 기존 오류 코드 의존 클라이언트의 호환 보수가 필요할 수 있습니다.
26. 확정 거절은 수정·폐기하고 불명확한 결과는 원래 요청을 재확인합니다. 오분류 시 중복·입력 손실 위험이 있어 좁은 분류를 검증했습니다.
27. 기존 삭제 감사 결함과 분리해 참조 삭제만 합성 트랜잭션에서 검증했습니다. 실제 삭제 API 검증은 별도로 남습니다.
28. 미배치 항목을 기존 폼에서 원자적으로 해결합니다. 변경 시 편집기·저장 연결 조정이 필요합니다.
29. 보강 강의실 충돌 함수도 오류 코드 정리에 포함했습니다. 승인 클라이언트 호환 검증 비용이 있습니다.
30. 신뢰된 보강 승인·취소 일정 변경에 감사 문맥을 적용했습니다. 범위가 넓으면 보호가 약해져 복원·직접쓰기 차단을 검증했습니다.
31. 제출한 생성·복제·이름·공유·보관 요청도 같은 탭에서 복구합니다. 복구 저장 형식 유지 비용이 있습니다.
32. 느린 회차 집계를 집합 연산으로 바꿨습니다. 결과가 달라지면 충돌 판단에 영향이 있어 전체 JSON 동등성을 검증했습니다.
33. 변경 없는 배치끼리의 중복 계산을 줄였습니다. 누락 위험에 대비해 전체 대상 비교와 DB 검사를 유지했습니다.
34. 운영 저장의 반복 점유 집계도 최적화했습니다. 보호 누락 위험에 대비해 기존 결과와 경쟁 상황을 검증했습니다.
35. 최대 배치 33.6–33.7ms는 목표 32ms 미달로 남겼습니다. 최대 규모의 간헐적 지연과 추가 최적화 비용이 남습니다.
36. 가져오기 요청도 원래 요청키·원본 지문으로 복구합니다. 추가 복구 형식과 테스트 유지 비용이 있습니다.
37. 과목 없는 옛 초안은 임의로 채우지 않고 거절합니다. 해당 원본은 수동 재작성 또는 별도 복구가 필요합니다.
38. 테스트 환경 빌드의 공개 조회 403 로그는 한계로 남겼습니다. 운영 공개 조회 확인과 테스트 환경 개선이 별도로 필요합니다.
39. 일시적 조회 실패의 자동 복구 확대는 보류했습니다. 사용자가 새로고침을 한 번 더 해야 할 수 있습니다.
40. 반영 완료 내역은 현재 요약 화면을 유지했습니다. 더 풍부한 과거 상세 조회에는 추가 UI 작업이 필요합니다.
