# 교재관리 탭 레이아웃 통일 및 고정 컬럼

- 날짜: 2026-09-10
- 작업 브랜치: `codex/dashboard-apple-design-20260909`; 누적 미커밋 변경 보존.
- 승인 범위: 교재관리 각 탭의 버튼·검색·필터·테두리·레이아웃 통일, 컬럼 순서/너비 결정 후 커스터마이징 삭제.
- 증거: `.codex-artifacts/textbook-tab-unification-20260910/`.

## 적용

- 다섯 탭 모두 공용 `DataTableWorkspaceToolbar`를 사용한다. 첫 줄은 검색과 고정 작업 영역, 둘째 줄은 필터, 이어서 목록과 같은 테두리 안의 페이지 이동이다.
- 검색·버튼은 desktop 36px, mobile 44px. 모바일은 검색 → 작업 → 2열 필터 순서이며, 필요한 필터 수에 따라 높이가 달라진다.
- 선택 시 같은 작업 영역 안에서 일괄 작업으로 전환한다. 주문·입고 반품과 출고의 취소·반품·삭제는 공용 더보기 메뉴에 있다. 선택 해제를 추가했다. 실제 처리 함수와 확인 단계는 보존했다.
- 재고 실사의 선택 반영은 항상 같은 자리에 있고, 반영할 선택 수량이 없으면 비활성이다.
- 교재관리의 `useDataTableColumns`, 저장된 숨김 설정 읽기, 컬럼 구성 UI를 모두 제거했다. 다른 관리 화면이 쓰는 공용 컬럼 설정 컴포넌트는 유지한다. 과거 브라우저 설정이 남아 있어도 교재 표에는 적용되지 않는다.
- 구매/출고/실사의 표 머리글·행·선택·작업 고정열을 공용 원시로 통일했다. 모바일 카드도 공용 테두리/선택 스타일을 쓴다.
- 교재관리에서만 root scrollbar gutter를 확보하고 modal scroll-lock 보정과 함께 검증했다. 스크린 미디어에만 적용해 문서 출력 스타일과 분리했다.
- 공용 대화상자는 명시적으로 전달된 시작 버튼으로 포커스를 되돌린다. 교재 수정 → 취소 후 동일한 편집 버튼 복귀, scroll 0 유지 확인.

## 고정 컬럼 설계

아래 수치는 프로젝트 선택 값이며 Apple 공식 치수가 아니다. 교재명은 남는 너비를 사용하고 긴 이름은 줄바꿈한다. 표가 화면보다 넓으면 내부 가로 스크롤을 사용하며 작업 열은 오른쪽에 유지한다.

| 탭 | 고정 순서와 너비(px) | 최소 표 너비 |
|---|---|---:|
| 교재 재고 | 선택40 · 교재 나머지(최소296) · 분류144 · 위치별80 · 합계80 · 판매가112 · 관리48 | 720 + 위치 수×80 |
| 요청 | 교재 나머지(최소288) · 요청104 · 요청자104 · 수업/위치184 · 작업132 | 812 |
| 주문·입고 | 선택40 · 교재 나머지(최소288) · 상태104 · 요청104 · 주문104 · 입고104 · 총판/단가128 · 수업/위치184 · 작업132 | 1188 |
| 출고 | 선택40 · 교재 나머지(최소300) · 대상120 · 상태104 · 수량72 · 수업/위치176 · 작업132 | 944 |

- 요청/주문의 처리일시는 교재명 아래에 유지한다. 주문의 요청자는 수업/위치 보조행에 유지한다.
- 출고월은 수업/위치 보조행에 유지한다. 학생용/교사용 요청·주문·입고 수량은 구분을 그대로 유지한다.
- 재고 위치 컬럼은 현재 등록된 위치 목록을 반영한다. 사용자가 열을 숨기거나 임의로 구성하는 설정은 없다.

## 실제 브라우저 검수

로컬 합성 데이터, CUA Chromium. 운영 검수와 구분한다.

- 1280×720에서 다섯 탭의 toolbar y138/h109, search x297/y150/h36 및 작업 영역 너비340이 일치했다. 한 비교 실행 안에서 검색창/toolbar 너비 차이는 0px이다. 스크롤바 표시 방식에 따라 사용 가능한 전체 너비는 달라진다.
- 이전에는 master와 재고 이력이 있는 탭 사이 scrollbar 유무로 너비 차이15px가 있었다. 공통 scroll container/gutter 적용 후 같은 조건의 탭 비교에서 차이0px.
- 위치 선택 열기/변경, 일괄 선택/메뉴, 출고 검색 결과 없음, 교재 수정 열기/닫기의 관련 좌표는 `browser-metrics.json`에 기록했다.
- 390×844에서 다섯 탭 모두 search x29/y214/w317/h44, 페이지 전체 가로 넘침0px. 필터 수에 따라 2~3행으로 배치되며 높이를 억지로 맞추지 않는다.
- 초기 비동기 위치 옵션이 들어올 때 SelectValue의 텍스트와 Radix portal이 충돌하는 개발 경고를 발견했다. custom children을 일관된 요소로 유지하도록 수정했고, 최종 새로고침/다섯 탭 순회에서 새 console error0건을 확인했다.
- 대표 캡처: `desktop-{master,requests,purchase,sales,inventory}.png`, 동일한 `mobile-*.png`, `desktop-sales-selected.png`, `desktop-sales-empty.png`, `desktop-edit.png`.

## 보존과 검증

- 변경 직전 workspace snapshot과 비교해 서비스 호출25곳의 호출식이 동일함을 확인했다.
- 주문서·반품 요청서 카드의 구조/내용 AST 동일. 본관·별관 기본 문서 위치 상수와 문서 수량·금액·생성 함수를 보존했다.
- 이번 단계에서는 신규 PNG/PDF를 생성해 픽셀 비교하지 않았다. 기존 출력 검수와 현재 문서 dialog/참조 회귀 검사를 구분한다.
- 관련 고유 검사 **187개 통과**: 공용/워크스페이스 계약105, 번호형 렌더러45, 참조/수정 UI30, 문서 dialog5, 필터2. 자원 문제가 있는 렌더러/문서/필터는 독립 프로세스의 성공 증거로 집계했다. 로그 목록과 고유 집계는 `test-validation-summary.txt`에 기록했다.
- 제품 production build(TypeScript 포함), 대상 ESLint, git diff --check 통과.
- 포커스 복귀는 실제 브라우저에서 검증했다. 불필요한 mock 핸들러 검사를 추가하지 않았다.
- [탭별 실제 구현 비교](http://127.0.0.1:3139/unified-tabs.html)와 [출고 실제 화면](http://127.0.0.1:3137/admin/textbooks?textbookTab=sales)을 검수 자료로 제공한다.

## 한계

- 전체 렌더러 테스트를 한 Node 프로세스에 누적 실행하면 기존 JSDOM 자원 문제로 SIGKILL이 발생한다. 개별 프로세스에서의 관련 검사 결과를 합산하며, 일괄 실행 환경 문제를 해결했다고 주장하지 않는다.
- 공용 컴포넌트 재사용과 저장 설정 구독 제거를 수행했으나 전체 속도 향상을 주장하지 않는다. 이번 확정 결과는 레이아웃/상태 통일과 컬럼 구성 제거다.
- 운영 DB 변경·고객 발송·배포는 수행하지 않았다.
