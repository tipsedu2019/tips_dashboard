# 관리팀 AI 업무 연결 확장

사용자 결정 (2026-09-30): 대상 수업을 미리 지정하지 않는다. 현재 및 앞으로 생길 전체 수업을 요청에 따라 수정할 수 있어야 한다. 학교 공식 홈페이지를 조사한 학사일정을 입력·최신화하며, 관리팀 업무 전반으로 API를 확장한다. 기존 1–2개 수업 온보딩 계획은 폐기한다.

## 현재 확인한 경계

PR #81의 수업 API와 최종 SQL writer, 중복 실행 방지, 충돌, 영수증 재조회는 유지한다. 모든 수업 권한은 특정 수업에 대한 필수 정보·일정 충돌·마감/승인 업무 규칙을 무시하는 권한이 아니다. API 연결과 실제 업무 요청은 구분한다. 독립 전자결재 메뉴는 폐기된 기능이며 확장 대상에서 제외한다.

## 구현 순서와 검증

### 전체 수업 및 학교 학사일정

- `agent_credentials.all_classes`를 기본 false로 추가한다. 새 발급 RPC에서 전체/선택 범위를 명시한다. 기존 키는 확대하지 않는다. health 및 연결 목록에 명시적인 `classAccess`를 반환한다. 전체 권한은 새 수업에도 적용한다.
- `/admin/settings/agent-access`에 전체/선택 수업 범위, 학사일정 조회/수정 권한을 제공한다. 설정 목록과 `NativeSelect`, `FormDialogContent`를 그대로 사용하고 `/admin/settings/schools` 및 기존 AI 연결 화면을 비교 기준으로 삼는다.
- 학교 목록과 학교/학년도별 workspace를 제공한다. 안정적인 학교 UUID와 이름·학교급으로 대상을 확인한다. 현재 학교 DB에는 NEIS/주소/공식 URL 필드가 없으므로 이를 이미 검증된 정보처럼 반환하지 않는다.
- 학년도는 3월~다음 해 2월. 최대 100개 일정의 추가/수정을 원자적으로 preview→commit한다. 명시한 항목만 변경하고 기존 메모·시험 범위·관계 데이터는 보존한다. 생략에 의한 삭제는 하지 않는다.
- 기존 일정 ID를 지정한 수정, 정규화한 제목/유형/학년/시작일의 동일 일정 일치 확인, 날짜가 다른 동일 제목 후보가 있으면 명시적 ID 재선택. 묵시적인 중복 추가/임의 병합 방지.
- 공식 출처 URL/자료 제목/확인 시각/발행일/학교 확인 근거를 저장하고 재조회한다. URL을 서버에서 가져오지 않으므로 SSRF 경로가 생기지 않는다. 출처 확인은 조사한 에이전트의 근거이며 서버가 사이트 내용을 독립 인증했다고 주장하지 않는다.
- preview는 실제 writer를 rollback하여 생성한다. 기존 UI 수정과 경쟁하지 않게 짧은 DB 잠금을 사용한다. commit에서 version 재검사, durable failed receipt와 정확한 SQLSTATE, 같은 key 재조회·재전송을 유지한다. 수업 작업과 달력 작업 영수증 경로를 분리해 기존 클라이언트를 깨뜨리지 않는다.
- 검증: 선택 키 범위 유지, 전체 키의 새 수업 접근, 읽기 키 쓰기 거절, 관리자 지위 상실/키 폐기, 학교·학년도·입력 검증, preview 비변경, 복수 일정 저장/전체 rollback, duplicate/no-op, 동시 UI 변경 stale/P0001, replay/서로 다른 body, 기존 학습/메모 보존, no-send. 실제 DB DTO와 HTTP 소비자 연결 검증. 데스크톱/390px 설정 UI.

### 관리팀 업무 전체 연결 (후속 구현도 사용자 범위에 포함)

| 업무 | 현재 API | 재사용할 업무 구현 | 추가할 연결 |
| --- | --- | --- | --- |
| 수업 기본 정보·주간/날짜별 일정·휴보강 | 지원 | agent-api, 최종 수업 writer | 전체 수업 권한 |
| 학교 학사일정 | 조회만 | academic-calendar-workspace, academic-event-utils, academic_events | 출처가 있는 일괄 추가/수정 |
| 등록·상담·참관·배정 | 미지원 | registration-track-service, registration-observation-service | 단계별 조회·전이·결과 확인 |
| 전반·퇴원·휴보강 승인 | 미지원 | 기존 operations/task RPC·휴보강 워크플로 | 요청 생성/검토/처리; 기존 승인 주체 유지 |
| 학생·수강 명단 | 미지원 | management 학생/수업 관계 서비스 | 동명이인 확인·관계 변경·이력 보존 |
| 교재 요청·주문·입고·출고·반품 | 미지원 | textbook-service 및 원장 RPC | 원장 단위 작업·수량/금액 검증 |
| 선생님·강의실·학교 등 설정 | 카탈로그 조회만 | management 설정 서비스 | 참조 무결성을 지키는 관리 작업 |
| 알림·문자·외부 동기화 | 자동 발송 없음 | 기존 provider/preview/dispatch 서비스 | 명시된 수신자·내용·발송 요청과 실제 전달 결과 분리 |
| 수납·환불·MakeEdu | 이 API에 없음 | 해당 외부 서비스 계약부터 확인 | 존재하지 않는 대시보드 기능을 있다고 가정하지 않음 |

전체 권한 하나로 임의 SQL, 임의 테이블 PATCH, 관리자 인증 토큰을 에이전트에 제공하지 않는다. 기능 목록은 실제 제공 상태를 표시한다. 업무별 계약과 기존 업무 writer를 재사용하여 하나씩 연결하며 미구현 업무를 완료됐다고 보고하지 않는다.

## 인수와 배포

검토된 migration chain과 pgTAP, HTTP/client 계약, 설정 UI를 확인하고 PR/CI 및 운영 transactional preflight 후 배포한다. 뮤즈와는 영어로 계약/검증을 협의하며 요청·막힌 점을 답변에 포함하도록 한다. 새 운영 키의 보안 입력은 사람이 직접 완료한다. 생산 데이터 쓰기는 사용자가 실제 업무를 요청했을 때 수행한다.
