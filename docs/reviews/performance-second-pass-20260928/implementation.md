# 수업계획 조회의 회차 집계 범위 개선

## 문제와 변경

기존 `get_academic_curriculum_numbered_page_v2`는 전체 목록에서 페이지를 이동할 때도 필터에 맞는 모든 반의 회차를 읽었다. 운영의 현재 수강 66개 반에서 6,117개 회차를 집계하고, 마지막 수정 시간도 페이지 행마다 같은 회차 CTE를 다시 스캔했다. 저장된 JSON 회차의 정상 날짜는 검증 함수를 두 번 거쳤다.

새 마이그레이션은 다음 세 가지를 변경한다.

- `viewMode=all`이고 전체 통계를 요청하지 않은 경우, 기존 정렬과 페이지 범위로 반을 먼저 선택한 뒤 해당 반의 회차만 읽는다. 전체 건수는 여전히 모든 적격 반에서 계산한다. 과거 `unlinked` 별칭은 기존처럼 `all`로 정규화한다.
- 통계가 필요한 첫 조회와 회차 상태에 따라 반을 고르는 필터는 모든 적격 반을 집계한다.
- JSON 날짜 검증 결과를 materialized CTE에서 한 번 계산해 재사용하고, `max(updated_at::text)`를 기존 회차 집계에 포함한다.

최종 정의는 `20260922054047_curriculum_schedule_and_class_textbooks.sql`에서 시작한다. 추가 마이그레이션의 6개 치환 대상은 각각 정확히 한 번 존재해야 한다. 일치하지 않으면 `55000`으로 중단한다. 적용 전후 함수 소유자와 ACL이 같아야 한다. 함수 서명, security invoker, RLS, 빈 search_path, 인증/입력 오류 SQLSTATE, 원본 회차와 일정 변경 RPC는 유지한다.

## 로컬 검증

네트워크와 포트가 없는 폐기 가능한 Docker DB에서 전체 기존 마이그레이션 체인 위에 적용했다. 합성 데이터는 트랜잭션 종료 시 롤백했다.

- 관련 pgTAP 5개 파일: **354/354 통과**. 수업계획 파일에는 날짜/상태/저장 모드, 권한, 숨겨진 행, 마지막 수정 시간, 중간/마지막/빈 페이지, 크기 10/15/20 및 모든 상태 필터 검증 **123개**가 포함된다.
- academic 서비스/페이지/조회 Node 테스트 **96/96 통과**.
- Supabase migration layout 검증과 Squawk 통과.
- 원본 함수와 최적화 함수의 전체 JSON 결과를 관리자/직원/강사/조교/조회자 × 필터 7개 × metadata 2개로 비교: **70/70 일치**.

`scripts/qa/curriculum-session-benchmark.mjs`의 105개 합성 반(legacy/shadow 100개 × 120회차, normalized 5개 × 120회차), 20행 첫 페이지, metadata=false 조건에서 워밍업 후 기존/개선 함수를 번갈아 25회씩 측정했다.

| DB 실행 시간 | 기존 | 개선 |
|---|---:|---:|
| p50 | 68.463 ms | 13.709 ms |
| p95 | 69.838 ms | 14.303 ms |
| 최대 | 70.688 ms | 14.453 ms |

로컬 합성 데이터의 수치이며 운영 API 지연의 p95가 아니다. 원본 측정은 `benchmark.json`에 보관한다.

## 운영 검증 계획과 현재 기준값

`production-benchmark.sql`은 기존 관리자 권한을 내부적으로 선택한 read-only 트랜잭션에서 조회 RPC만 실행한다. 사용자 정보와 업무 데이터는 출력하지 않는다. 각 조건에서 1회 워밍업 후 5회 측정하며, 표본이 작으므로 중앙값과 범위로만 해석한다.

적용 전 2026-09-27 15:25 UTC: 전체 목록 2페이지 10행(metadata=false)의 중앙값 131.947 ms, 범위 131.000–135.648 ms. 전체 통계가 있는 1페이지 중앙값 130.849 ms, 범위 129.601–133.024 ms. 두 조건은 같은 수강 필터를 사용한다.

PR 검증 후 별도 DB 배포를 진행하고 같은 SQL을 재측정한다. 최종 함수/ACL 확인, 운영 원본 쿼리와 결과 비교, 실제 페이지 이동을 검증한 뒤 배포 결과를 기록한다. 관측된 전체 사용자의 장기 p95나 과거의 간헐적 지연 원인 전체가 해결됐다고 해석하지 않는다.
