# 성능 개선 결과와 적용 계획

2026-09-27 · 기준 `origin/main 062c8601f2b502f123661d8f13130cf51a012ec3` · 독립 작업 브랜치 `codex/performance-remediation-20260927`

기존 전체 성능 리뷰의 R1–R9를 최신 소스에 다시 대조하고 반복 조회·취소 누락·서버 미디어 직렬 처리·교재 파생 계산을 수정했다. 이 문서는 로컬 구현과 검증 결과다. 운영 앱 배포 및 운영 DB migration은 수행하지 않았다. 기존 작업 디렉터리의 미완료 변경도 보존했다.

숫자는 합성 테스트 또는 로컬 production 산출물의 비교다. 운영 p95, 첫 화면 완성 시간, 실제 사용자 네트워크 개선율로 해석하지 않는다. DB 수치는 단일 비교 실행이며 반복 표본 기반 SLA가 아니다. 초기 JS는 정적 HTML script 파일의 개별 gzip 합이며 실제 전송량이나 경로 이동 증분이 아니다.

## 의도적으로 유지한 계약과 남은 범위

- 인증·RLS·기존 데이터 조회 권한·최종 DB 충돌 guard·잠금·idempotency·SQLSTATE를 유지했다. 생성 열의 기존 서버 저장 호환성을 위해 데이터 조회가 없는 분류 함수 6개의 실행 권한만 `service_role`에 추가했다. 로컬 pgTAP가 최종 migration 체인에서 정확한 휴보강 domain 오류와 충돌 경계를 검사했다. 실제 메시지 발송 및 운영 데이터 쓰기는 하지 않았다.
- 교재 page/summary는 독립 RPC를 유지한다. 재고 집계는 여전히 각 RPC에서 계산한다. 분류 규칙 함수가 추후 바뀌면 생성 열을 다시 계산하는 migration이 필요하다. 생성 열 추가 시 기존 행 재작성과 인덱스 생성은 잠금을 수반하므로 운영 적용 시간을 별도로 잡는다.
- 보강 충돌의 날짜/강의실 완전 범위 제한은 보류했다. 기존 수업 시간표 문자열과 이벤트 note에 포함된 일시를 잘못 좁히면 충돌을 놓칠 수 있다. 현재는 투영 열·활성 상태·태그로 줄이며, 정확한 구조화 데이터로 대체할 때 최종 DB guard와 함께 추가 개선한다.
- 학사 번호 목록의 scope metadata 중복, 기타 legacy 상세/전환 읽기까지 모두 캐시화한 것은 아니다. 조회 취소는 이번에 수정한 범위 hook 경로에 적용했다.
- R1의 과거 운영 간헐 지연 원인은 미확정이다. 과목 설정 무제한 대기는 수정했지만 네트워크·pooler·DB 자원·배포 버전의 상관관계는 운영 관측이 더 필요하다.

## 검증 근거

- 실제 React hook/서비스/API를 실행하고 외부 transport만 합성 처리했다. 관리 메타데이터·검색·취소·미디어·휴보강·과목 설정에 실패 재현 후 회귀 테스트를 추가했다.
- 네트워크가 차단된 새 Docker Postgres에 baseline과 최종 121개 migration을 순서대로 재생했다. 생성 열/역할별 저장 12, 교재 읽기 198, 업무 현황 22, 휴보강 SQLSTATE 25, 운영 충돌 127 assertions를 검증했다.

- 관련 회귀 **839/839**, CI 공유 디자인 계약 **63/63**, DB **384/384** 통과. Next production build(타입 검사 포함) 성공, 변경 파일 lint 오류 0(기존 테스트 미사용 변수 경고 1), 모든 surface의 free-tier 쿼리 제한 검사 통과. 새 회귀 테스트와 생성 열 pgTAP를 CI에 연결했다. 독립 전체 변경 리뷰 1회에서 서버 역할 생성 열 권한 회귀 1건을 발견했고, SQLSTATE `42501` 재현 후 최소 권한 연결과 INSERT/UPDATE 회귀로 수정했다. ## 운영 적용 순서와 중단 기준

1. 브랜치 PR에서 최종 변경과 테스트를 검토한다. 운영 배포 SHA를 확인하여 비교 기준을 고정한다.
2. DB migration을 먼저 적용한다. lock timeout 5초/statement timeout 120초를 유지하며 잠금 획득 실패 시 트랜잭션을 중단하고 사용량 낮은 시간에 다시 계획한다. 긴 잠금을 자동 재시도하지 않는다.
3. 교재 읽기·업무 현황·휴보강 guard와 권한 smoke test 후 앱을 배포한다. 앱 변경은 기존 RPC 응답 계약을 유지하여 점진 배포가 가능하다.
4. 학생 5페이지, 수업계획 검색, 날짜 범위 전환, 교사 미디어 관리, 교재 목록/요약, 등록 진입을 같은 사용자·데이터·네트워크로 재측정한다. 요청 수·응답 시간·실패율과 DB 자원 지표를 분리한다.
5. 기존 행/권한 노출, 충돌 누락, 저장 실패, p95/오류율 악화 시 앱을 이전 버전으로 되돌리고 증거를 보존한다. 추가된 열/인덱스는 구버전 앱과 호환되므로 사고 중 즉시 제거하지 않는다.
