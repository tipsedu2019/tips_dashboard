# 성능 후속 개선 — 2026-09-27

기준: main `4757c00c` / PR #71 이후 남은 반복 계산·승인 조회·운영 지연 조사.

## 재현과 변경

1. **학생 목록·통계·필터 N+1**: 최종 `20260921144020_student_enrollment_status.sql`은 학생별로 등록 정보, 학생 배열, 반 배열의 다섯 관계를 다시 계산했다. 운영의 실제 admin RLS 아래 read-only EXPLAIN에서 통계 1회 **767.709ms, shared hit 49,842, disk read 0**. 네트워크만의 문제라는 가정은 배제한다. 새 invoker 집계는 보이는 학생·반을 한 번 구체화하고 같은 우선순위(재원 > 대기), 중복 제거, 활성 등록 조건을 유지한다. numbered·통계·필터와 기존 cursor 목록을 연결하고 단건 상세 계약은 유지한다.
2. **수업계획 페이지 메타데이터**: 같은 actor/role·필터에서 통계·옵션을 30초 재사용한다. 페이지 행은 항상 조회한다. 새로고침/저장 후, actor 변경, 만료는 재계산하며, 응답의 전체 건수/해석된 기간이 달라지면 완전한 페이지를 다시 받아 오래된 통계와 합치지 않는다. 취소된 응답은 캐시를 채우지 않는다.
3. **보강 승인 충돌 후보**: 세 컬렉션을 1천 행씩 끝까지 읽던 서버 루프를 service-role 전용 읽기 RPC 한 번으로 바꾼다. 정규 수업은 보강 요일, 신청/학사일정은 겹치는 날짜 구간으로 줄인다. 방 별칭, 시간 및 충돌 판단은 기존 JS 모델에 맡기며 애매한 legacy 날짜는 보수적으로 남긴다. 휴강 전용·환불·멱등 replay는 후보 조회를 건너뛴다. 최종 잠금·동시 충돌 판정·알림 발송 경로를 바꾸지 않는다. RPC 실패/잘못된 응답은 승인 실패로 처리하고 8초 deadline/자동 재시도 금지를 적용한다.

## 검증

- `benchmark.json`: 같은 격리 DB, 학생 1,000명/반 535개, warm-up 뒤 각 25회 교차 측정. 학생 통계 p50 **330.549→42.516ms**, p95 **334.825→43.362ms**, 최대 버퍼 접근 **81,028→81**. 실제 운영 p95가 아닌 합성 DB 측정이다.
- 관리자·직원·교사·조교·조회자 모두 이전 단건 집계와 결과 일치. 추가 restrictive RLS에서 숨긴 학생/반이 새 집계로 유출되지 않는 pgTAP 포함.
- 관련 SQL **716 assertions / 8 suites** 통과. 권한 오류 SQLSTATE `42501`, 입력 오류 `22023`, 기존 동시성/도메인 충돌 테스트 유지. 최종 마이그레이션 순서에서 검사했다.
- 충돌 SQL 생산자 → 실제 JS 소비자: 충돌 **7건 동일**, 기존 route와 같은 선택 필드의 fixture wire **2,712→1,809 UTF-8 bytes**. 과거 보강 신청 1천→1만 건 및 관련 없는 수업/일정 2천 건을 추가해도 후보 payload 동일. NBSP/BOM을 포함한 기존 메모 파싱도 유지한다. 애매한 legacy 항목과 같은 요일 수업은 의도적으로 남으므로 모든 데이터 분포에서 상수 비용을 주장하지 않는다.
- 브라우저 코드 관련 **285 tests** 통과, production build 통과, lint 오류 0(기존 경고 7). 기존 sidebar 테스트의 render 중 외부 변수 대입은 effect로 옮겨 lint 오류를 해소했다.
- 새 SQL 두 파일 Squawk 오류 0, migration manifest/CI 무결성 검사 통과. CI에 충돌 pgTAP 및 실제 DTO probe를 추가했다.

## 운영 측정 해석

Supabase 로그의 `response.origin_time`을 요청 경로별로 집계하며 본문·JWT·연락처·사용자 ID는 저장하지 않는다. 이전 배포 후 10:50 UTC부터의 조회 표본에서 학생 stats p95 1,537ms(N=4), filter options 1,478ms(N=4), numbered page 1,495ms(N=16)였다. 이 구간에는 수동 검증도 포함된다. 표본이 작으므로 장기 사용자의 체감 p95나 전체 메뉴 성능으로 일반화하지 않는다.

`pg_stat_statements`는 2026-08-13 이후 누적값이므로 과거 최대 7초대 호출을 현재 배포의 p95로 사용하지 않는다. 점검 시 차단 잠금 0, 해당 구간 REST 관측 오류 0이었으며, 과거의 모든 간헐적 지연 원인을 하나로 확정하지 않는다. 이번 변경은 실제 재현된 학생별 관계 재계산을 제거한다.
