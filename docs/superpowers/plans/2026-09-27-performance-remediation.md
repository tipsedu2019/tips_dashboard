# 성능 개선 실행 계획

기준: origin/main `062c8601`. 근거: `docs/reviews/2026-09-22-performance-review.md`.
요청 범위: 발견된 성능 문제 수정 및 검증. 운영 배포, 실데이터 변경, 메시지 발송은 포함하지 않는다.

### Task 1: 관리 목록 메타데이터 재사용
동일 사용자·권한·필터의 페이지/정렬/크기 변경은 목록만 조회한다. 메타데이터 요청은 페이지 취소와 분리하고 필터 변경·새로고침·수정·삭제·인증 변경 시 폐기한다. 30초 TTL, 실패 후 재시도, 이전 권한 결과 차단. 파일: use-management-records.ts 및 관련 행동 테스트. 다섯 페이지의 RPC 15→7과 취소/무효화 검증.

### Task 2: 날짜 범위 취소와 검색 확정
학사·운영 read service에 AbortSignal을 전달하고 hook의 교체/해제/권한 변경 시 이전 범위를 취소한다. 기존 데이터 유지와 refreshVerified 의미 보존. 수업계획/진도 검색은 조합 중 조회를 보류하고 확정된 검색에 250ms 지연, Enter/지우기 즉시 적용. 구식 테스트 fixture를 현재 계약에 맞춘다. 실제 hook과 소비자 테스트로 검증.

### Task 3: 홈페이지 미디어 조회
교사 미디어 URL을 중복 제거하여 storage batch API로 발급하고 파일별 실패 처리·600초 TTL·권한을 유지한다. 공개 파일은 전체 교사 목록 대신 정확한 게시 참조를 조회한다. 실제 handler/store와 외부 저장소 경계 테스트.

### Task 4: 휴보강 승인 조회 범위
단일 요청을 처리하는 클라이언트 전체 workspace 조회를 제거한다. 서버는 보강이 있는 경우에만 날짜/강의실 충돌 범위를 읽고 취소·환불은 불필요한 전체 조회를 생략한다. DB 최종 guard와 기존 P-code 오류/락/권한을 보존한다. 성공·충돌·취소·권한 테스트는 합성 데이터만 사용한다.

### Task 5: 교재·업무 SQL 비용
교재 page/summary의 최종 SQL을 확인하고 결과 동등성을 유지하며 불필요한 집계 중복을 제거한다. 업무 status 이벤트 조회에 필요한 최소 인덱스를 EXPLAIN과 로컬 DB로 검증한다. 신규 migration 및 pgTAP, 실데이터 적용 없음. 환경상 증명하지 못한 최적화는 근거와 제한을 기록한다.

### Task 6: 초기 코드와 등록 조회
실제 production build에서 조건부 calendar/create/retest UI를 분리하여 최초 JS를 재측정한다. 등록 runtime/capability 요청의 캐시·취소·시간 제한을 점검하고 재현되는 중복/진단 공백을 고친다. 원인 미확인 운영 지연을 해결했다고 단정하지 않는다.

### Task 7: 통합 검증과 최종 검토
관련 React/service/API/SQL 테스트, 타입·lint·production build, UI loading/focus/scope 유지 확인. 실행 계획 스킬이 요구하는 독립 전체 변경 리뷰 1회와 필요한 수정 1회 수행. 결과 문서에 관측값, 해결 범위, 미검증 운영 사항 및 적용 순서를 남긴다.
