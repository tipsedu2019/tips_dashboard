# 등록 예약 확인·알림톡 미리보기 복구 설계

## 목표

- 예약 저장 전 확인 화면은 `예약을 저장할까요?`와 `저장`·`돌아가기`만 보여준다.
- 실제 저장 RPC가 시작될 때만 저장 상태를 표시한다.
- 등록 상세 모달 안에서 여는 알림톡 미리보기가 항상 상세 모달 위에 보이고 조작 가능해야 한다.

## 확인된 원인

예약 입력값은 한국 시각에서 UTC ISO로 정상 변환됐지만 확인 요약이 ISO 원문을 그대로 출력해 다른 시각처럼 보였다. 확인 화면을 만들기 위해 저장 전에 리마인드 미리보기 RPC도 호출했고, 그 대기 시간부터 `saving` 상태를 켜 실제 저장 중인 것처럼 표시했다.

알림톡 미리보기는 등록 상세 모달(`z-[80]`) 안에서 다시 여는 Dialog인데 공통 기본 레이어(`z-50`)를 사용했다. 미리보기는 DOM과 포커스 상태상 열렸지만 상세 모달 뒤에 가려져 화면이 멈춘 것처럼 보였다.

## 설계

1. 예약 저장 버튼은 유효성 확인 후 네트워크 요청 없이 즉시 인라인 확인 화면만 연다.
2. 확인 화면에서는 요약·설명·리마인드 사전 조회를 제거한다.
3. 확인 화면의 `저장`을 누른 뒤 실제 저장 작업이 시작될 때만 `saving=true`로 둔다. 성공·실패와 관계없이 `finally`에서 반드시 해제한다.
4. 공통 Dialog가 선택적으로 overlay 레이어를 받을 수 있게 하고, 알림톡 미리보기의 overlay와 content를 모두 `z-[90]`으로 올린다.
5. 미리보기·명시적 발송·중복 방지·서버 claim/finalize 계약은 변경하지 않는다. 브라우저 QA에서는 실제 고객 발송을 누르지 않는다.

## 검증

- 저장 버튼을 누르면 즉시 질문과 두 버튼만 보이고 저장 중 표시나 ISO 요약이 없어야 한다.
- `돌아가기`는 저장하지 않고 입력 화면으로 복귀해야 한다.
- 알림톡 버튼을 누르면 모바일 화면에서도 미리보기 제목·내용·닫기 버튼이 상세 모달 위에서 보여야 한다.
- 집중 테스트, ESLint, TypeScript, Production build와 배포 후 운영 브라우저 검증을 통과해야 한다.
