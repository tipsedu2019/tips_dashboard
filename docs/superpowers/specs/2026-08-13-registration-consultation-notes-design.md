# 등록 상담 내용 기록 설계

**작성일:** 2026-08-13

**상태:** 승인

## 1. 변경 목적

상담 책임자가 상담 결과만 선택할 수 있어, 상담 중 확인한 학습 목표·반 배정 판단·보호자 요청 같은 맥락을 등록 업무 안에 남길 수 없다.

이번 변경은 상담 결과 아래에 여러 줄의 `상담 내용` 입력란을 제공하고, 해당 내용을 결과와 함께 안전하게 저장·재표시한다.

## 2. 확정된 결정

- 상담 내용은 과목별 `ops_registration_consultations` 레코드에 텍스트로 저장한다.
- 기존 상담 결과 저장 RPC가 결과·상태·상담 내용을 하나의 원자적 저장으로 처리한다.
- 기존과 같이 해당 상담의 상담 책임자만 상담 결과와 내용을 수정할 수 있다.
- 상담 내용은 결과 선택의 보조 기록이다. 결과를 선택하지 않은 상태에서는 저장할 수 없다.
- 결과·진행 상태·기존 상담 이력·알림·메시지 발송은 변경하지 않는다.

## 3. 검토한 접근

### 접근 A — 상담 레코드의 텍스트 필드와 기존 저장 RPC 확장

`ops_registration_consultations`에 nullable 텍스트 열을 추가하고, 현재 `save_registration_consultation_details_v1` RPC와 화면 저장 요청에 포함한다.

- 장점: 결과와 기록의 원자성이 보장되고 현재 권한·중복 요청 키·새로고침 흐름을 그대로 재사용한다.
- 단점: 작성자별 변경 이력은 별도 제공하지 않는다.
- 결정: **채택**

### 접근 B — 별도 상담 메모 테이블

상담 메모를 상담 레코드와 분리해 여러 건으로 축적한다.

- 장점: 향후 메모 이력과 작성자별 기록을 확장하기 쉽다.
- 단점: 목록·권한·저장 단위를 새로 설계해야 하며 이번 요청 범위를 넘는다.
- 결정: 채택하지 않는다.

### 접근 C — 기존 결과 값에 텍스트를 결합

결과나 이력 메타데이터에 자유 텍스트를 섞어 저장한다.

- 장점: 스키마 변경을 피할 수 있다.
- 단점: 의미가 불명확하고 재표시·검색·유지보수가 취약하다.
- 결정: 채택하지 않는다.

## 4. 화면과 저장 계약

`전화상담 결과` 또는 `방문상담 결과` 카드에서 결과 선택 버튼 아래에 `상담 내용` 다중 행 입력란을 표시한다.

- 기존 결과 버튼과 저장 버튼의 위치·동작을 유지한다.
- 빈 내용도 허용한다. 결과만 기록하는 기존 업무는 계속 가능하다.
- 기존 내용은 상세를 다시 열었을 때 입력란에 표시한다.
- 결과 또는 내용이 저장된 값과 달라지면 저장 버튼을 활성화한다.
- 저장은 결과, 내용, 상태, 요청 키를 동일 RPC에 전달한다. 성공 후 최신 값을 다시 불러와 화면에 반영한다.
- 상담 책임자가 아닌 사용자는 기존 안내문을 계속 보고 결과와 내용을 수정할 수 없다.

## 5. 데이터·권한 계약

새 nullable `text` 열 `note`를 `public.ops_registration_consultations`에 추가한다.

- 신규 및 기존 상담 레코드 모두 기본값은 `NULL`이다.
- 입력 공백만 저장되면 `NULL`로 정규화한다.
- DB RPC는 현재 상담 결과 저장과 같은 상담 책임자 검증 및 요청 키 중복 방지 계약을 사용한다.
- 읽기 모델, 서비스 타입, fixture는 `note`를 함께 전달한다.
- 새 테이블·공개 API·RLS 정책은 추가하지 않는다. 기존 상담 레코드와 RPC 권한 경계를 넓히지 않는다.

## 6. 오류와 접근성

- 입력란은 명시적인 `상담 내용` 레이블과 안내 문구를 제공한다.
- 저장 중에는 결과 선택과 입력을 잠가 중복 제출을 막는다.
- 저장 실패 시 기존 오류 표시·재시도 흐름을 사용하고 작성 중인 값은 유지한다.
- 내용만 바뀌어도 저장 활성 상태와 요청 키가 바뀐다.

## 7. 구현 경계

포함:

- 상담 레코드 스키마와 기존 상담 결과 저장 RPC의 `note` 지원
- 서비스 타입·응답 매핑·fixture의 상담 내용 전달
- 상담 결과 카드의 다중 행 입력과 dirty/save 상태
- 관련 SQL·서비스·화면 계약 테스트

제외:

- 메모 이력, 댓글, 첨부 파일, 전문 검색
- 상담 책임자 배정·결과·상태 전환 규칙 변경
- 알림 규칙, 공급자 호출, 실제 메시지 발송
- 원격 DB 마이그레이션 적용, 배포, 프로덕션 데이터 변경

## 8. 검증 계약

### 8.1 SQL

- 상담 테이블에 nullable `note text` 열이 존재한다.
- 상담 책임자가 결과와 내용을 함께 저장하면 정규화된 내용이 다시 반환된다.
- 공백 내용은 `NULL`로 저장된다.
- 상담 책임자가 아닌 사용자는 내용만 바꿔도 거부된다.
- 같은 요청 키 재시도는 결과와 내용을 중복 변경하지 않는다.

### 8.2 서비스와 화면

- 상담 읽기 모델이 저장된 내용을 노출한다.
- 결과와 내용이 모두 저장된 값과 같으면 저장 버튼은 비활성이다.
- 내용만 수정해도 저장 버튼이 활성화되고 저장 요청에 포함된다.
- 결과 없이 내용만 작성하면 저장할 수 없다.
- 권한 없는 사용자는 내용 입력과 저장을 할 수 없다.

### 8.3 브라우저

- 전화·방문 상담 결과에서 장문 입력, 저장, 새로 열기 후 유지 여부를 확인한다.
- 상담 책임자가 아닌 사용자에게 수정 제어가 열리지 않는지 확인한다.
- 이 검증은 메시지 발송이나 운영 데이터 변경을 유발하지 않는다.

## 9. 완료 조건

- 상담 책임자가 상담 결과와 장문의 상담 내용을 한 번에 저장할 수 있다.
- 저장한 내용이 다시 열 때 정확히 표시된다.
- 기존 상담 결과·상태·권한·요청 키 중복 방지 계약이 유지된다.
- 관련 SQL·단위·화면 테스트가 통과한다.
