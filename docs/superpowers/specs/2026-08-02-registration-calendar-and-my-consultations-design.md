# 등록 예약 달력 및 내 담당 상담 보기 설계

**작성일:** 2026-08-02

**상태:** 사용자 문서 검토 대기

**관련 설계:** `2026-07-15-registration-appointments-reminders-design.md`

## 1. 변경 목적

등록 화면은 `목록 / 달력`을 별도 보기로 제공하지만, 달력에서도 목록용 전체 프로세스 탭을 그대로 노출한다. 이 탭을 누르면 `view=calendar`가 삭제되어 사용자가 의도하지 않았는데도 목록으로 이동한다. 또한 상담책임자는 `상담 신청`과 `상담 완료`에서 본인에게 배정된 과목을 처리하지만 현재 목록은 전체 상담을 먼저 보여 준다.

이번 변경은 다음 두 가지를 해결한다.

1. 달력을 레벨테스트와 방문상담 예약을 한눈에 관리하는 전용 보기로 만든다.
2. `상담 신청`과 `상담 완료`에서 로그인 사용자의 담당 과목을 기본 업무 목록으로 제공한다.

등록 프로세스 상태, 예약 저장 구조, 상담책임자 배정, 알림 및 권한 계약은 변경하지 않는다.

## 2. 확정된 사용자 결정

- 달력에서 일정 유형을 바꿔도 목록으로 자동 전환하지 않는다.
- 달력은 레벨테스트와 방문상담 예약에 특화한다.
- `상담 신청`과 `상담 완료`에는 `내 담당 / 전체` 전환을 제공한다.
- 상담 목록의 기본 범위는 `내 담당`이다.
- 다과목 신청에서는 로그인 사용자가 상담책임자인 과목만 `내 담당` 결과에 포함한다.

## 3. 검토한 접근

### 접근 A — 목록과 달력의 보조 탐색을 분리

`목록 / 달력`을 최상위 보기 전환으로 유지하고, 그 아래 탐색은 현재 보기에 맞게 바꾼다.

- 목록: 기존 등록 프로세스 8개 탭
- 달력: `전체 일정 / 레벨테스트 / 방문상담`
- 장점: 프로세스 상태와 예약 종류를 섞지 않으며 달력에서 목록으로 튀는 경로 자체를 제거한다.
- 단점: 모드가 바뀔 때 두 번째 탭 행의 의미가 달라진다.
- 결정: **채택**

### 접근 B — 달력에서도 전체 프로세스 탭 유지

프로세스 탭 클릭 시 달력 모드만 유지하고 관련 예약을 필터한다.

- 장점: 현재 화면 모양의 변경이 작다.
- 단점: 예약이 없는 `대기 신청`, `수납 진행 중` 등의 탭과 달력의 관계가 불명확하고 프로세스 상태와 예약 종류가 계속 섞인다.
- 결정: 채택하지 않는다.

### 접근 C — 등록 예약을 별도 페이지로 분리

등록 목록과 예약 달력을 서로 다른 경로로 이동시킨다.

- 장점: 정보 구조가 완전히 분리된다.
- 단점: 공용 상세 진입과 목록 복귀 흐름을 다시 설계해야 하며 현재 요청보다 변경 범위가 크다.
- 결정: 채택하지 않는다.

## 4. 화면 구조

### 4.1 최상위 보기

등록 화면 상단의 `목록 / 달력` 전환은 그대로 유지한다.

- `목록`은 학생·과목별 프로세스를 처리하는 보기다.
- `달력`은 정규 예약을 날짜와 시각 기준으로 확인하는 보기다.
- 보기 전환은 열린 등록 상세와 선택된 예약을 기존 방식대로 안전하게 닫고, 저장이나 업무 상태 변경을 일으키지 않는다.

### 4.2 목록 모드

목록에서는 기존 8개 프로세스 탭을 유지한다.

1. 등록 문의
2. 레벨테스트 신청
3. 상담 신청
4. 상담 완료
5. 대기 신청
6. 등록 신청
7. 수납 진행 중
8. 완료

`상담 신청` 또는 `상담 완료`를 선택하면 프로세스 탭 아래에 작은 범위 전환을 표시한다.

- `내 담당 {건수}`
- `전체 {건수}`

기본 선택은 `내 담당`이다. 다른 프로세스 탭에서는 범위 전환을 표시하지 않는다. 기존 프로세스 탭의 건수는 전체 업무량을 계속 나타내고, 범위 전환의 건수는 현재 상담 단계에서 본인 담당과 전체를 각각 나타낸다.

### 4.3 달력 모드

달력에서는 목록용 8개 프로세스 탭을 표시하지 않는다. 같은 위치에 다음 일정 유형 탭을 표시한다.

- `전체 일정 {건수}`
- `레벨테스트 {건수}`
- `방문상담 {건수}`

건수는 현재 월·주 범위와 선택된 예약 상태에 해당하는 불러온 일정 기준이다. 일정 유형을 바꾸는 동작은 화면을 달력에 그대로 두며 업무 프로세스 상태를 변경하지 않는다.

기존의 다음 기능은 유지한다.

- 월·주 보기
- 이전 기간, 오늘, 다음 기간 이동
- 예약·완료·취소 상태 필터
- 데스크톱 달력과 모바일 날짜별 agenda
- 예약 카드에서 정규 등록 상세 열기

달력의 기본 일정 유형은 `전체 일정`, 기본 예약 상태는 기존과 같이 `예약`이다.

## 5. 상담 범위 계약

### 5.1 본인 판정

`내 담당`은 이름 문자열이 아니라 ID로 판정한다.

```text
과목 트랙의 directorProfileId === 현재 등록 viewer ID
```

실제 환경에서는 로그인 사용자 ID를 사용하고, 등록 브라우저 fixture에서는 fixture viewer ID를 사용한다. 표시 이름이 같거나 변경되더라도 다른 사용자의 상담이 섞이면 안 된다.

### 5.2 다과목 신청

한 학생의 신청 건에 같은 상담 단계의 과목이 여러 개 있어도 `내 담당`에서는 본인에게 배정된 과목만 `matchingTracks`에 남긴다.

예:

- 영어 상담책임자: 로그인 사용자
- 수학 상담책임자: 다른 사용자

`내 담당` 결과에는 학생 신청 건이 한 행으로 한 번 나타나며 영어만 표시·처리 대상이 된다. 수학은 같은 행에 행동 가능한 과목으로 노출하지 않는다. `전체`로 전환하면 영어와 수학을 모두 확인할 수 있다.

대표 과목, 상담 유형, 정렬 시각, 검색 대상도 범위 적용 후 남은 과목을 기준으로 다시 계산한다. 따라서 다른 상담책임자의 과목이 대표 과목이나 다음 행동으로 선택되지 않는다.

### 5.3 건수와 빈 상태

- `내 담당`과 `전체` 건수는 학생 신청 건 단위로 세며, 같은 신청 건을 과목 수만큼 중복 계산하지 않는다.
- 본인에게 배정된 과목이 없으면 오류가 아니라 `내 담당 상담 신청이 없습니다.` 또는 `내 담당 상담 완료가 없습니다.`를 표시한다.
- 현재 viewer ID를 확인할 수 없는 경우 `내 담당` 결과는 비어 있으며 `전체` 전환은 계속 제공한다.
- 검색은 먼저 상담 범위를 적용한 뒤 실행한다. `내 담당` 검색 결과가 다른 상담책임자의 과목 정보 때문에 일치하면 안 된다.

## 6. 달력 일정 유형 계약

달력의 권위 데이터는 기존 `ops_registration_appointment_calendar` 조회 결과다. 이 결과는 이미 다음 두 종류만 허용한다.

- `level_test`
- `visit_consultation`

전화상담, 레거시 부모 행의 시각, 일반 프로세스 단계는 달력에 추가하지 않는다. 일정 유형 전환은 불러온 정규 예약을 클라이언트에서 `kind`로 필터하며, 예약 상태·기간 변경에 따른 기존 조회 계약은 그대로 사용한다.

공유 예약은 참여 과목 수와 관계없이 기존처럼 예약 한 건으로 표시한다. 일정 유형 필터는 예약을 복제하거나 과목별 일정으로 나누지 않는다.

## 7. URL 및 탐색 계약

### 7.1 목록 URL

목록 모드는 기존 `flow`를 사용한다.

```text
/admin/registration?flow=consultation_requested
```

- 상담 URL에 유효한 범위 값이 없으면 `내 담당`으로 해석한다.
- `전체`를 선택하면 `owner=all`을 사용한다.
- `내 담당`은 기본값이므로 `owner`를 생략한다.
- `상담 신청`과 `상담 완료` 사이를 이동할 때 명시적으로 선택한 `owner=all`은 유지한다.
- 다른 프로세스 단계로 이동하면 `owner`를 삭제한다. 이후 상담 단계에 새로 들어오면 다시 `내 담당`이 기본이다.

### 7.2 달력 URL

달력 모드는 `view=calendar`를 권위 값으로 사용한다.

```text
/admin/registration?view=calendar
/admin/registration?view=calendar&kind=level_test
/admin/registration?view=calendar&kind=visit_consultation
```

- `전체 일정`은 기본값이므로 `kind`를 생략한다.
- 달력에 진입할 때 목록 전용 `flow`와 `owner`를 URL에서 제거한다.
- 일정 유형 탭은 `view=calendar`를 삭제하지 않는다.
- 목록으로 돌아갈 때 `view`와 `kind`를 제거하고 현재 세션의 목록 프로세스를 `flow`로 복원한다.
- 달력 URL을 직접 새로 연 뒤 목록으로 돌아가면 기본 프로세스인 `등록 문의`로 진입한다.
- 기존 예약 상세 딥 링크의 `taskId`, `trackId`, `appointmentId`, `view=calendar` 계약은 유지한다.
- 예약 상세를 닫으면 상세를 열기 전의 달력 월·주, 일정 유형, 상태 필터를 같은 세션에서 유지한다.

알 수 없는 `owner` 또는 `kind` 값은 오류 화면을 만들지 않고 각각 `내 담당`, `전체 일정`으로 정규화한다.

## 8. 오류 및 접근성

- 목록과 달력의 탭은 각각 독립된 `tablist` 이름을 사용한다.
- 선택 상태는 색상뿐 아니라 `aria-selected` 또는 `aria-pressed`로 전달한다.
- 키보드 화살표, Home, End 이동은 현재 보기에 실제로 표시된 탭 집합 안에서만 순환한다.
- 일정 유형을 바꾸는 중에는 기존 예약 조회 오류를 새 오류로 만들지 않는다.
- 선택한 기간·상태·일정 유형에 예약이 없으면 조건을 설명하는 단일 빈 상태를 표시한다.
- 상담 범위를 바꿀 때 등록 상세를 자동으로 열거나 저장하지 않는다.

## 9. 구현 경계

이번 변경에 포함한다.

- 등록 작업 공간의 모드별 보조 탭 렌더링과 URL 동기화
- 상담 단계의 `내 담당 / 전체` 범위 상태와 건수
- 상담 목록 모델의 ID 기반 과목 필터와 대표 과목 재계산
- 등록 달력의 일정 유형 필터와 건수
- 관련 단위·계약·브라우저 회귀 검증

이번 변경에 포함하지 않는다.

- 데이터베이스 스키마, 뷰, RPC 또는 마이그레이션 변경
- 상담책임자 자동 배정 규칙 변경
- 등록 프로세스 탭·상태 분류 변경
- 달력 드래그, 크기 조정, 달력 안의 직접 예약 수정
- 학사일정으로 등록 예약 복사
- 알림 규칙, 수신자, 공급자 활성화 또는 실제 메시지 발송
- 운영 배포, 원격 push 또는 프로덕션 데이터 변경

## 10. 검증 계약

### 10.1 모델 테스트

- `내 담당`이 `directorProfileId`와 viewer ID가 같은 과목만 남긴다.
- 다과목 신청에서 본인 과목만 남기고 대표 과목과 정렬값을 다시 계산한다.
- `전체`는 기존 상담 목록 결과를 보존한다.
- `상담 신청`과 `상담 완료` 모두 같은 범위 계약을 사용한다.
- 검색은 범위 밖 과목의 책임자·장소로 일치하지 않는다.
- 건수는 학생 신청 건 단위로 중복 없이 계산한다.
- 일정 유형 필터가 공유 예약을 복제하지 않고 정확한 `kind`만 남긴다.

### 10.2 작업 공간 계약 테스트

- 달력 모드에서 8개 프로세스 탭 대신 3개 일정 유형 탭을 표시한다.
- 일정 유형을 바꿔도 `view=calendar`가 유지된다.
- 목록과 달력 전환이 `flow`, `owner`, `view`, `kind`를 정의된 계약대로 정리한다.
- 상담 단계의 기본 범위가 `내 담당`이고 `owner=all`만 명시적으로 전체를 연다.
- 일정 유형 및 상담 범위 탭이 접근 가능한 이름과 선택 상태를 제공한다.

### 10.3 실제 브라우저 검증

- 데스크톱에서 달력의 `전체 일정`, `레벨테스트`, `방문상담`을 전환해도 목록으로 이동하지 않는지 확인한다.
- 월·주 보기, 예약 상태 필터, 기간 이동과 일정 유형 필터가 함께 동작하는지 확인한다.
- 예약 카드를 열고 닫은 뒤 달력 문맥이 유지되는지 확인한다.
- 상담책임자 fixture에서 `상담 신청`과 `상담 완료`가 본인 담당으로 시작하는지 확인한다.
- `전체` 전환과 다과목 행의 과목 제한을 확인한다.
- 모바일에서 일정 유형 탭, 날짜별 agenda, 상담 범위 전환이 가로 넘침이나 가림 없이 동작하는지 확인한다.
- 테스트 중 저장·상태 변경·알림 발송은 실행하지 않는다.

## 11. 완료 조건

- 달력에서 어떤 일정 유형을 선택해도 목록으로 자동 전환되지 않는다.
- 달력의 보조 탭은 레벨테스트와 방문상담 예약만 명확하게 다룬다.
- `상담 신청`과 `상담 완료`는 `내 담당`으로 시작하며 `전체`로 즉시 전환할 수 있다.
- 다과목 신청에서 다른 상담책임자의 과목이 본인의 행동 대상으로 노출되지 않는다.
- 기존 프로세스 상태, 정규 예약 상세, 공유 예약, 권한 및 무발송 계약이 유지된다.
- 관련 테스트와 데스크톱·모바일 브라우저 검증이 통과한다.
