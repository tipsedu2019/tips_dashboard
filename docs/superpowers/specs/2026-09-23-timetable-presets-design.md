# 여러 학기 시간표 프리셋 설계

작성: 2026-09-23 · 상태: 상세 계획, 구현 전

## 1. 목표와 핵심 결정

`시간표` 안에서 여러 학기와 여러 대안을 함께 편성하고 저장한다. 선생님 주간·강의실 주간·일별 선생님·일별 강의실은 **하나의 시간표 배치를 다르게 보여주는 네 화면**이다. 어느 화면에서 입력·배치·이동해도 같은 데이터가 갱신된다.

확정 방향은 **운영 시간표 + 이름을 붙인 독립 프리셋 + 운영 수업의 그림자**다.

- 운영 시간표: 기존 `수강 / 개강 준비 / 종강` 수업의 현재 기본 시간표.
- 프리셋: `2027 1학기`, `2027 여름`, `2027 2학기`, `2027 1학기 B안`처럼 원하는 만큼 생성하는 계획 공간.
- `개강 준비`는 수업 상태로 유지한다. 여러 계획을 담는 식별자나 학기 이름으로 재사용하지 않는다.
- 프리셋은 수업그룹·옛 기간 필터의 복원이 아니다. 계획을 골라도 운영 수업의 학기·기간·수강생을 자동 변경하지 않는다.
- 각 프리셋은 전체 과목을 함께 담는다. 과목은 보기 조건이며 저장 공간을 나누는 기준이 아니다.
- 수강 중인 수업은 계속 운영한다. 프리셋에는 그 수업을 읽기 전용 그림자로 겹쳐 표시해 같은 선생님·강의실의 자리를 비워 둔다. 실제 수업의 상태·시간·명단을 바꾸지 않는다.
- 프리셋 저장은 운영 반영과 별개다. 세 학기 뒤의 프리셋도 현재 수업을 바꾸지 않고 계속 편집할 수 있다.

사용자가 확인한 방향과 이를 구체화한 설계는 다음과 같다.

1. 자동 배치: **요일·시간 입력 시 즉시 배치 + 빈 시간 추천**. 사용자 선택을 반영한다. 전체 학원 자동 편성 최적화는 별도 확장이다.
2. 운영 → 프리셋: **실제 이동/상태 전환 없이 그림자로 참조**. 최초 요청의 ‘내리기’는 사용자의 후속 설명에 따라 이 방식으로 대체한다. 기존 수업이 계속 차지하는 자리를 신규 수업이 침범하지 않게 하는 것이 목적이다.
3. 관리자·직원은 공동 편집한다. 선생님은 기존 운영 시간표 열람을 유지하며 프리셋은 공유 대상으로 지정되었을 때 열람/편집한다. 운영 반영 권한은 관리자·직원에 둔다. 이는 ‘같이 편성’을 구체화한 제안이다.

## 3. 화면 구성

기존 `/admin/timetable`을 유지한다. 별도 시간표 메뉴를 만들지 않는다.

```text
시간표   [운영 시간표 ▾]                     [프리셋 만들기] [더보기]
         ├ 운영 시간표
         ├ 2027 1학기
         ├ 2027 1학기 B안
         └ 2027 여름

[선생님 주간] [강의실 주간] [일별 선생님] [일별 강의실]
[과목] [선생님/강의실/요일]           [수업 추가] [수업 목록]

┌ 수업 목록 ───────┬──────────────── 시간표 ───────────────┐
│ 검색            │ 동일한 배치 데이터를 네 가지 보기로 표시 │
│ 전체 / 미배치    │ 옅은 기존 수업 그림자 + 편집 가능한 새 수업 │
│ □ 중2 영어 A    │                                        │
│ □ 중3 수학 B    │                                        │
└─────────────────┴────────────────────────────────────────┘
                                          저장 중 / 저장됨 / 재시도
```

- `운영 시간표` 선택 시 기존 수업 상태 필터를 유지한다. 프리셋에는 운영 상태 필터 대신 선택한 프리셋명과 미배치 상태가 보인다.
- 보기/필터를 바꿔도 프리셋, 선택한 수업, 미저장 입력을 잃지 않는다. 선택은 수업 ID 집합이며 현재 화면의 블록 개수와 다르다.
- 전체 선택은 `이 프리셋 전체 N개` 또는 `검색 결과 N개`로 범위를 명시한다. 화면 밖 선택이 있으면 건수를 유지한다. 프리셋 자체를 바꿀 때만 선택을 초기화한다.
- 수업 목록은 드래그 원본·검색·복수 선택·미배치 복구를 담당한다. 기본 폭은 280px, 접을 수 있다. 390px에서는 공용 Sheet에서 항목을 선택한 뒤 Sheet를 닫고 셀 선택/폼으로 배치한다. 열린 modal Sheet 밖으로 드래그를 요구하지 않는다.
- 프리셋의 새 수업은 편집 가능한 상태로 열린다. 운영 시간표와 프리셋의 그림자는 읽기 전용이다. 실제 운영 수업 변경은 기존 수업관리 동선을 유지한다.
- 새 수업을 선택하면 기존 작업 영역에 `선택 N개 · 수강으로 보내기 / 다른 프리셋으로 보내기`가 나타난다. 그림자는 전송 선택·드래그 원본에 섞지 않는다. 새로운 요약 행을 밀어 넣지 않는다.
- 프리셋 이름 변경·복제·보관·공유는 더보기에서 제공한다. 보관된 프리셋은 읽기 전용이며 복원할 수 있다. 영구 삭제는 1차 범위에 넣지 않는다.
- 프리셋에는 선택적인 기준 시작일/종료일을 둘 수 있다. 정렬·이름·검토 범위용 메타데이터이며 날짜가 되어도 자동으로 수강 전환되지 않는다.
- 기존 패널 이미지 저장을 유지하고 프리셋명·보기·출력 시각을 결과에 넣는다. 이미지 저장을 DB 저장과 같은 이름으로 표시하지 않는다.

## 4. 운영 수업 그림자와 직접 배치

### 그림자는 실제로 자리를 비워 두게 하는 기준이다

- 모든 `수강` 수업의 현재 주간 기본 배치를 프리셋에 자동으로 보여 준다. 프리셋별로 복사해 저장하는 수업이 아니라 운영 데이터의 실시간 참조다.
- 예: 김선생님·1강의실·월 18:00–20:00에 기존 수업이 있으면, 그 칸은 옅은 그림자와 `기존 수업` 표식으로 보인다. 같은 선생님 또는 같은 강의실로 겹치는 새 수업은 배치할 수 없다.
- 그림자는 보기마다 동일 운영 slot ID를 사용한다. 드래그/resize/삭제가 불가능하며 클릭·터치·키보드로 수업명·시간·담당·강의실을 확인할 수 있다.
- 운영 수업이 옮겨지거나 담당·방·상태가 바뀌면 최신 그림자를 재조회한다. 그 결과 기존에 저장한 새 배치와 충돌하면 프리셋에 `충돌 해결 필요`를 표시하고 양쪽을 모두 보존한다. 운영 변경을 프리셋 때문에 차단하거나 새 배치를 자동 삭제하지 않는다.
- 숨긴 과목/선생님도 그림자 충돌 검사에 포함한다. 필터는 표시만 바꾼다. 1차 버전에서는 그림자를 임의로 제외해 자리를 해제하는 기능을 두지 않는다.
- 그림자는 운영의 **주간 기본 자리**다. 날짜별 예외 회차는 프리셋 기준 기간이 있으면 해당 구간을 별도로 검사하고 구체 날짜로 알려 준다. 날짜별 skipped/moved 회차가 있어도 프리셋의 주간 기본 자리를 비우지 않는다. 실제 날짜별 운영 쓰기는 effective-session 권위와 dedup 및 skipped 제외를 따른다. 기준 기간이 없으면 기본 자리로 편성하되 운영 반영 직전 미래 실제 회차까지 반드시 검사한다.
- 운영 원본을 복제하여 비슷한 새 수업을 만들고 싶을 때는 `이 수업으로 새 초안 만들기`를 사용한다. 기본정보를 채운 미배치 항목을 만들고, 기존 그림자의 자리는 그대로 막는다.

### 수업과 배치의 구분

`중2 영어 A`라는 수업 하나에 `월 18:00–20:00`, `수 18:00–20:00` 두 배치가 붙을 수 있다. 블록 하나를 옮기면 그 배치 하나만 바뀐다. 수업 전체 요일을 바꾸거나 전체 담당을 바꾸는 작업은 수업 편집 폼에서 명시적으로 실행한다.

| 보기 | 패널 | 열 | 드롭 위치에서 정하는 값 | 보존하는 값 |
| --- | --- | --- | --- | --- |
| 선생님 주간 | 선생님 | 요일 | 선생님, 요일, 시작 시각 | 강의실, 수업 길이 |
| 강의실 주간 | 강의실 | 요일 | 강의실, 요일, 시작 시각 | 선생님, 수업 길이 |
| 일별 선생님 | 요일 | 선생님 | 요일, 선생님, 시작 시각 | 강의실, 수업 길이 |
| 일별 강의실 | 요일 | 강의실 | 요일, 강의실, 시작 시각 | 선생님, 수업 길이 |

1. 수업 목록의 항목을 셀로 드래그하면 해당 셀의 값이 채워진다. 누락된 강의실/선생님/길이가 있으면 같은 편집 창에서 그 값만 추가한다.
2. 빈 셀을 클릭하거나 시간 범위를 드래그하면 해당 값이 채워진 수업 추가 창이 열린다. 새 수업 또는 기존 프리셋 수업의 추가 요일을 고른다.
3. 배치된 새 수업 블록을 이동하면 길이를 보존한다. 끝점을 조절하면 길이를 바꾼다. 둘 다 같은 저장 명령을 사용한다. 그림자에는 이 조작을 제공하지 않는다.
4. 과목명·수업명·선생님·강의실·요일·시작/종료를 입력하고 저장해도 동일한 배치가 만들어진다. 월/수/금처럼 여러 요일 선택은 한 원자적 명령으로 저장한다.
5. 배치 해제는 해당 슬롯만 지우고 수업을 목록에 남긴다. 수업 삭제는 프리셋 항목 전체에 대한 별도 행동이다. 운영 수업 삭제와 연결하지 않는다.

### 시간 정확도

- 저장은 자정 기준 정수 분(`startMinute`, `endMinute`)이며 0 ≤ 시작 < 종료 ≤ 1440이다. 요일은 기존 DB와 같은 일요일 0–토요일 6이다.
- 화면 눈금은 30분, 드래그는 5분 스냅을 기본으로 한다. 폼에서 입력한 17:10 또는 17:13을 17:00으로 내림하지 않는다. 기존 블록은 이동 거리만 5분 단위로 적용하여 원래 분 오프셋과 길이를 보존한다.
- 읽기 모드는 현재처럼 실제 수업 전후 30분을 보여 준다. 편집 모드는 기본 09:00–24:00에 기존 배치를 포함하도록 확장하고, 시간 범위에서 00:00–24:00을 고를 수 있다. 오전 수업이나 늦은 수업을 잘라내지 않는다.
- 드래그 시작 시 시간축을 고정한다. 저장/취소가 끝날 때까지 축 재계산으로 셀이 이동하지 않는다.
- 23:30–24:00 허용. 자정을 넘는 한 슬롯은 거부하고 두 요일로 나누도록 안내한다.
- 새 프리셋에도 사용 가능한 선생님·강의실로 빈 보드를 그린다. 자원 카탈로그가 정말 없으면 설정 화면으로 이동하는 한 가지 행동을 제공한다.

### 자동 배치

- 요일·시간이 주어지면 충돌 확인 후 바로 배치한다.
- 운영 수업은 그림자로 즉시 표시한다. 기존 준비 수업/옛 초안을 가져오면 슬롯을 복사하되 그림자나 다른 새 수업과 충돌하는 슬롯은 미배치 목록에 원래 시간·사유와 함께 보존한다.
- 네 기본정보만 있는 새 수업은 요일·시간을 임의로 만들어 저장하지 않는다. 수업 길이와 가능한 요일/시간을 선택하면 최대 5개의 충돌 없는 후보를 제공한다.
- 후보 정렬은 선택한 요일 순서 → 빠른 시작 시각으로 고정한다. 선생님·강의실은 입력한 값을 유지하며 그림자와 새 수업을 모두 피해 최대 5개 후보를 제시한다. 후보 하나를 누르면 네 보기에 함께 반영된다.
- 후보가 없으면 `조건에 맞는 빈 시간이 없습니다`와 변경할 조건을 보여 준다. 기존 수업을 밀어내거나 자동 덮어쓰지 않는다.
- 프리셋 전체 최적화, 선생님 이동시간·점심시간·강의실 정원 등 추가 제약은 초기 필수 범위에서 제외한다. 추후 넣더라도 같은 배치 명령/검증 경로를 사용한다.

## 5. 충돌 규칙

### 프리셋 안의 충돌

동일 프리셋의 새 수업들 및 운영 그림자 전체를 합친 범위에서, 동일 요일에 아래 중 하나이면 새 배치 저장 불가다.

- 같은 선생님 ID의 시간이 겹침.
- 같은 강의실 ID의 시간이 겹침.
- 같은 수업의 서로 다른 슬롯 시간이 겹침.

시간 구간은 `[시작, 종료)`다. 18:00–19:00과 19:00–20:00은 허용한다. 18:59 시작은 충돌한다. 이동 중인 **슬롯 한 개**만 기존 충돌 검사에서 제외한다. 같은 수업의 다른 슬롯은 제외하지 않는다.

- 화면에 숨긴 과목·요일·선생님도 검사한다. 조회 필터로 충돌 범위를 좁히지 않는다.
- 서로 다른 프리셋의 새 수업은 대안이므로 같은 빈 시간 사용을 허용한다. 각 프리셋은 동일한 운영 그림자 자리는 침범할 수 없다. 운영 반영 직전에 운영 시간표 전체와 다시 검사한다.
- 이름이 같아도 ID가 다르면 다른 자원이다. 실제 한 사람/공간의 카탈로그 중복은 사전 진단으로 정리한다. 문자열 이름으로 자동 합치지 않는다.
- 자원 미정 수업은 저장할 수 있지만 미배치 목록에 남는다. 교사·강의실이 모두 확정된 슬롯만 확정 배치로 저장한다.
- 삭제/숨김 처리된 자원은 기존 배치에서 이름을 보존하고 `사용 불가`로 표시한다. 새 배치/운영 반영에는 유효한 자원 재선택이 필요하다.
- 이미 충돌한 운영/가져온 자료를 숨기거나 한 블록으로 덮지 않는다. 둘 다 확인할 수 있어야 하며, 추가 충돌을 만드는 저장은 거부한다. 운영 자료의 시각/자원 ID가 미해결이면 해당 검증 범위는 `확인 필요`로 막고 빈 시간으로 취급하지 않는다.

### 운영과의 충돌

- 프리셋 편집·반영은 기존 `수강` 전체의 기본 슬롯을 검사한다. 과목별로 분리하지 않는다. `종강`/`개강 준비` 기본 슬롯은 주간 그림자로 예약하지 않는다.
- 이미 생성된 향후 유효 회차(`active`, `exception`, `makeup`)는 수업 상태와 별개로 자원을 점유한다. `tbd`, `skipped`는 점유하지 않는다. 취소/휴강의 실제 최신 상태 매핑은 구현 시 최종 함수 기준으로 고정한다.
- 운영 기본 슬롯과 동일 수업·원본 슬롯·날짜의 회차는 기존 스냅샷이 그날의 확정값이다. 같은 실제 예약을 두 번 세지 않는다. 그림자와 충돌하는 새 수업을 자기 자신이라며 제외하는 예외는 없다.
- 프리셋 편집·반영으로 기존 수업 기본값이나 생성된 회차를 수정하지 않는다. 실제 회차 자체의 변경은 기존 일정 편성 작업을 사용한다.
- 새 프리셋 날짜로 현재 운영에 유효기간 규칙이나 두 번째 운영 시간표를 만들지 않는다. 미래 계획은 저장해 두고 실제 전환할 때 운영 반영한다.

### 검사와 저장

1. 브라우저에서 드래그 유효 위치·충돌 대상·원인을 즉시 표시한다.
2. 서버에서 필터 없는 권위 데이터로 다시 검사한다. 브라우저에서 통과했다는 플래그는 신뢰하지 않는다.
3. 프리셋 쓰기도 운영 자원 잠금→프리셋 행 잠금 순서로 최신 그림자와 검증·저장한다. 운영 기본값/회차/반영은 같은 자원 잠금 규약을 사용한다.
4. 운영 반영과 기존 운영 저장이 같은 자원을 동시에 요청해도 둘 다 성공하지 않아야 한다. 프리셋 저장과 운영 변경이 경쟁하면 서버는 최신 그림자로 검사하며, 먼저 저장된 프리셋이 나중 운영 변경으로 충돌한 경우 초안을 보존하고 다시 해결하게 한다.
5. 충돌은 `23P01` + `timetable_resource_conflict`, 오래된 revision은 `P0001` + `timetable_stale`로 구별한다. 도메인 충돌에 `40001`을 사용하지 않는다. 기존 API 오류 계약은 호환 매핑을 유지한다.

운영 변경으로 이미 충돌한 초안이 있더라도 이름 등 비점유 수정과 다른 안전한 슬롯 편집은 허용한다. 변경 슬롯의 새 점유를 검사하고, 미변경 충돌 슬롯은 보존한다. 일부 수강 반영에서는 선택한 항목만 미배치/충돌 여부를 검사하므로 선택하지 않은 초안의 문제 때문에 안전한 선택까지 막지 않는다.

구간 중첩과 잠금 방식은 PostgreSQL의 [range 문서](https://www.postgresql.org/docs/current/rangetypes.html), [명시적 잠금 문서](https://www.postgresql.org/docs/current/explicit-locking.html)를 참고한다. 구체적인 중첩 정책과 원자적 반영은 이 프로젝트의 설계 결정이다.

## 6. 선택·일괄 이동과 복사

### 작업의 의미

`이동/복사`는 **프리셋에서 새로 편성한 수업**을 수강 또는 다른 프리셋으로 보낼 때 원본을 남기는지 결정한다. 기존 수강 수업은 내려오지 않고 그림자로만 참조한다.

| 방향/방식 | 목적지 | 원본 | 수강생·이력 |
| --- | --- | --- | --- |
| 프리셋 → 수강, 이동 | 신규 수업 생성, 상태 수강 | 성공한 프리셋 항목 제거, 감사 이력 유지 | 신규 수업의 명단/이력은 비어 있음 |
| 프리셋 → 수강, 복사 | 신규 수업 생성, 상태 수강 | 프리셋에 `반영 완료` 구성으로 보존 | 학생·대기·출결·수납·교재사용이력 미복사 |
| 수강 → 프리셋 참조 | 운영 슬롯을 읽기 전용 그림자로 표시 | 운영 수업과 상태 그대로 | 모든 관계/이력 원본 유지 |
| 수강을 참고해 새 초안 생성 | 기본정보만 채운 미배치 새 항목 | 운영 수업과 그림자 유지 | 학생/운영 이력 미복사 |
| 프리셋 A → B, 이동/복사 | 새 항목/슬롯 ID로 배치 저장 | 이동은 A 항목 제거, 복사는 유지 | 운영 기록 없음; 출처만 기록 |

- 출처 ID는 참고용이며 운영 원본을 덮어쓰는 연결이 아니다. `기존 수업 이어가기`, 수강 상태 내리기, 종강/재개를 이 전환창에 넣지 않는다.
- 복사로 올린 항목은 원래 편성 내용을 프리셋 목록의 `반영 완료`에 읽기 전용으로 보존한다. 주 그리드에는 실제 운영 그림자 **한 개만** 표시한다. 반영 완료 snapshot 슬롯은 충돌 검사/빈 시간 추천에도 중복 포함하지 않는다. 저장된 구성은 목록에서 확인할 수 있다. 프리셋 A→B 복사는 양쪽 모두 초안으로 유지한다.
- 이동으로 올린 항목은 프리셋에서 제거되고 운영 그림자가 그 자리에 나타난다. 이동/복사 모두 운영 수업과 프리셋 블록을 이중 표시하지 않는다.
- 반영 완료 항목은 다시 올릴 수 없다. 다른 수업으로 활용하려면 `새 초안으로 복제`하여 미배치 항목을 만들고 새로운 빈자리를 고른다. 원본 수업이 나중에 변경/종강/삭제되어도 자동 재반영하지 않는다.
- 다른 프리셋이 같은 빈자리로 계획 중이었다면 새 운영 수업이 그림자로 나타나 충돌을 알려 준다. 저장된 계획을 자동 수정하지 않는다.
- 과목·명칭·슬롯 외 기본정보(학년, 정원, 수업료 등)는 미리보기에서 유효한 값을 확인한다. 신규 수업 필수값 누락은 해당 행에서 입력한다. 회차 생성은 기존 수업계획에서 별도로 한다.
- 미배치 슬롯(`pending_slots`)이 남거나 확정 슬롯이 0개인 수업은 수업 전체 반영을 차단한다. 월요일만 올리고 미해결 수요일을 버리는 부분 반영은 금지한다.
- 반영 응답은 항목 상태/제거와 새 운영 그림자를 하나의 결과로 반환하고 한 번에 화면에 반영한다. 두 조회를 따로 갱신하다가 잠깐 중복되거나 사라지는 상태를 만들지 않는다.

### 미리보기와 실행

1. 한 개 또는 여러 수업 선택 → 목적지 → 이동/복사 선택.
2. 생성할 수업, 원안 유지 여부, 기존 운영 불변, 미배치/충돌/차단 사유를 수업별로 표시.
3. 오류가 하나라도 있으면 선택 묶음 전체를 적용하지 않는다. 사용자가 문제 행을 선택 해제하면 그 명시적 새 선택으로 다시 검사한다.
4. 실행은 **한 DB 트랜잭션**이다. 프리셋 항목 제거/반영 완료 처리는 신규 수강 수업 저장 성공과 함께 커밋된다. 기존 수강 수업은 변경하지 않는다.
5. 요청 키 재실행은 같은 결과를 반환한다. 통신 실패로 결과를 모르면 같은 키로 확인/재시도하며 새 수업을 중복 생성하지 않는다.
6. 서버 결과와 재조회가 일치한 뒤 완료 표시. 반영한 수업으로 이동하거나 프리셋에서 계속 작업할 수 있다.

## 7. 저장·공동 편집·복구

- 완성된 폼 제출과 드롭/resize 완료 단위로 자동 저장한다. 포인터 이동마다 RPC를 보내지 않는다.
- 네 보기는 같은 canonical state를 구독한다. 보기 변경은 DB 쓰기나 별도 복제를 일으키지 않는다.
- 서버 확인 전 `저장 중`, 성공 후 `저장됨`, 실패 시 `저장 실패 · 재시도`를 표시한다. 실패한 변경을 확정 배치처럼 표시하지 않고 작업 초안을 보존한다.
- 같은 항목의 연속 명령은 직렬화한다. 먼저 저장한 결과가 늦게 와서 사용자의 다음 이동을 되돌리지 않는다. 다른 항목의 저장은 각각의 revision으로 확인한다.
- 타 사용자 변경은 프리셋 또는 운영 그림자 변경 알림을 받아 재조회한다. 보이는 동안 20초 revision/fingerprint 확인 및 창 재활성화 재조회로 누락된 이벤트도 복구한다. 학생 개인정보는 채널 payload에 넣지 않는다. 그림자 조회가 실패하면 이전 그림자를 보존하되 새 저장/반영을 막는다.
- 같은 항목 동시 수정은 한쪽만 성공한다. 실패한 사람에게 서버 값과 본인 초안을 보여 주고 다시 적용/취소를 고르게 한다. 서로 다른 수업 수정은 덮어쓰기 없이 합쳐진다.
- 프리셋명/보관/공유는 metadata revision, 수업 편집은 item revision을 검사한다. 전체 프리셋 JSON을 마지막 저장으로 덮지 않는다.
- 프리셋/메뉴 이동에 미저장 초안이 있으면 기존 이탈 방지 UI를 사용한다. 미저장 항목과 전송 요청은 사용자 ID+역할+프리셋 ID로 분리한 sessionStorage에 보존하며 같은 탭의 새로고침/세션 복구만 지원한다. 탭과 창을 닫으면 세션이 끝나므로 새 브라우저 세션 복구를 보장하지 않는다. 서버에 저장한 프리셋은 브라우저 재시작 뒤에도 유지된다. 로그아웃·actor/역할 변경은 actor 범위 전체 복구 정보를 제거한다. 단일 프리셋 공유 철회는 그 프리셋의 항목·관련 전송·관련 메타데이터 복구와 이름 캐시만 제거하며 다른 허용 프리셋의 미확정 요청을 보존한다. 제출 후 결과가 불명확한 생성/복제/이름/공유/보관/복원/가져오기 요청도 원본 body/key를 같은 actor 세션에 보존하고 다른 입력보다 원래 receipt를 먼저 확인한다. 제출 전 일반 폼 입력은 이탈 방지만 적용한다. 오프라인 작업을 서버 저장 완료로 표시하지 않는다.
- 실행 취소는 1차로 프리셋의 직전 배치 변경에 제공한다. 서버의 새로운 역명령으로 처리하며, 다른 사용자가 그 수업을 변경했으면 덮어쓰지 않는다. 운영 반영/명단/회차 작업은 일반 실행 취소에 묶지 않는다.

## 8. 데이터와 API 설계

### 신규 테이블

| 테이블 | 주요 필드/역할 |
| --- | --- |
| `timetable_plans` | id, name, target_start_date/end_date nullable, state(draft/archived), meta_revision, change_sequence, created_by/updated_by, timestamps |
| `timetable_plan_members` | plan_id, user_id, access(viewer/editor); 지정된 교사 공유용. 관리자·직원은 기존 역할로 관리 |
| `timetable_plan_items` | id, plan_id, name, subject/subject_area_key, grade, capacity/tuition nullable, default teacher/room IDs nullable, duration_minutes nullable, source_class_id nullable, state(draft/applied), applied_class_id/transfer_id/at nullable, revision |
| `timetable_plan_slots` | id, plan_id, item_id, weekday, start_minute, end_minute, teacher_catalog_id, classroom_catalog_id, resource-name snapshots, source_slot_id nullable; item/plan 복합 FK |
| `dashboard_private.timetable_plan_mutation_receipts` | actor_id+operation+request_key unique, request_hash, response; 재시도 결과 보존 |
| `dashboard_private.timetable_plan_transfers` | transfer id, request key, actor, source/target, selected item/class mapping, revision과 결과; 반영·이동 감사/중복 식별 |

불완전/충돌한 가져오기 슬롯은 확정 슬롯에 삽입하지 않고 `timetable_plan_items.pending_slots` JSON에 허용된 배치 필드와 진단 사유만 보존한다. 옛 원본 entry 전체, 학생 IDs, status, 알 수 없는 필드를 pending/raw 하위 값에도 넣지 않는다. 이는 미배치 복구 입력이며 충돌 판정·운영 반영의 권위 데이터로 사용하지 않는다. 해소 후 정규화 슬롯으로 이동한다. 일반적인 확정 배치를 JSON에 중복 저장하지 않는다.

기존 `classes`, `class_schedule_slots`, `class_lesson_sessions`, `class_textbook_assignments`를 운영의 권위 데이터로 유지한다. 그림자는 이 운영 데이터에서 읽어 오며 별도 shadow 클래스/슬롯 복사본을 DB에 저장하지 않는다. `source_class_id`는 초안의 출처이며 자동 쓰기 링크가 아니다. `applied_class_id`는 결과 추적/중복 표시 방지용이다. 모든 새 운영 수업은 새 UUID를 받는다. 원본 수업 삭제 시 snapshot은 유지하고 출처 FK만 null로 바뀐다.

반영 완료 블록 제외는 `applied_class_id` 유무가 아니라 `state=applied`로 판정한다. 운영 수업이 삭제되어 FK가 null이어도 오래된 편성 블록이 다시 살아나지 않는다. `shadowFingerprint`에는 수강 상태·슬롯 값/revision·자원 변경·미해결 상태를 포함한다.

운영 신규 수업 초기화는 범위 결함을 고친 기존 슬롯 저장 helper를 사용한다. 그림자 조회에는 기존 수업·세션·수강생 데이터 쓰기를 연결하지 않는다.

### 권한·동시성

- public 테이블 RLS 활성화, 익명 접근 금지. 프리셋 접근은 관리자·직원 또는 명시 멤버에 한한다. 공유 가능한 계정은 기존 역할/교사 연결 검증을 통과해야 한다.
- 일반 클라이언트의 직접 INSERT/UPDATE/DELETE를 막고, 모든 저장은 권한 검사하는 제한 RPC를 통과한다. 권한 있는 RPC의 private helper는 외부 execute를 철회한다.
- item의 state/applied 관련 필드는 전환 RPC만 관리한다. 일반 편집 입력으로 applied를 draft로 바꾸거나 반영 연결을 해제할 수 없다.
- 직원 권한 회수·공유 해제 뒤에는 열린 탭에서도 다음 조회/저장이 거부된다. 이름/과목을 포함한 초안 채널과 캐시도 정리한다.
- 선생님 editor는 공유 프리셋만 편집한다. 그림자는 기존 시간표 수준의 수업/자원 정보만 읽는다. 수강 반영은 관리자·직원만 가능하며 학생 명단을 프리셋에 노출하지 않는다.
- 잠금 순서는 모든 경로에서 동일하게 고정한다. 운영 자원 잠금 → 프리셋 ID 정렬 → 관련 수업 ID 정렬 → 항목/슬롯 순이다. 기존 경로가 먼저 class row를 잡는다면 진입점부터 이 순서로 수정해야 한다.
- 초기 운영 자원 잠금은 단일 transaction advisory lock으로 단순화한다. 실제 쓰기 부하를 측정한 뒤 필요할 때 자원별 잠금으로 좁힌다. 드래그가 끝났을 때만 저장하므로 pointer 빈도와 DB 잠금 빈도는 다르다.
- plan_id/item_id/weekday/resource 조회 인덱스를 둔다. 제한 초과 결과를 잘라 정상 데이터로 반환하지 않는다. 항목 500/슬롯 2000 초과는 명시적 용량 오류로 읽기만 허용하고 확대 설계를 검토한다.

RLS/ACL은 [Supabase 공식 RLS 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)의 접근 통제를 기반으로 하되, 위 역할/프리셋 멤버 정책을 적용한다.

## 9. 기존 기능과의 연결

- 기존 `개강 준비` 수업은 그대로 둔다. 새 프리셋 만들기에서 선택한 준비 수업을 **초안으로 복사**할 수 있다. 원본 자동 삭제/상태 전환/학기 추정 이관은 하지 않는다.
- 옛 `app_preferences` 초안이 남아 있는지는 읽기 전용으로 조사한다. 데이터가 없으면 과거 초안을 복구했다고 주장하지 않는다. 발견되면 원본을 보존하고 보기별로 다른 내용을 병합하지 않은 채 별도 복구 후보로 제시한다. historical entries는 객체이고 네 surface 키는 독립 후보다. 전역 app_preferences는 개인 저장소가 아니므로 관리팀 전용 RPC에서만 안전한 필드를 읽는다. 미리보기 이후 원본이 바뀌면 새 가져오기 요청은 stale로 거절한다. 과목 정보 누락은 임의 값으로 채우지 않고 명시적 오류로 거절한다. 원본 수업/학생/상태/이력 및 이전 preference 행은 변경하지 않는다.
- 현재 운영으로 반영한 뒤 관리 목록·시간표·수업계획·등록의 해당 수업 캐시를 무효화한다. 공개 API의 기존 무효화 계약도 보존하되 공개 UI는 별도 저장소에서 변경하지 않는다.
- 복사/이동/저장으로 고객·직원 알림을 자동 생성하거나 발송하지 않는다. notification outbox/외부 provider 호출이 0인지 검증한다.
- 현재 회차 기반 교재/진도, 출결·정산, 이전 `session_key`와 슬롯 FK를 유지한다. 클래스 배열 복사로 학생을 새 수업에 넣지 않는다.
- 수업관리·일정 편성·휴보강 등 다른 경로에서 충돌을 만들 수 있으면 시간표에서만 차단해도 보장되지 않는다. 공유 검사/잠금 통합이 수강 반영 활성화의 선행 조건이다. 운영 변경이 초안과 충돌할 때는 운영을 막지 않고 초안 재검토로 처리한다.

## 10. 출시 범위와 완료 기준

1차 출시에는 여러 프리셋, 운영 수업 그림자, 네 보기에서 새 수업 직접 편집, 폼/빈 시간 추천, 관리자·직원 공동 편집 및 교사별 공유, 충돌 차단, 전체/선택 수강 반영과 프리셋 간 이동·복사, 오류 복구를 모두 포함한다. 단계별 개발은 가능하지만 필수 기능이 빠진 상태를 최종 완료로 보고하지 않는다.

다음 항목은 별도 확장이다: 학기 날짜에 자동 운영 전환, 학원 전체 최적화 엔진, 수강생 자동 이관, 생성된 회차 일괄 재작성, 무제한 버전 이력/다단 실행 취소.

| 검증 | 입력 | 기대 결과 |
| --- | --- | --- |
| 4방향 연동 | 같은 슬롯을 각 보기에서 한 번씩 이동 | 다른 3보기·재접속·다른 사용자에서 같은 값 |
| 복수 요일 | 월/수/금 중 수요일만 이동 | 월/금 보존, 같은 수업 ID 유지 |
| 패널 간 이동 | 교사 A 월18시 → 교사 B 월18시 | 시간이 같아도 담당 변경 저장 |
| 빈 보드 | 새 프리셋 첫 수업 드롭 | 카탈로그 기반 빈 보드에서 생성 |

| 경계 | 18–19시 + 19–20시 | 허용 |
| 그림자 | 운영 A 월18–20시 + 신규 B 월19시 | A는 수강 유지, B 배치 거부, 네 보기 같은 자리 |
| 그림자 변경 | 운영 A가 새 시각으로 이동 | 모든 프리셋 최신 그림자 갱신, 신규 충돌은 초안 보존 후 표시 |
| 그림자 불완전 | 운영 시간 파싱/자원 ID 확인 실패 | 빈칸 취급 금지, 관련 배치/반영 차단 |
| 프리셋 격리 | 운영 그림자와 겹치지 않는 A/B의 동일 시간 | 각각 저장 가능, A 새 수업 편집은 B/운영 불변 |
| 부분/전체 전환 | 전체 20개 중 3개 이동·복사 | 선택 3개만 정의된 원본/목적 결과 |
| 원자성 | 3개 중 마지막 수업 충돌 또는 강제 DB 실패 | 3개 모두 원본과 목적지 불변 |
| 이력 | 기존 수강 수업을 그림자로 참조 | 상태·시간·명단·회차·출결·수납·교재 전부 불변 |
| 복사 반영 | 신규 A를 수강으로 복사 | A 원안은 반영 완료로 보존, 그리드에는 운영 그림자 1개 |
| 재반영 | 반영 완료 A 다시 실행/응답 유실 재시도 | 새 운영 수업 중복 생성 0 |
| 미배치 | 월 확정/수 pending인 수업 반영 | 항목 전체 차단, 원래 요일 유실 0 |
| 동시성 | 같은 프리셋의 두 사용자 같은 슬롯/같은 자원 저장 | 하나만 성공; 패자 초안 보존 |
| 다른 항목 | 같은 프리셋에서 충돌 없는 두 수업 동시 수정 | 둘 다 저장, 네 보기 동일 결과 |
| 그림자 경쟁 | 프리셋 저장 직후 운영 수업이 그 자리로 변경 | 운영 계속, 초안 보존, 충돌 표시 및 반영 차단 |
| 재시도 | 성공 응답 유실 후 같은 requestKey | 수업/슬롯 중복 0, 최초 결과 재반환 |
| 저장 범위 | A 기본값 저장, B 존재 | B의 schedule/teacher/room/revision 불변 |
| 권한 | 익명, 다른 교사, 공유 해제된 editor | 조회/쓰기/직접 DML 거부, 운영 반영 차단 |
| no-send | 모든 저장·전환 | 학생 관계 불변, 알림 enqueue/provider 0 |
| UI | 1440/390px, 라이트/다크, 긴 이름, 터치·키보드 | 내부 스크롤, 입력/초점 보존, 표준 접근 가능 |

기능 구현·자동 검사·브라우저·로컬 DB·운영 migration·배포·실제 운영 전환은 각각 증거를 남긴다. 이 문서 작성은 구현/배포 완료를 의미하지 않는다.
