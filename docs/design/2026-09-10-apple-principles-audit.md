## 개선안

### P0: 흔들림과 메뉴 잘림

- 선택 작업은 기존 도구 영역 안의 같은 높이 슬롯에서 전환한다. 검색·필터·표 경계는 유지한다. 새로운 일괄 작업 줄을 삽입하지 않는다. 속성 변경은 직접 노출하고 드문 상태 변경/삭제는 공용 메뉴로 정리한다.
- 데스크톱 표 본문과 페이지 탐색의 위치를 빈 결과·로딩·오류에도 유지한다. 실제 스크롤 소유 요소에 안정된 스크롤바 여백을 적용한다. 모바일은 자연스러운 문서 스크롤을 유지한다.
- 초기화는 기존 도구 행 안에서 자리를 유지하고 조건이 없으면 비활성화한다. 모바일에서 새 줄을 만들거나 표의 열 설정 속에 검색 조건을 섞지 않는다.
- 설정 메뉴는 Radix 가용 높이와 화면 여백 안에서 최대 높이를 제한하고 본문만 스크롤한다. 제목/초기화에 항상 접근할 수 있게 한다. 고정 열과 조절할 수 있는 열을 구분해 비활성 제어의 반복을 줄인다.
- SearchField의 검색 지우기는 한 개만 표시한다. 입력값·포커스·검색 접근성은 보존한다.

### P1: 공통 조작과 설정 범위

- 기존 Button, DataTableToolbar/Filters/Viewport, 행 동작, 페이지 탐색, FormDialogContent를 개선하고 재사용한다. 중복된 검색 마크업은 공용 DataTableSearchField로 추출한다.
- 과목/학교 구분처럼 짧은 목록은 공용 선택 메뉴로, 출판사/세부과목처럼 검색이 유용한 목록은 검색형 선택기로 유지한다. 높이·테두리·아이콘·상태는 같은 토큰을 사용한다.
- 재고 표 설정은 우선 열 표시를 대상으로 한다. 교재명·합계·선택·행 동작 등 필수 열을 보존하고 분류·판매가·위치 열 표시를 조절한다. 위치 열은 실제 데이터에 따라 구성한다.
- 그룹화·정렬은 기존 목록별 계약을 따른다. 현재 페이지10행만 정렬하는 기능을 전체 목록 정렬로 제공하지 않는다. 전체 범위 정렬을 지원하지 않는 재고 조회에는 새 정렬 메뉴를 달지 않는다. 서비스 계약 확장이 필요하면 별도 제안한다.
- 공용 설정 프레임은 지원되는 기능만 표시한다. 학생 목록의 전체 설정을 그대로 복사하지 않는다.
- 수정 창의 전체 폭 제목과 고정 행동 영역을 유지한다. 분류(과목·학교 구분·학년·세부과목), 공급/가격(출판사·판매가), 식별정보(ISBN·바코드)를 배치로 구분하고 새 설명 카드를 추가하지 않는다.

### P2: 밀도와 마감

- 필터 라벨을 선택값과 같은 줄에 배치해 상단 높이를 줄인다. 긴 제목은 숨기지 않고 열 너비를 우선 배분한다.
- 그룹 행을 낮추고 헤더 명도·구분선을 일정하게 한다. 수량·금액은 tabular 숫자와 오른쪽 정렬을 유지한다.
- 같은 역할의 높이·테두리·모서리·아이콘·상태를 통일한다. 탭·체크박스·메뉴는 각 역할의 공용 규칙을 따른다.
- 같은 데이터와 화면 크기에서 완전히 보이는 행 수를 줄이지 않는다. 기본10행/10·15·20선택지와 페이지 계약은 유지한다.

## 제안 토큰: Apple 실측값이 아닌 TIPS 결정안

|---|---|
| 글꼴·색 | 기존 Pretendard, 의미 기반 색상 유지 |
| 간격 | 4·8·12·16·24px |
| 제어 | 데스크톱 기본36px, 표 안 보조32px. 모바일 주요 누름 영역44px 목표 |

| 메뉴 | 150ms, 최대2px, cubic-bezier(.2,.8,.2,1) |
| 대화상자 | 200ms, 불투명도 중심, 이동최대4px. 레이아웃 속성 애니메이션 없음 |
| reduced motion | 이동/스케일 없음, 즉시 상태 반영 |

시각 시안 proposal.png는 AI 생성된 방향 설명용 이미지다. 한글·세부 데이터·행 높이·간격의 정확한 구현 근거는 실제 코드와 위 규격이다. 시안에서 자동 정리된 제목/줄바꿈을 데이터 변경으로 채택하지 않는다. 시안은 기존 필터 라벨을 여전히 별도 줄로 그렸으나 최종 제안은 라벨과 선택값을 같은 줄에 놓는 것이다.

## 다음 구현의 검증 기준

- 같은1280×720/390×844, 데이터·상태·스크롤 위치로 비교한다. 실제 사용 창 크기도 확인한다.
- 선택/해제·초기화 유무·빈 결과/로딩/오류에서 의도하지 않은 제어·표 경계 이동은1 CSS px이내, 목표0px. 정상적인 내용 변화와 구분한다.
- 설정 메뉴는 화면 가장자리 최소8px 안쪽. 끝 항목을 마우스·키보드·터치로 조작할 수 있어야 한다.
- 동일 데이터에서 완전한 행 수와 업무 조작 수를 비교한다. 등록/수정의 한 번 클릭 진입을 늘리지 않는다.
- 렌더·요청 횟수·응답 시간은 같은 조건에서 비교한다. 재사용만으로 성능 개선을 주장하지 않는다.
- 영향받는 공용 UI 사용처와 관련 회귀 테스트를 확인한다. 문서 스타일에 영향이 있으면 동일 주문/반품 데이터의 PNG/PDF 내용·수량·금액을 다시 비교한다.

## 참조와 검증 한계

공식 Apple 원문·실제 지원 화면과 버전/확인일은 apple-references.md, 코드 경로와 재사용 계약은 component-audit.md에 기록한다. 각 파일은 원시 자료 폴더에 있다. 서브에이전트의 초기 후보 중 초기화를 표 설정에 넣기, 재고 전체 정렬 추가, 긴 제목 두 줄 제한, 제목을 통한 수정 진입 제거는 채택하지 않았다. 현재 기능과 전체 텍스트를 보존한다. 모션은 기존 150/200ms를 먼저 토큰으로 묶고 실제 비교 후 조정한다.

기존 design-qa.md17단계의 기능 축소와18~21단계의 필터·폼·문서 검수를 재사용한다. 과거 검사 수를 이번 실행으로 합산하지 않는다. 이번에는 제품 코드를 변경하지 않았으므로 새 빌드/회귀 통과나 성능 개선을 주장하지 않는다.

Finder 목록 직접 캡처는 Mac 잠금으로 진행하지 못했다. 사이드바/선택은 공식 캡처 관찰, 목록 정렬/열 설정은 공식 문서 텍스트로 구분한다. 앱/OS버전이 확인되지 않은 캡처는 확인일만 기록한다. 모바일 viewport 검사는 실제 iOS/Android 터치·가상 키보드 검증이나 전체 WCAG준수를 대신하지 않는다.

데이터·스키마·API·인증·권한·업무 계산·저장/복구·재고 원장·기존 문서를 보존한다. 제거한 기간·정산·불필요한 상태 분류를 재도입하지 않는다. 실제 구현은 방향 확인 후, 확장은 대표 구현 검수 후, 배포는 별도 요청 시 진행한다.
