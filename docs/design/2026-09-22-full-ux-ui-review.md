# TIPS 전체 UX/UI 리뷰

작성일: 2026-09-22 · 결과: 리뷰와 개선 계획 작성 · 구현/배포 작업 아님

전체적인 시각 체계는 이미 정리되어 있다. 지금 가장 큰 개선 여지는 **메뉴 안의 정보와 행동 정리, 업무 상태를 정확하게 보여주기, 오류 복구와 모바일 행동 도달**이다. 최근 대시보드의 정보 계층과 학생관리·등록의 공통 목록 구성을 기준으로 확장하고, 시간표·연간 일정표의 업무별 표현은 유지한다. 사용자 추가 범위를 반영한 메뉴 개선 순서는 **캘린더 → 전반·퇴원 → 휴보강**이다.

- 운영 화면: `https://tipsedu.co.kr`, 현재 로그인된 관리자 세션, 새 리뷰 전용 Chrome 탭. 데스크톱 기본 화면 약 1710×896, 대표 모바일 390×844.
- 코드: 원격 `main` **b0f16bf5e5001edcdb25410fd68a8be3297adde3**. `git ls-remote`와 `origin/main` 일치를 확인했다. 작업 폴더 HEAD `9f962dfc`는 오래되어 변경 파일은 원격 commit의 내용을 직접 읽었다. 운영 배포의 정확한 SHA 자체는 조회하지 않았다.
- 기준: 최신 `DESIGN.md`, `AGENTS.md`, 공통 Table/Dialog/WorkspaceTabs, `tips-quality`. 접근성 검토에 [저장소가 지정한 Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/e3d624baaf29dc1fc645aff3e38f03e564d2d6b1/command.md)를 참고했다. 외부 브랜드 스타일은 적용하지 않는다.
- 현재 활성 메뉴 22개의 기본 화면을 방문하고, `page.tsx` 61개를 실제 화면/redirect/오류/레거시로 분류했다. 메뉴에 없는 구 전자결재·데모 경로를 활성 메뉴의 문제로 세지 않았다.
- **운영 확인**은 이번 화면/DOM에서 관찰한 사실, **소스 확인**은 현행 코드에서 조건을 추적한 사실이다. 소스 조건부 문제를 운영에서 이미 발생한 사고로 해석하면 안 된다.
- 운영 저장·삭제·승인·발송·일정 생성·설정 저장은 실행하지 않았다. 입력 실패/동시 수정/역할별 권한/모든 모달/실기기 터치/다크/화면 확대/VoiceOver 전체 검증은 후속 범위다. 테스트·빌드·배포를 완료했다고 주장하지 않는다.
- 최초 순회에서 전반·퇴원·휴보강·시간표·학사일정·재시험·수업계획·통계 일부 조회가 실패했다. 이후 전반과 수업 목록은 정상 조회됐다. **지속 장애나 전체 서비스 장애를 확정한 것은 아니다.** 아래 F01은 실패 원인과 별개로 확인되는 화면 표현 문제다.

### 추가 반영: 메뉴 내부 정리 우선순위

아래는 사용자가 추가로 전달한 현재 코드·운영 대표 화면의 검토 내용과 우선순위다. 기존 F01–F17과 통합하되, 이 추가 내용 전체를 이번 캡처에서 직접 재현한 것으로 표시하지 않는다. 실행 계획의 메뉴 순서와 T4/T8/T9에 수정 범위·검증 기준을 연결했다.

| 우선순위 | 메뉴 | 추가로 정리할 내용 |
|---|---|---|
| 높음·첫 작업 | 학사일정 → 캘린더 | 일정 셀의 강한 색·그림자, 잘리는 제목, 날짜 이동·검색·보기 전환 배치 |
| 높음·두 번째 | 전반·퇴원 | 지나치게 넓은 표, 숨겨진 검색, 신청·처리 단계별 핵심 정보 |
| 높음·세 번째 | 휴보강 | 상태별 불필요한 열, 검색·필터, 신청/처리 화면의 정보 계층 |
| 중간 | 영어 단어 재시험 | 중첩 외곽 틀, 반복 배지·강조, 필터와 시험 행동의 배치 |
| 중간 | 알림 설정 | 별도 스타일의 이중 탭, 강한 선택 표시, 하단 저장 영역 |
| 중간 | 홈페이지 관리 | 검색·필터·목록의 공통 구성, 행 높이와 수정·순서 변경 배치 |
| 낮음 | 채용 지원서 | 중복 제목, 빈 상태·목록·페이지 이동 구성 |

대시보드·등록·학생/수업관리·교재관리·수업계획·시간표·학교 연간 일정표는 주요 개편을 보존한다. 통계와 기본 설정 목록의 추가 시각 정리는 후순위이며, 이미 발견한 정확성·저장·접근성 결함은 별도로 남긴다. 삭제된 전자결재와 수업그룹 설정은 개선 대상에서 제외한다.

사용자는 캘린더가 첫 조회 실패 후 재시도로 복구됐다고 전달했다. 이 리뷰의 캡처 08은 최초 실패 상태만 증명한다. 정상 화면 확인과 조회 안정성 재현을 T9에 포함하며, 근거 없이 지속 장애나 특정 원인을 단정하지 않는다.

## 3. 먼저 보존할 점

1. 학생·수업·교재의 검색→조건→데이터→페이지 이동 구조, 10/15/20행, 저장된 열 설정과 선택 시 레이아웃 유지.
2. 학생 상태의 재원/대기/퇴원 파생 기준과 수강 현황. 이를 과거의 수동 상태 편집으로 되돌리지 않는다.
3. 대시보드의 처리 대기 업무와 오늘 일정. 미처리 업무 기능을 새로 만들 필요는 없다.
4. 수업계획의 일정 편성 전용 전환과 수업관리의 사용 교재 원장. 진도·교재 입력을 일정 생성의 전제 조건으로 다시 넣지 않는다.
5. 최근 시간표와 학교 연간 일정표의 도메인 색상, 상세 popover, 모바일 구분. 일반 관리 표를 그대로 강제하지 않는다.
6. 등록·교재·휴보강의 초안 보호, 권한, 쓰기 확인, 중복 방지, 공개 전 검토와 알림 발송 경계.

## 4. 발견 사항

우선순위: **P1** 업무 완료/상태 신뢰에 직접 영향, **P2** 반복 동선·조건부 정확성·접근성, **P3** 의미·시각 일관성. 확인된 긴급 데이터 손실이나 보안 사고(P0)는 없다.

### F01 · P1 · 조회 실패와 ‘업무 없음’을 동시에 표시

**운영+소스 확인.** 전반은 ‘전반 없음’과 ‘페이지를 불러오지 못했습니다.’, 퇴원도 같은 구조였다. 시간표는 `TimeoutError: signal timed out`과 ‘조건에 맞는 시간표가 없습니다.’를 함께 표시했다. 재시험은 실패한 목록에서 ‘없음’과 추가 버튼을 보여줬다. 휴보강은 동일 timeout 원문이 두 위치에 나타나면서 빈 목록을 표시했다.

사용자는 업무가 없는 것인지 아직 확인할 수 없는 것인지 구분하기 어렵다. 최초 조회 실패는 해당 영역의 오류/재시도로, 성공한 0건만 빈 상태로 표시해야 한다. 재조회 실패 시에는 마지막 성공 결과와 그 조회 조건을 보존하고 ‘이전 조회 결과’임을 눈에 보이게 알려야 한다. 수업계획은 실패 안내는 보이나 남아 있는 행이 이전 조회 조건의 결과인지 표시하지 않고, 갱신 상태만 스크린리더 전용 영역으로 알린다.

근거: [ops-task-workspace.tsx:9422](https://github.com/tipsedu2019/tips_dashboard/blob/b0f16bf5e5001edcdb25410fd68a8be3297adde3/src/features/tasks/ops-task-workspace.tsx#L9422), 같은 파일 6901–6903/12871–12874; [timetable-workspace.tsx:631](https://github.com/tipsedu2019/tips_dashboard/blob/b0f16bf5e5001edcdb25410fd68a8be3297adde3/src/features/academic/timetable-workspace.tsx#L631), 458–471; curriculum-workspace.tsx:255–276/581–592. 화면 04–11, 16. 정상 복구된 전반은 화면 22–23.

### F02 · P1 · 모바일 프로필에서 저장·닫기가 잘림

**운영+소스 확인.** 390×844에서 dialog 가시 영역은 y=16–828인데 저장 버튼은 y=830–866, 하단 닫기는 y=874–910에 있었다. 바깥은 `overflow: hidden`, 전체 내용 높이는 909px이어서 터치로 하단 행동에 도달하기 어렵다. 상단 X로 닫을 수는 있다.

공통 편집 창의 고정 머리/바닥과 스크롤 본문을 적용한다. 아바타 내부 스크롤만으로 전체 폼 스크롤을 대신하지 않는다. 같은 변경에서 프로필 오류를 필드 가까이 연결하고 결과를 alert/status로 발표한다. 원시 공급자 오류 직출력은 사용자용 메시지로 바꾼다.

### F03 · P1 · 휴보강 저장·처리 실패가 열린 창 뒤에 표시

**소스 확인; 실제 실패 저장은 실행하지 않음.** 신청·승인 등의 실패는 페이지 공통 error에 기록되지만 열린 dialog 안에는 해당 오류 영역이 없다. 창은 계속 열려 있어 사용자가 실패 원인과 재시도를 찾기 어렵다.

페이지 조회 오류와 현재 dialog의 제출 오류를 분리한다. 실패한 행동 바로 옆에 원인/재시도를 표시하고 입력·선택·메모를 보존한다. 페이지 다시 불러오기를 실패한 저장의 재시도로 대신하지 않는다.

### F04 · P2 · 모바일 메뉴를 선택해도 메뉴가 본문을 계속 가림

**운영+소스 확인.** 모바일 계정 창을 닫고 학생관리로 이동했을 때 URL/목록은 바뀌었지만 탐색 메뉴 sheet가 그대로 남았다. Escape로 따로 닫아야 했다.

### F05 · P2 · 검색 대상이 정렬과 묶이고 모바일에서는 선택할 수 없음

**모바일 검색 UI+소스 확인.** 전반 모바일의 검색은 ‘전 수업 값 입력’으로 고정되어 학생을 검색 대상으로 선택하는 제어가 없다. 데스크톱은 열 헤더를 누르면 정렬과 검색 대상이 동시에 바뀐다. 검색어를 유지한 채 날짜/상태를 정렬하면 다른 열에 검색이 적용될 수 있다.

검색 대상을 정렬과 분리한다. 서버 계약이 허용하면 학생·수업 식별자를 함께 찾는 공통 검색을, 그렇지 않으면 명시적인 검색 대상 선택을 양쪽 화면에 제공한다. 모바일 전반 카드는 학생을 먼저, 이전/이후 수업을 각각 줄바꿈해 긴 이름도 비교하게 한다.

### F06 · P2 · 수업 상세 총원이 불러온 명단 수에 의존

## 5. 판단을 보류한 항목

- 단순 카드 수, 여백, 배지 수만으로 대규모 재디자인을 제안하지 않는다. 성능 향상 수치·업무 처리시간 단축률은 측정하지 않았다.
- 시간표의 내부 가로 스크롤 키보드 접근, 연간표 갱신 중 skeleton에 따른 스크롤 변화는 실제 조건에서 추가 확인한다.
- 31명 이상 상세 총원, 일정 미리보기 정규화 분기, 과밀 한 주 보기, 알림 장애 격리는 합성 데이터로 먼저 재현한다.
- 데이터가 실패한 화면은 정상 상태의 시각 품질까지 확인한 것으로 세지 않는다. 재조회 후 모든 역할/상태에 대해 회복됐다고 주장하지 않는다.
- 모든 화면에서 새 카드/설명/단축키를 추가하는 방식은 이 제품의 개선 방향에 맞지 않는다.
