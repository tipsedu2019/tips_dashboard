# 퇴원 마지막 수업일 경계

퇴원기준일은 마지막 수업일이며 서울 날짜 기준으로 당일을 포함한다. 회차 번호는 정산 주기마다 다시 시작하므로 날짜 경계의 비교 키로 사용하지 않는다.

## 완료와 실제 제외

- 기준일 당일 또는 그 전에 완료하면 업무와 체크리스트를 완료하고, 고정된 기준일의 제외 예약을 기록한다. 양방향 수업 명단, 등록 claim, 학생 상태는 유지한다. 응답의 `rosterReleaseScheduled: true`는 예약 완료를 의미하며 실제 해제된 등록 ID는 빈 배열이다.
- 기준일이 이미 지났다면 기존 원자적 즉시 제외를 수행한다. 선택한 수업만 제외하며 다른 등록·대기 관계가 있으면 학생은 재원으로 유지한다.
- 예약 처리기는 서울 날짜가 기준일보다 커진 뒤 기존 명단 제거 절차를 적용한다. 완료 RPC와 알림 producer를 다시 호출하지 않는다.
- 완료 요청 영수증은 예약 실행 전후에 같은 결과를 반환한다. 처리기는 현재 claim과 학생–수업 명단 변경 이력 개수를 재검증하여 수동 해제·복원·재등록 뒤의 새로운 관계를 제거하지 않는다.
- 완료 전 취소와 취소 후 재개는 기존 계약을 유지한다. 완료된 퇴원의 수정·취소·재개를 새로 허용하지 않는다.

`timetable_roster_updated`는 조기 완료에서는 제외 예약까지 확정되었다는 의미다. 감사 기록은 이를 `제외 예약`으로 구분하고, 실제 제외 기록은 처리 후에 남긴다. 이 필드의 기존 boolean 계약은 유지한다.

## 실행 준비와 배포 경계

마이그레이션은 알림을 보내거나 cron을 활성화하지 않는다. 새 앱의 퇴원 완료는 날짜 경계 capability와 V3 완료 RPC를 요구하며, 구버전 즉시 제외 RPC나 직접 배열 수정으로 fallback하지 않는다. 등록 런타임의 유지보수 차단도 유지한다.

예약 생성은 `tips-withdrawal-roster-release-v1` 작업이 정확한 명령·1분 주기·활성 상태·현재 DB·postgres 실행자로 준비되어 있을 때만 허용한다. 준비되지 않은 경우 `55000 / withdrawal_release_scheduler_not_ready`로 실패한다. `manage_withdrawal_roster_release_scheduler_v1`의 `inspect`, `install`, `disable`, `remove`는 service role 전용이다. 활성화는 별도 운영 승인을 받은 릴리스 작업이며 이번 변경 작성과 합성 검증에서는 수행하지 않는다.

cron 명령은 처리 SELECT 전에 `statement_timeout = '30s'`를 설정한다. 처리 함수의 잠금 대기는 5초, 한 배치는 최대 100건이며 동시 처리기는 advisory lock으로 중복 실행을 건너뛴다. 전체 SQL 문과 개별 잠금 대기의 제한은 [PostgreSQL 17 timeout 계약](https://www.postgresql.org/docs/17/runtime-config-client.html#GUC-STATEMENT-TIMEOUT)을 따른다. 실제 pg_cron 실행 모드에서 제한이 적용되는지는 별도 릴리스 검증 대상이다.

현재 명단과 인원은 실제 제외 처리에 따라 바뀐다. cron 지연·중단이나 처리 실패 시 현재 명단의 제외도 늦어진다. 준비 검사는 실행 성공을 보장하지 않으므로 별도 릴리스에서 실행 이력, 실패 예약, 지연량과 공개 인원 캐시 갱신을 확인해야 한다. 미래 수업의 시험·학생 시간표 충돌 계산은 예약의 고정된 기준일을 적용하므로 기준일 이후 학생을 제외한다.

홈 요약과 충돌 조회는 서로 다른 캐시 snapshot이며 열린 화면에 주기적 갱신은 없다. 처리 전 명단을 캐시한 뒤 실제 제외 후 충돌 조회가 이루어지면 새로고침 전까지 오래된 명단이 보일 수 있다. 이번 변경은 이 기존 캐시 계약을 실시간 명단 조회로 확장하지 않는다.

## 기존 계약과 미정 예외

등록 claim이 있는 완료 업무는 예약 대기 중에 원본 업무 삭제를 막는다. 적용 시에는 기존 claim의 release-source FK가 삭제 제한을 맡으며, 예약이 다른 명단 변경으로 무효화되면 임시 삭제 제약을 해제한다. 불변 예약 snapshot을 이유로 새로운 영구 삭제 금지를 만들지 않는다. claim 없는 완료 업무의 기록 삭제는 허용되며, 삭제가 이미 완료된 퇴원을 되돌리지 않는 기존 의미에 따라 예약은 남는다. 업무 삭제를 퇴원 취소로 해석하지 않는다.

기준일 선택 뒤 휴강·수업 이동·회차 변경에 따라 기준일을 자동 변경하는 정책은 추가하지 않는다. 완료 후 예약 자체의 취소·변경, 학생별 보강의 원수업/실제 보강일 기준, 외부 출석부 및 과거 날짜별 명단은 기존 구현 근거가 없어 별도 정책 확인이 필요하다.

## 검증 경계

회귀 검증은 로컬 합성 데이터와 격리 PostgreSQL에서 수행한다. pg_cron 설치 및 자동 tick은 운영에서 검증하지 않으며, 로컬 readiness fixture는 cron 작업 메타데이터를 모사한다. 실제 학생 데이터, 운영 SQL, 알림 발송·재발송, 배포는 이 작업 범위에 포함하지 않는다. 사용자 첨부 JPEG는 Library materialization 재시도 후 로컬 파일을 확보하지 못하여 픽셀을 확인하지 못했다.
