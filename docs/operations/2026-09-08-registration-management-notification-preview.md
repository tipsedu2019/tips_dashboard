# 등록 관리팀 알림 미리보기와 이전 요청 처리

이 문서는 2026-09-08 로컬 개선안의 동작과 이전 미발송 요청의 복구 경계를 설명한다. 운영 DB 적용, 배포, 실제 Google Chat 전달 여부와 별개의 기록이다.

## 현재 동작

등록의 진행상태 저장과 관리팀 알림 전달은 별도 작업이다. 상담 신청·상담 완료·대기·등록 신청에서 `관리팀 알림 미리보기`로 저장된 정보, 적용 문구, 수신 채팅방, 담당 원장 멘션을 확인하고 `이 내용으로 관리팀에 전달`을 눌러야 알림 요청이 생긴다. 미리보기 조회 자체는 source, claim, 발송 이력을 생성하지 않는다.

운영 설정의 `관리팀 진행 공유`에서 네 단계의 개별 ON/OFF·내용·담당자 멘션을 편집한다. 신규 멘션 설정은 OFF로 추가하며 기존 ON 값과 규칙의 ON/OFF는 유지한다. 멘션을 켠 경우에도 현재 과목 담당 원장 중 활성 상태이며 Google Chat 계정이 검증된 사람만 멘션한다. 그 조건을 충족하지 못하면 미리보기에 `담당자 멘션 없음`이 표시된다.

확정 시 등록 사실·규칙·문구·멘션 설정·담당자 계정·채팅방 연결의 지문을 재확인한다. 기존 v2 source 생성과 기존 legacy 발송 경로를 사용한다. 실제 외부 시도 기록을 남기는 마지막 DB gate에서도 같은 지문을 확인한다. 중간에 달라졌으면 SQLSTATE `23514`로 중단한다. HTTP 408은 전달 여부 불명으로 보존하며 같은 영수증을 자동으로 다시 보내지 않는다.

## 설정을 바꿔도 바로 발송할 수 없는 경우

| 미리보기 상태 | 의미 | 운영자가 할 일 |
| --- | --- | --- |
| 이 진행단계 알림이 꺼짐 | 현재 규칙이 OFF이고 기존 요청이 없음 | 필요한 단계만 운영 설정에서 켜고 다시 미리보기. 이 조회로 과거 요청이 생기지는 않는다. |
| 수신 채팅방 연결 필요 | 관리팀 Chat 연결을 사용할 수 없음 | 전역 수신 채팅방 연결을 확인한 뒤 미리보기. |
| 현재 내용으로 새 안내 준비 | 이전 요청의 설정과 현재 설정이 다르며, 서버가 이전 요청에 외부 시도·발송 소유권 기록이 없음을 확인함 | `보관할 이전 요청`과 현재 내용을 확인한 뒤 `이 내용으로 관리팀에 전달`. 이전 기록은 보관되고 새 요청으로 연결된다. |
| 이전 요청의 설정과 현재 설정이 다름 | 요청의 설정은 달라졌지만 안전한 복구 조건을 만족하지 못함 | `이전 관리팀 알림 기록`에서 실제 처리 이력을 확인. 새 확정은 차단된다. |
| 이미 전달함 | 같은 현재 등록 사실의 기존 요청에 전달 완료 영수증이 있음 | 중복 전달하지 않고 기존 기록을 사용. |
| 기존 처리 이력 확인 필요 | claim, 외부 시도 또는 전달 여부 불명 상태가 있음 | 실제 수신 채팅방과 전달 기록을 확인. 미리보기 화면에서 다시 보내지는 않는다. |

이전 버전에서 생성된 요청은 보관된 규칙·문구 snapshot을 비교한다. 이번 버전에서 미리보기로 확정한 요청은 멘션·담당자 계정·연결 지문까지 비교한다.

규칙을 OFF→ON으로 바꾸거나 미리보기를 여는 동작 자체는 과거 요청을 복구하지 않는다. 현재 정책상 전달할 수 있고 이전 요청의 안전 조건을 만족할 때만 새 미리보기에서 복구 가능 상태를 표시한다. 사용자가 내용을 확인하고 전달 버튼을 누르면 별도의 v4 계약이 이전 요청과 새 요청을 연결한다. 기존 요청을 지우거나 문구 snapshot을 덮어쓰지 않는다.

기존 이력 조회는 읽기 전용이다. 이 화면에서는 공용 전달 상태 컴포넌트의 재발송 버튼도 숨겨 미리보기 차단을 우회하지 않는다. 사실과 다른 입력을 저장하거나 진행상태를 반복 변경해 새 알림을 만드는 방식은 복구 절차가 아니다.

## 명시적으로 확인한 미발송 요청 복구

읽기 전용 미리보기의 `recoveryAvailable=true`와 `recoverySourceEventId`는 서버가 판정한다. 클라이언트가 임의로 복구를 선택하거나 현재 OFF 규칙을 켜는 기능은 없다. 새 미리보기 지문은 현재 확인자의 새 내용과 복구 대상 요청을 함께 묶는다.

확정 호출은 `ensure_registration_workflow_notification_v4`에 미리보기 지문, 복구 대상, 기존 요청 키를 전달한다. 서버가 같은 트랜잭션에서 안전 조건을 재확인하고 이전 요청의 보관 관계와 새 요청을 준비한다. 기존 v3 호출은 자동으로 복구하지 않는다. 실제 전달은 기존 legacy dispatcher를 사용한다.

확정 후 화면에는 `보관된 이전 요청`과 `새 안내 전달 상태`가 연결된다. 새 안내를 다시 열어도 미리보기의 `recoveredFromEventId`로 이전 기록과 현재 전달 기록을 함께 확인할 수 있다. 확정 중 이전 안내의 처리 기록이나 현재 설정이 바뀌면 새 미리보기를 요구한다. 이미 전달했거나 claim·외부 시도·결과 불명 기록이 있는 요청은 계속 차단한다. 전송 실패라는 표시만으로 외부 시도가 없다고 판단하지 않는다.

미리보기와 확정 RPC는 15초 시간 제한을 둔다. 응답이 늦으면 클라이언트는 전달을 시작하지 않으며, 같은 미리보기의 재확인에는 같은 요청 키를 유지한다. 등록건·과목·사용자 전환 뒤 도착한 확인 응답도 새 화면에서 전달을 시작하지 않는다. 사실과 다른 입력을 저장하거나 운영 영수증을 삭제하는 방법은 복구 절차에 포함하지 않는다.
