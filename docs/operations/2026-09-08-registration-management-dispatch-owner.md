# 등록 관리팀 알림 발송 소유권 정합성

운영 화면에서 상담 신청 규칙이 켜져 있어도 관리팀 알림 미리보기가 `owner_changed`로 차단됐다. 읽기 전용 운영 조회 결과 등록 발송 플래그는 ON이지만, 등록 범위의 발송 소유권은 `legacy`였다. 미리보기는 플래그 하나만으로 소유권이 전환됐다고 판단하고 있었다.

`20260908090400_registration_management_dispatch_owner.sql`은 상담 신청·상담 완료·대기·등록 신청 네 알림에서 실제 범위 소유권을 사용한다. 기존 소유권이면 확인 후 직접 전달할 수 있고, 정규 작업 처리기는 같은 알림을 가져가지 않는다. 정규 소유권에서는 직접 전달을 차단하며 정규 발송 플래그도 켜져야 작업 처리기가 전달할 수 있다. 소유권이 누락된 경우에는 양쪽 모두 차단한다.

발송 소유권을 미리보기 지문에 포함하므로 확인 후 소유권이 바뀌면 기존 최종 외부 발송 gate가 SQLSTATE `23514`로 거부한다. 등록 사실·진행상태 저장, 방문상담·청강·고객 알림톡의 별도 발송 설정, 멘션·수신 채팅방, 실제 발송 이력은 변경하지 않는다. 운영 플래그·소유권 값·연결을 변경하거나 과거 알림을 재발송하는 마이그레이션이 아니다.

`registration_management_notification_owner_test.sql`은 운영과 같은 플래그 ON/소유권 legacy 조합에서 읽기 전용 미리보기, v4 확정, 실제 legacy plan, 점유, 최종 외부 시도 gate까지 확인한다. 정규 소유권·비활성 플래그·소유권 누락과 확인 후 소유권 변경도 검사한다. 테스트는 격리 DB에서 롤백하며 실제 Google Chat 요청을 보내지 않는다. 기존 미리보기·복구 테스트와 실제 DB 경합 probe에도 소유권 fixture를 명시했다.

격리 DB의 관련 pgTAP 36개 파일, 1,543개 검사가 통과했다. 별도 실제 DB 경합 6개 시나리오에서 잠금 대기를 관찰했고, 중복 복구·뒤늦은 응답 차단과 `23514`를 확인했다. 관련 Node 검사 52개, 마이그레이션 경계 검사 39개, 최종 함수 74개에 대한 읽기 전용 배포 계약 검사가 통과했으며 Squawk 2.63.0 지적은 0개다. 외부 발송 호출은 0회다.

운영 DB 적용·애플리케이션 배포·운영 미리보기 확인·실제 고객/직원 수신 결과는 별개의 증거다. 배포 후에는 기존 운영 플래그와 소유권이 그대로인지, 관리팀 미리보기에서 차단이 해소됐는지를 읽기 전용으로 확인한다.
