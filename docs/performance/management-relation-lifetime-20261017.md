# 상세 관계 목록의 응답 수명 보호

학생·수업 상세의 다음 30건 조회는 그 상세를 열었던 수명에만 행·관련 이름·커서·오류·로딩을 반영한다. 닫기, 같은 행 재열기, 다른 상세 조회 시작, 사용자 변경, unmount 뒤의 응답은 현재 상세를 바꾸지 않는다.

기준 main `0bfd21716dbbb24cd82149731e90b79ceebef91a`의 실제 ManagementPage와 실제 다음 30건 버튼을 합성 deferred 데이터 경계로 실행했다. A 페이지 요청 → 닫기 → B 상세 → A 응답 도착 경로에서 B는 A 요청이 끝날 때까지 비활성화됐고, B의 다음 요청이 `a:stale-next`를 사용했다. 수정 후 B는 즉시 조회할 수 있고 `b:first`를 유지한다. 정상 업무 데이터나 운영 장애 빈도를 측정한 것은 아니다.

기존 `detailRequestRef`와 수용된 상세 세대를 비교하고, 타입이 있는 단일 요청 객체로 동기 잠금을 소유한다. React loading 반영 전 같은 이벤트 묶음에서 두 번 눌러도 읽기는 한 번만 시작한다. 성공·오류·finally는 세대와 요청 소유자를 모두 확인한다. 새 상세 조회가 대기 중일 때 아직 표시된 이전 상세가 새 세대로 요청하지 못하도록 수용된 세대는 실제 상세를 수용할 때만 갱신한다. 새 세대에서 이전 loading은 표시하지 않는다.

기존 공통 Button·dialog·명단 구성과 학생/수업 상세를 디자인 기준으로 유지한다. 스타일·문구·단축키·저장 동작·서버 cursor 검증·SQL·역할·권한·RLS·캐시·의존성·workflow는 바꾸지 않는다. 이미 시작한 읽기 자체를 취소하는 변경은 아니며, 늦은 결과의 UI 반영만 막는다.

새 회귀 9건은 정상 마지막 페이지·초안 보존·같은 이벤트 묶음의 중복 클릭, 다른 행 cursor 유지, 동일 행 재열기, 이전 성공/실패와 새 pending 요청, 현재 오류 재시도, 상세 교체 대기, 학생 수강 페이지, actor 변경·unmount를 검증한다. 업무 mutation 호출은 0이다.

재현 명령(저장소 Node 22):

```sh
node --test --experimental-strip-types --test-name-pattern='relation pagination' tests/management-detail-race.test.mjs
```

범위는 JSDOM의 실제 페이지/핸들러와 합성 서비스 경계다. 실제 브라우저·390px·운영 명단 관측, 네트워크 지연 개선이나 DB 실행 감소는 이 증거로 주장하지 않는다. 기존 관계 서비스의 cursor 대상 검증은 그대로 유지한다.

## 003 후속 보완: 같은 상세의 새 관계 snapshot 수락

PR149는 다른 상세 수명의 늦은 응답을 차단했다. 같은 상세에서 관계 변경 뒤 새 snapshot을 수락하는 경계는 당시 독립 리뷰가 기존 소스에서 추정한 별도 한계로 남겼으며, PR149가 도입한 회귀가 아니다. 이 변경은 003의 후속 보완으로 묶고 별도 개선 번호나 완료 건수를 추가하지 않는다. 운영에서 일반 상세 조회는 확인됐지만 핵심 페이지 경합은 자연 대상 부재로 관측되지 않았다는 기존 집계도 유지한다.

현재 main `19244c0e8361da03bacb487af111f44e50b3fb33`의 실제 페이지·공용 dropdown DOM·읽기/저장 서비스와 hook의 원문 상세 변환 callback으로 합성 학생90명을 실행했다. 60명을 표시한 뒤 마지막30명 응답을 보류하고, 보이는001의 수강 해제와 최신 상세002–031 수락 후 이전061–090 응답을 전달하면 89명 중60명만 표시되고 다음30건이 사라졌다. 중간032–060의29명이 화면에서 누락됐다. 변경 없음과 변경 거절은90명 모두 표시했다. 이는 합성 재현 수치이며 실제 DB 관계 유실이나 운영 빈도를 뜻하지 않는다.

`acceptDetailRow`는 기존 현재성 검사를 통과한 최신 상세 수락에서만 이전 관계 요청의 소유권·로딩·별도 cursor 상태를 함께 초기화한다. 최초 상세 열기와 일반 저장·관계 추가·등록/대기 전환·해제 뒤 재조회 수락이 같은 처리를 사용한다. 기존 request identity guard로 늦은 성공·오류·finally를 무시하며 상세 세대, 미저장 폼·시간표 초안, optimistic 변경, 정상 페이지 append와 서버 계약은 유지한다. 공용 관리 페이지이므로 학생·교재 상세의 같은 수락 지점에도 적용된다.

추가 회귀는 변경 없음·변경 거절, 변경 성공 뒤 늦은 성공/실패와 새 pending 요청의 경쟁을 검증한다. 최신 cursor031부터 다시 읽어 전체89명에 접근하고 중복 저장 없이 초안을 보존하는지 확인한다. 기존 PR149의 정상 페이지·상세 전환/닫기·동일 행 재열기·actor/unmount 검사는 그대로 유지한다. 원본 상세 변환 및 서비스는 실행하지만 전체 `useManagementRecords` hook은 마운트하지 않으며 auth/router/list refresh/전송은 합성이다. 실제 Chrome 합성 검증과 최종 소스 결속은 후속 작업의 별도 증거에서 확인한다.
